## 1. 어떻게 대조했나

체크리스트 항목마다 코드에서 찾을 수 있는 흔적을 정해 루트 `.ts` 전체를 훑었다.

| 체크리스트 | 찾은 흔적 | 결과 |
|---|---|---|
| 1 서버 가드 | `entity.owner.get() === world.getServerPlayer()` | CoreAPI 8 · 패널 4 전부 있다. `Puzzle_ProgressServer` 는 반대 방향 가드(`!==`)로 서버 전용을 지킨다 |
| 3 `start()` 재진입 · 4 전환 후 살아야 할 값 | `dispose()` 유무, 타이머·구독·입력·포커스 모드의 정리 | **실험용 패널 2종에 `dispose()` 가 없었다** → §2.2·§2.3 |
| 5 모듈 싱글턴 정리 | `PuzzleHubRegistry` · `PuzzleBoardStage` · `PuzzleTextureLibrary` 의 `.instance` 사용처 | `bootToMainMenu()` 가 정리한다. 레지스트리는 같은 id 로 재등록하면 덮어쓰고, 텍스처 라이브러리는 키로 덮어쓴다 |
| 6 로컬에 오지 않는 이벤트 | `OnPlayerEnterWorld` · `OnPlayerExitWorld` · `OnGrabEnd` · `OnAttachEnd` | `Puzzle_LocalOwnership`(Default) 하나뿐. 잡기·부착은 쓰지 않는다 |

| 8 이벤트 경계 | `NetworkEvent` · `LocalEvent` · `CodeBlockEvent` · `sendNetworkBroadcastEvent` | 경계를 넘는 통신은 진행도 중계 3종뿐이고 전부 `NetworkEvent` 다. **다만 첫 요청이 전환 중에 나간다** → §2.1 |

| 13 루트 등록 · 루트 폴더 | `.editor` 와 루트 폴더 목록 | 루트 `.ts` 는 전부 `.editor` 에 있다. **루트에 `_workspace/` 폴더가 있었다** → §2.4 |

## 2. 고친 것 4건

### 2.1 `PuzzleUI_MainPanel` - 진행도 요청이 소유권 전환 중에 유실되면 다시 묻는다 (§2.2)

**규칙.** 소유권이 넘어가는 동안 발행된 이벤트는 **지연 발행분까지 전부 유실된다.** 그래서
전환 직후의 상태를 이벤트 도착에 기대어 복원하면 안 되고, 필요한 값은 다시 읽어 와야 한다.

**어긋난 곳.** 허브 패널은 `initializeUI()` 에서 `REQUEST` 를 브로드캐스트한다. 그 시점이
바로 소유권이 이 플레이어에게 넘어오는 순간이다. 응답이 5초 안에 없으면 "서버 스크립트가
없다" 고 경고만 하고 끝났으므로, 첫 요청이 유실되면 **서버가 있는데도 진행도 없이 빈 메뉴로
남았다.** 저장은 계속 나가므로 그 세션에서 깬 레벨은 서버에 쌓이지만, 그 전에 있던 진행도는
그 세션 동안 보이지 않는다.

**수정.** 응답 타이머가 울리면 먼저 다시 묻고, 세 번까지 물어도 없을 때만 경고한다.

```ts
const PROGRESS_REQUEST_MAX_ATTEMPTS = 3;

private sendProgressRequest(player: Player, key: string): void {
    this._progressRequestAttempts++;
    this.sendNetworkBroadcastEvent(PuzzleProgressNetworkEvents.REQUEST, { player: player });
    this.startProgressWaitTimeout(player, key);
}

// startProgressWaitTimeout() 의 타이머 안
if (this._progressRequestAttempts < PROGRESS_REQUEST_MAX_ATTEMPTS) {
    console.log('[PuzzleHub] No reply from Puzzle_ProgressServer yet. Sending the request again (2/3).');
    this.sendProgressRequest(player, key);
    return;
}
console.warn('[PuzzleHub] No reply from Puzzle_ProgressServer for "..." after 3 requests. ...');
```

늦게 온 응답은 원래대로 `hydrate()` 가 큰 쪽을 남기며 합치므로, 요청이 두 번 나가 응답이
두 번 와도 진행도가 뒤로 가지 않는다. 경고까지 걸리는 시간은 5초에서 최대 15초가 됐다.
게임은 그 사이에도 그대로 돈다.

**같은 파일의 작은 정리.** 토스트 타이머(`_toastTimeoutId`)만 `dispose()` 에서 지우지 않고
있었다. 다른 타이머와 같게 `clearToastTimeout()` 으로 묶어 정리한다 (§2.1 - 패널이 내려간 뒤
버려진 바인딩에 `set` 이 가지 않게).

### 2.2 `DragLab_Panel` - `dispose()` 추가 (§2.1 · §8-3)

**규칙.** 소유권이 바뀌면 컴포넌트가 내려갔다가 `start()` 가 다시 불린다. 앞선 생의 잔재를
정리하지 않으면 두 벌이 돈다.

**어긋난 곳.** 이 패널은 `start()` 에서 다음을 만들지만 되돌리는 자리가 없었다.

| 만드는 것 | 런타임이 스스로 끊는가 | 안 끊으면 |
|---|---|---|
| `World.onUpdate` 구독, `async.setInterval` 2개(flush 타이머·정지 감지) | **끊는다** (`Component.dispose()` 문서 - `connect*` 와 `async` 는 자동 정리) | - |
| `Gestures` 객체와 `onPan` 구독 (`horizon/mobile_gestures`) | **끊지 않는다** | 다음 생이 새로 만드는 `Gestures` 와 함께 팬 이벤트가 두 번 온다 |
| `AnimatedBinding` 의 `Animation.repeat` | 끊지 않는다 | 네이티브 쪽 반복이 남는다 |
| Focused Interaction 모드 진입 | **끊지 않는다** | 플레이어가 고정 화면에 갇힌다. `*_CoreAPI.dispose()` 가 `releaseInteraction()` 을 부르는 이유와 같다 |

**수정.** `dispose()` 를 두어 위 넷을 전부 되돌린다. 런타임이 끊어 주는 것도 프로젝트의
다른 패널과 같은 규약으로 명시해서 끊는다. 정지 감지 타이머는 id 를 담아 두지 않아 지울 수
없었으므로 `_stallTimerId` 필드를 추가하고 두 번 켜지지 않게 막았다.

```ts
public dispose(): void {
    // World.onUpdate 구독, flush 타이머, 정지 감지 타이머, onPan 구독, Gestures 를 차례로 끊고
    this._pulse.stopAnimation();
    if (this._isFocusMode === true) {
        this._isFocusMode = false;
        this.exitFocusMode();
    }
}
```

### 2.3 `FocusDragDemo_Panel` - `dispose()` 추가와 펄스 기본 끔 (§2.1 · §7)

**`dispose()`.** §2.2 와 같은 이유다. 이 패널이 끊지 않고 남기던 것은 `PlayerControls.connectLocalInput`
으로 만든 커스텀 입력 버튼 2개(`E`/`F`)와 Focused Interaction 모드다. 입력 버튼은 런타임이
정리해 주지 않으므로 `disconnect()` 로 끊는다. 정지 감지 타이머도 §2.2 와 같이 id 를 담는다.

**펄스 막대 기본 끔 (두 패널 공통).** §7 표의 "커스텀 애니메이션 지속 2초 이내, 권장은
쓰지 않기" 항목이다. UI 스레드와 메인 스레드가 5~6초 어긋난다는 것이 근거다. 두 패널의
`showNativePulse` 는 `Animation.repeat` 로 **끝나지 않는** 왕복 애니메이션을 걸고, 기본값이
켬이었다. 이 막대는 "네이티브 렌더가 살아 있는가" 를 가르는 진단 장치라 없애지는 않고
**기본값만 끔으로** 바꿨다. 정지 원인을 가를 때만 에디터에서 켠다.

> 이 두 패널은 인게임이 아니라 실험실이다. `DragLab` 의 R1·R5·R6 처럼 프레임마다 `set` 을
> 내는 렌더 모드는 **한도를 넘을 때 무엇이 일어나는지 재려고 일부러 둔 것**이므로 손대지
> 않았다. 인게임 패널(`PuzzleBoardUI_Panel` · `PuzzleUI_MainPanel`)의 `Animation.timing` 은
> 전부 유한하고 기본값이 0.3초 이하다.

### 2.4 루트 `_workspace/` → `Documents/_workspace/` (§7 카탈로그)

**규칙.** 스크립트 카탈로그(클라우드)가 원본이라 `.editor` 에 없는 루트 파일은 에디터가
조용히 지우고, **루트에 만든 폴더는 폴더째 사라진다.** 인월드에서 돌 필요가 없는 것은
`Documents/` 아래에 둔다.

**어긋난 곳.** 문서 윤문 작업의 중간 산출물 폴더 `_workspace/2026-09-18-001/` 이 루트에
있었다. 에디터를 다시 열면 폴더째 사라질 자리다.

**수정.** `Documents/_workspace/` 로 옮겼다. 내용은 그대로다.

## 4. 검증

`../가이드/타입체크와_테스트_실행.md` 의 §1 · §2 · §2.1 · §3 을 전부 돌렸다.

| 검사 | 결과 |
|---|---|
| `tsc --noEmit --skipLibCheck` | 오류 0 (`Documents/SampleHtml/` 제외) |
| `tsc --target ES5 --lib ES2020` (에디터 다운레벨 재현) | 오류 0 |
| `tsc --declaration --emitDeclarationOnly` (선언 파일 생성) | 오류 0 |
| Node 테스트 10개 스위트 | 아래 §4.1 |

`dispose()` 와 재요청은 `horizon/core` 에 묶여 있어 Node 테스트로는 덮지 못한다. 인월드에서
확인할 항목은 둘이다.

1. 허브 패널을 띄운 뒤 콘솔에 `Sending the request again` 이 찍히는지. 찍힌다면 첫 요청이
   실제로 유실된 것이고, 그 뒤 `LOADED` 가 도착해 Continue 가 살아나야 한다.
2. `DragLab` · `FocusDragDemo` 에서 Focus 모드에 들어간 채로 월드를 나갔다 다시 들어왔을 때
   화면이 고정 상태로 남지 않는지.
