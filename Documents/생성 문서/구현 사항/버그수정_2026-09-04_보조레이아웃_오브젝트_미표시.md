# 버그수정 — 보조 레이아웃의 오브젝트가 보이지도 눌리지도 않던 문제

> 대상 파일: `PuzzleBoardUI_Panel.ts`
> 관련 문서: `버그수정_2026-09-02_보드패널_64kB_한도초과.md` (트레이를 `DynamicList` 로 바꾼 작업),
> `작업기록_2026-09-03_보드UI_상대배치_전면개편.md` (슬롯 크기를 퍼센트로 바꾼 작업)

---

## 1. 증상

레이저 퍼즐에서 화면 아래 보조 레이아웃의 **오브젝트 트레이가 비어 있었다.**

- 크리스탈이 한 개도 보이지 않는다
- 슬롯을 눌러도 아무 반응이 없다 (집을 수 없으니 퍼즐을 풀 수 없다)
- 그런데 **좌우 화살표는 보이고, 눌러 페이지를 넘기는 것도 된다**

세 번째가 원인을 가리키는 단서였다. 화살표가 보인다는 것은 트레이 상자 자체는 제자리에
그려졌다는 뜻이고(`_hasItems` 가 켜져 있어야 상자가 그려진다), 페이지가 넘어간다는 것은
슬롯 수·페이지 계산도 정상이라는 뜻이다. 즉 **슬롯만** 그려지지 않았다.

---

## 2. 원인 — `DynamicList` 안에서는 슬롯의 `height: '100%'` 가 잡히지 않는다

트레이 슬롯은 "트레이 높이를 꽉 채우는 정사각형" 으로 규격이 잡혀 있다.

```ts
style: { height: '100%', aspectRatio: 1, ... }
```

이 두 줄은 **부모의 세로 길이가 정해져 있어야** 성립한다. 트레이 상자는
`height: '82%'` 로 길이가 정해져 있으므로, 그 직속 자식인 좌우 화살표
(`height: '80%'` + `aspectRatio`)는 문제없이 그려진다.

그런데 슬롯은 화살표와 달리 `DynamicList` 안에 들어 있었다. 목록이 자식을 자기 내부
상자에 담으면서 세로 길이의 연결이 끊겨 `height: '100%'` 가 잡히지 않았고, 슬롯은
**높이 0** 으로 계산됐다. `aspectRatio: 1` 이 붙어 있으니 폭도 따라서 0 이다.

- 크기가 0 → 화면에 아무것도 보이지 않는다
- 크기가 0 → 눌릴 영역도 없어 `onPress` 가 오지 않는다 (인터랙션 없음)

**본 격자의 칸이 멀쩡한 이유**도 같은 규칙에서 나온다. 칸은 퍼센트가 아니라
`flex: 1` 로 자리를 잡으므로 부모의 길이를 되묻지 않는다.

두 작업이 겹치면서 생긴 문제다. 트레이가 `DynamicList` 가 된 것은 64kB 한도 대응이고
(`버그수정_2026-09-02_보드패널_64kB_한도초과.md`), 슬롯 크기가 픽셀에서 퍼센트로 바뀐 것은
상대 배치 개편이다(`작업기록_2026-09-03_보드UI_상대배치_전면개편.md`). 각각은 옳았지만
**퍼센트 높이가 목록 안으로 들어가는 순간** 둘의 전제가 어긋났다.

---

## 3. 해결 — 슬롯 8개를 화살표와 같은 자리에 그대로 둔다

트레이의 `DynamicList` 를 걷어내고 슬롯 8개를 평범한 `View` 의 자식으로 되돌렸다.
지금 페이지에 없는 슬롯은 `display: 'none'` 으로 접는다.

```ts
private readonly _itemSlotShown: Binding<boolean>[] =
    createSlotBindings(PUZZLE_BOARD_MAX_ITEMS, () => false);
```

- `applyItemPage()` 는 이제 목록 데이터가 아니라 **이 플래그들**을 다시 세운다.
  슬롯 노드와 내용 Binding 은 예전처럼 절대 슬롯 번호로 고정되어 있으므로,
  페이지를 넘기는 일은 "어느 슬롯을 펴고 접을지" 를 정하는 것이 전부다.
- 접힌 슬롯은 자리도 차지하지 않으므로 남은 슬롯이 가운데로 모인다.

### 3.1 64kB 한도는 괜찮은가

슬롯은 최대 8개뿐이다. 칸 81개를 목록으로 바꾼 것과 달리 여기서 아낄 수 있는 트리는
슬롯 7벌(노드 약 56개, 실측 평균 149 B/노드 기준 약 8kB)뿐이고, 본 격자가 이미 목록으로
빠져 전체 트리가 20kB 아래로 내려와 있다. 한도까지 여유가 크다.

### 3.2 왜 슬롯에 픽셀 크기를 주지 않았는가

`height: '100%'` 대신 좌표 단위 숫자(`_itemSlotSide`)를 넣어도 그려지기는 한다. 하지만
그 길이는 화면 비율에서 환산한 값이라, 화면이 바뀔 때마다 다시 계산해 넣어야 하는
**픽셀 계산 축이 되살아난다** - 상대 배치 개편이 없앤 바로 그것이다. 화살표가 퍼센트로
잘 그려지고 있으므로, 슬롯도 같은 자리에 두어 같은 규칙을 쓰게 하는 편이 맞다.

---

## 4. 회귀 방지

`height`/`width` 를 **퍼센트로 준 노드를 `DynamicList` 의 자식으로 넣지 않는다.**
목록 안에서 자리를 잡아야 하는 노드는 `flex` 로 나누거나, 부모가 아니라 자기 자신이
길이를 갖도록(`aspectRatio` 만으로는 부족하다) 만든다. 본 격자의 행·칸이 그 예다.
