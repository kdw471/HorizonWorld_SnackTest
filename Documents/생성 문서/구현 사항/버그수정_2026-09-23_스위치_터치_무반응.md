# 버그수정 2026-09-23 — 스위치 퍼즐, 터치해도 키 캡 색이 바뀌지 않는다

> 지시: "스위치 퍼즐이 문제가 있어, 터치를 해도 블록 색상 변화가 없어서, 확인하고 수정해줘"
> 관련 문서: `버그수정_2026-09-02_드래그_놓기_판정_실패.md` (같은 원인의 드래그 판)

## 1. 증상

인월드에서 스위치 퍼즐(PUZ_08)의 키 캡을 아무리 눌러도 **색이 전혀 바뀌지 않는다.**
보드는 그려지고 스위치 영역 미니 격자도 뜨는데, 누름만 반응이 없다.

테스트는 136건 전부 통과하고 있었다. **테스트가 인월드와 다른 순서로 신호를 보냈기
때문**이다 (§4).

## 2. 원인 — 뗄 때 먼저 도착하는 `onExit` 가 세션의 "뗀 자리" 를 판 밖으로 밀었다

스위치는 M2 규칙상 **다운한 키 캡 위에서 떼야** 눌림이 확정된다. 그래서
`SwitchInputController` 는 다운 위치와 현재 위치를 따로 들고 있다가 뗄 때 비교한다.
현재 위치는 `touchMove()` 가 갱신한다.

그런데 `Pressable` 은 손가락이 떨어질 때 `onExit` 를 `onRelease` 보다 먼저 보내는
경우가 있다. 제자리 탭 한 번에도 신호는 이렇게 들어온다.

```
onPress(C3)    -> pointerDown(12)  -> touchDown(12)        다운 위치 = 12
onExit(C3)     -> pointerExit(12)  -> touchMove(-1)        현재 위치 = 판 밖   ← 여기서 지워졌다
onRelease      -> pointerUp()      -> touchUp()            -1 != 12  ->  RELEASED_OUTSIDE
```

프레젠터는 이 상황을 이미 알고 있다. 스쳐 가는 exit 으로는 지워지지 않는
"마지막으로 올라가 있던 진짜 칸"(`_lastInsideCell`)을 따로 기억해 두었다가 뗄 때
`onCellUp(12)` 로 정확히 돌려준다 (2026-09-02 수정).

**`Switch_CoreAPI` 만 그 값을 버리고 있었다.**

```ts
onCellUp: () => { this.session.touchUp(); },   // 프레젠터가 준 칸 번호를 버린다
```

버리면 세션은 자기가 기록한 -1 을 보고 판정하므로, 모든 탭이 취소된다. 드래그를 쓰는
다른 퍼즐(레이저·러시아워·정렬·연결)은 전부 `onCellUp: (cell) => ...` 로 받고 있어서
이 증상이 없었다. 스위치 하나만 예외였다.

## 3. 고친 방법 — 프레젠터가 준 뗀 칸을 그대로 세션까지 내린다

| 파일 | 수정 |
|---|---|
| `Switch_CoreAPI.ts` | `onCellUp: (cell) => { this.session.touchUp(cell); }` |
| `Switch_Session.ts` | `touchUp(releasedPosition?: number)` — 그대로 컨트롤러에 넘긴다 |
| `Switch_InputController.ts` | `touchUp(releasedPosition?: number)` — 주어지면 그것이 뗀 자리의 진실이고, 드래그 중 기록한 위치를 덮어쓴다 |

인자를 **선택**으로 둔 이유는 기존 호출부(테스트, 큐 경로)를 그대로 두기 위해서다.
주지 않으면 예전처럼 마지막 `touchMove()` 를 쓴다.

취소 방향도 함께 맞다. 판을 진짜로 벗어나면 프레젠터가 `_lastInsideCell` 까지 지워
`onCellUp(-1)` 을 주므로 RELEASED_OUTSIDE 가 유지된다. 일시정지·결과 화면에서
`cancelPress()` 가 부르는 `onCellUp(-1)` 도 마찬가지라, **취소가 도리어 키 캡을 누르는**
반대 방향 버그까지 같이 막힌다.

## 4. 왜 테스트가 못 잡았나

`PuzzleBoardUI_Tests.ts` 의 스위치 통합 테스트는 CoreAPI 의 배선을 재현한다면서
**`onCellUp` 의 칸 번호를 똑같이 버리고 있었고**, 탭 경로에서 `pointerExit` 를 아예 보내지
않았다. 인월드에서 늘 오는 신호가 테스트에는 없었던 것이다.

거기에 "칸 밖에서 떼면 눌리지 않는다" 항목이 `pointerExit` 로 판 밖을 흉내 내고 있었다.
프레젠터의 규약상 **판을 벗어났다는 신호는 격자 밖 배경의 `pointerLeaveBoard()`** 이고
칸의 exit 는 뗄 때 늘 오는 신호다. 즉 이 항목은 버그를 정답으로 고정하고 있었다.

고친 내용은 이렇다.

- 통합 테스트의 배선을 `onCellUp: (cell) => session.touchUp(cell)` 로 맞췄다
- "칸 밖" 흉내를 `pointerLeaveBoard()` 로 바꿨다
- `onPress → onExit → onRelease` 순서로 탭해도 키 캡이 토글되는지 보는 회귀 항목을 넣었다
- `Switch_Tests.ts` 에 컨트롤러 단위의 회귀 2건을 넣었다 (늦게 온 exit 을 덮어쓴다 /
  넘어온 뗀 자리가 판 밖이면 취소한다)
