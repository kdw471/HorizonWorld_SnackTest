# 0. 무엇을 했나

퍼즐 보드를 **3D 오브젝트 대신 Custom UI 패널에 그리도록** 표현 계층을 바꿨다.

```
이전   세션 이벤트 → 키 캡 25개의 position / visible / tintColor
이후   세션 이벤트 → PuzzleBoardPresenter 의 칸 패치 → Custom UI Binding
```

**로직 계층은 한 줄도 건드리지 않았다.** `Switch_Session` / `Switch_Board` /
`Switch_LevelGenerator` / `Switch_DataTables` / `Switch_GameEvents` 는 그대로다.
바뀐 것은 `Switch_CoreAPI` 의 표현·입력 배선뿐이다 (PUZ_00 §7.1 로직과 표현의 분리가
이 교체를 가능하게 한 지점이다).

## 0.1 왜 지금 바꿨나

설계 문서 §4 의 진행 순서가 **"표현 방식 결정을 나머지 7개 CoreAPI 를 쓰기 전에"** 로
잡혀 있다. 3D 방식으로 7종을 더 쓴 뒤에 바꾸면 같은 작업을 7배로 다시 하게 된다.
지금은 `Switch_CoreAPI` 하나만 있으므로 교체 비용이 가장 싸다.

## 0.2 무엇이 해결되나

설계 문서 §2 가 꼽은 멀티플레이의 세 가지 장벽이 **표현 계층에서 사라진다.**

| 장벽 | 3D 오브젝트 | Custom UI |
|---|---|---|
| §2.2 보드가 월드에 한 세트뿐 | 키 캡 25개를 플레이어 수만큼 복제 | 복제할 엔티티가 없다 |
| §2.2 `position`/`visible`/`tintColor` 가 네트워크 동기화 | A 가 누른 키가 B 화면에서도 변한다 | 로컬 UI 라 애초에 전파되지 않는다 |
| §2.3 플레이어별 가시성 분리가 없음 | `setVisibilityForPlayers` 를 일일이 걸어야 함 | Local 소유 Custom UI 는 그 플레이어에게만 렌더된다 |

남아 있는 것은 **§2.1 소유권 배분(리그 풀)** 하나다. 이번 작업 범위가 아니며 §6 에 정리했다.

## 1.1 계층 구조

```
Switch_Session (순수 로직)                     ← 변경 없음
      │  세션 이벤트 (LEVEL_LOADED, KEY_PRESSED, ...)
      ▼
Switch_CoreAPI (Horizon Component, Local)      ← 표현·입력 배선만 재작성
      │  presenter.setCell(cell, { fill, isVisible })
      ▼
PuzzleBoardPresenter (순수)                    ← 신규
      │  CELL_CHANGED / LAYOUT_CHANGED
      ▼
PuzzleBoardUIPanel (Custom UI gizmo, Local)    ← 신규
      │  Pressable onPress/onEnter/onExit/onRelease
      ▼
PuzzleBoardPresenter.pointerDown/Enter/Exit/Up
      │  onCellDown / onCellMove / onCellUp / onCellTap
      ▼
Switch_Session.touchDown/touchMove/touchUp     ← 변경 없음
```

**컨트롤러와 패널을 다른 엔티티로 나눈 이유**는 패널의 Display Mode 를 자유롭게
고르기 위해서다. Screen Overlay(화면에 겹침)와 Spatial(월드에 판이 서 있음)을
에디터에서 바꿔 끼울 수 있고, 코드는 어느 쪽이든 같다.

## 1.2 스테이지 — 패널이 어떤 보드를 그릴지 정하는 자리

메인 UI 는 한 번에 퍼즐 하나만 돌리므로(`PuzzleUI_Model` 의 화면 상태 머신),
패널은 "지금 올라와 있는 보드" 하나만 그리면 된다.

```ts
PuzzleBoardStage.instance.mount(this._presenter);    // 레벨 로드 시
PuzzleBoardStage.instance.unmount(this._presenter);  // abort / dispose 시
```

패널이 CoreAPI 보다 늦게 초기화돼도 `stage.current` 를 읽어 따라잡는다.
`PuzzleHubRegistry` 와 같은 이유로 싱글턴이며, Local 스크립트는 클라이언트마다
별도 JS 컨텍스트에서 도므로 플레이어끼리 섞이지 않는다 (설계 문서 §1.2).

## 1.3 슬롯 번호와 칸 번호가 다르다

`initializeUI()` 는 **한 번만** 불리고 `UINode` 를 나중에 갈아 끼우는 API 가 없다.
그래서 패널은 최대 격자(9×9 — 러시아워 `RUSH_HOUR_FULL_GRID_SIZE` 가 가장 크다)만큼
Pressable 을 미리 만들고, 실제 격자 밖은 `display: none` 으로 숨긴다.

```
슬롯 번호 = row * 9(고정)        + col     ← UI 트리의 자리
칸  번호 = row * 현재 colCount   + col     ← 퍼즐 로직의 row-major 번호
```

둘을 오가는 것이 `PuzzleBoardUIPanel.applyGridCell()` / `toCellIndex()` 다.
5×5 판에서 칸 7번은 슬롯 (1,2) = 11번에 그려진다.

# 2. 입력 규약 — 무엇이 바뀌고 무엇이 남았나

| | 3D 보드 (이전) | Custom UI 보드 (지금) |
|---|---|---|
| 입력 원천 | `Basics_Input_Screen` 의 화면 터치 | `Pressable` 콜백 |
| 칸 판정 | ray ↔ 보드 평면 교차 → 반올림 | Pressable 이 칸을 직접 안다 |
| Focused Interaction | **필수** (없으면 터치가 아예 안 온다) | 불필요 |
| 고정 카메라 | 사실상 필수 | 선택 (`focusCamera`, 기본 꺼짐) |
| `boardCentre` | 좌표계 정의 그 자체 | 카메라 연출용으로만 선택 사용 |
| 단일 터치 강제 (PUZ_00 §8.1) | `PuzzleTouchRouter` | `PuzzleBoardPresenter` |
| 누른 칸 밖에서 떼면 취소 (PUZ_08 M2) | 유지 | 유지 |
| 보드 밖 좌표 (PUZ_00 §8.4) | 평면 교차라 항상 나옴 | `PUZZLE_BOARD_CELL_OUTSIDE`(-1) |

## 2.1 enter/exit 순서를 신뢰하지 않는다

칸 A 에서 B 로 손가락을 옮기면 UI 는 `onExit(A)` 와 `onEnter(B)` 를 내는데
**둘의 순서가 보장되지 않는다.** 그래서 `pointerExit()` 는 칸 번호를 받아
**지금 올라가 있는 칸이 그 칸일 때만** 밖으로 처리한다.

```
exit(A) → enter(B)   :  hover = 밖 → hover = B      ✅
enter(B) → exit(A)   :  hover = B  → (A≠B 라 무시)   ✅
```

두 순서 모두 검증 항목으로 넣었다 (`PuzzleBoardUI_Tests.ts` "enter 이후 도착한 이전 칸 exit 는 무시").

## 2.2 숨긴 칸은 보드의 일부가 아니다

스위치의 FREE 좌표(§4 "아무런 오브젝트가 생성되지 않는다")는 `isVisible: false` 로 둔다.
프레젠터는 숨긴 칸의 `pointerDown` 을 거절하고, 드래그 중 숨긴 칸에 들어가면
보드 밖으로 나간 것과 같게 다룬다. 자리는 그대로 차지하므로 격자 모양은 유지된다.

# 4. 에디터 월드에서 수정할 것

**절차서 정본은 `../가이드/에디터_퍼즐_셋업.md` 다.** 여기서는 기존 월드를 옮길 때의
차이만 정리한다. 새로 셋업한다면 가이드를 그대로 따르면 된다.

## 4.1 지워도 되는 것

| 오브젝트 | 이유 |
|---|---|
| **KeyCapRoot 와 자식 큐브 25개** | 보드를 UI 로 그리므로 3D 키 캡이 필요 없다 |
| **PuzzleBoard** (빈 엔티티) | 좌표계 정의가 사라졌다. `focusCamera` 를 켤 거면 남긴다 |
| **InputListener** + `Basics_Input_Screen` | 스위치는 더 이상 화면 터치 이벤트를 쓰지 않는다 |

> `Basics_Input_Screen.ts` **스크립트 파일 자체는 지우지 않는다.** 매치3 계열이 참조한다
> (가이드 §2 "이름이 매치3 계열 같아도 절대 지우면 안 됨").
> 다른 퍼즐이 3D 표현으로 남는다면 InputListener 엔티티도 남긴다.

## 4.2 새로 만들 것

**BoardPanel** — Custom UI gizmo 하나.

| 설정 | 값 |
|---|---|
| 붙일 스크립트 | `PuzzleBoardUI_Panel` |
| 실행 모드 | **Local** |
| Display Mode | `Screen Overlay` (화면에 겹침) 또는 `Spatial` (월드에 판이 서 있음) |
| 배치 | Spatial 로 둘 때만. 플레이어가 볼 위치에 놓고 정면이 플레이어를 향하게 회전 |

패널 props 는 기본값으로 두어도 동작한다.

| Prop | 기본값 | 언제 바꾸나 |
|---|---|---|
| `showTitle` | true | 메인 UI 의 HUD 와 제목이 겹치면 끈다 |
| `boardHeightPercent` | 78 | 격자가 너무 크거나 작을 때 |
| `cellGapPercent` | 1.2 | 칸 사이 간격 |
| `drawBackgroundWhenEmpty` | false | 퍼즐 밖에서도 패널 배경을 보이고 싶을 때 |

## 4.3 고칠 것

**PuzzleController** (`Switch_CoreAPI`)

| Prop | 조치 |
|---|---|
| `keyCapRoot` | **사라졌다.** 에디터에서 항목이 없어진다 |
| `cellSpacing` | **사라졌다** |
| `boardCentre` | 비워 둔다. `focusCamera` 를 켤 때만 채운다 |
| `focusCamera` | **신규.** 기본 꺼짐. 월드에 세운 패널을 정면에서 보게 하려면 켠다 |
| `cameraObject` / `cameraDistance` / `cameraFov` | 그대로. `focusCamera` 가 꺼져 있으면 쓰이지 않는다 |
| `difficulty` / `autoStart` / `seed` | 그대로 |

**OwnershipSetter** (`Puzzle_LocalOwnership`)

`targets` 에 **BoardPanel 을 추가한다.** 소유권이 넘어오지 않으면 패널은 빈 화면만 그린다.

```
targets = [ PuzzleController, BoardPanel, PuzzleUIMainPanel(쓴다면) ]
```

InputListener 엔티티를 지웠다면 targets 에서도 뺀다.

## 4.4 셋업 체크리스트

```
□ BoardPanel (Custom UI gizmo) + PuzzleBoardUI_Panel, 실행 모드 Local
□ PuzzleController + Switch_CoreAPI, 실행 모드 Local
□ OwnershipSetter + Puzzle_LocalOwnership, 실행 모드 Default(서버)
□ OwnershipSetter.targets = [PuzzleController, BoardPanel]
□ KeyCapRoot / PuzzleBoard / InputListener 정리 (§4.1)
□ 플레이 → 5×5 격자가 빨강/녹색으로 뜨고 탭이 먹으면 성공
```

## 4.5 정상 동작 확인 — 콘솔 로그

```
1. [SwitchCoreAPI] Server instance. Waiting for ownership transfer.
2. [PuzzleLocalOwnership] Transferred ownership of 2 entities to the player.
3. [SwitchCoreAPI] Started on the local client. Ownership transfer OK.
4. [SwitchCoreAPI] Switch area updated: 010111010
```

1번은 정상 셋업에서도 한 번 뜬다. 3번이 이어서 뜨는지가 판단 기준이다.

## 4.6 안 될 때

| 증상 | 원인 / 해결 |
|---|---|
| 화면이 비어 있고 로그 3번이 안 뜬다 | 소유권 미이전. `targets` 확인 (가이드 §1.2) |
| 로그 3번은 뜨는데 격자가 안 보인다 | BoardPanel 이 `targets` 에 없다 → 서버 인스턴스라 빈 화면을 그린다 |
| 격자가 보이는데 탭이 안 먹는다 | 퀘스트가 시작되지 않았다. `autoStart` 를 켜거나 메인 UI 에서 시작 |
| 탭해도 색이 안 변한다 | 누른 칸 **위에서** 떼야 확정된다 (PUZ_08 M2). 손가락을 옮겼다가 떼면 취소가 정상 |
| 칸이 정사각형이 아니다 | 직사각형 판이면 늘어난다. 정사각 판(5×5)에서 어긋나면 `boardHeightPercent` 조정 |
| 퍼즐 종료 후 카메라에 갇힌다 | `focusCamera` 를 켰는데 `abort()` 경로를 안 거쳤다. 기본값(꺼짐)이면 발생하지 않는다 |

# 6. 남은 작업

## 6.1 인월드 확인이 필요한 것

코드로는 검증할 수 없고 **에디터에서 실제로 눌러 봐야 아는 것들**이다.

| 항목 | 왜 불확실한가 | 안 되면 |
|---|---|---|
| 모바일에서 드래그 중 `onEnter` 가 오는가 | 문서상 "raycast 또는 마우스가 들어올 때"라 터치 드래그 동작이 명시돼 있지 않다 | 스위치는 탭만으로도 동작한다(같은 칸에서 떼면 확정). 드래그 퍼즐로 확장할 때 문제가 되므로 그때 대안을 잡는다 |
| 패널 **바깥**에서 손을 떼면 | 어떤 Pressable 도 `onRelease` 를 받지 못해 누름이 붙잡힐 수 있다 | 일시정지/메뉴 복귀 때 `setInputEnabled(false)` 가 취소한다. 증상이 보이면 프레임 단위 안전망을 추가한다 |
| 9×9 = 81개 Pressable 의 렌더 비용 | 실측 전 | 퍼즐별 실제 크기만큼만 만드는 방식으로 좁힌다 |

## 6.2 멀티플레이 — 리그 풀 (다음 단계)

이번 작업으로 표현·가시성 문제는 사라졌지만 **소유권은 여전히 배타적**이라
`Puzzle_LocalOwnership` 의 `firstPlayerOnly` 가 그대로 남아 있다.
먼저 들어온 한 명만 플레이할 수 있는 상태다.

설계 문서 §4 의 남은 순서다.

| 순서 | 작업 | 상태 |
|---|---|---|
| 0 | 표현 방식 결정 (3D 리그 / Custom UI) | ✅ 이번 작업 — Custom UI |
| 1 | `Puzzle_LocalOwnership` → `Puzzle_PlayerRigPool` 재작성 | ⬜ 미착수 |
| 2 | 리그 가시성 분리 (`setVisibilityForPlayers`) | ✅ 불필요해짐 (Custom UI 라 공짜) |
| 3 | 게임 플로우의 `PLAYER_LEFT` 종료 경로와 리그 반납을 짝짓기 | ⬜ 미착수 |

리그 하나의 구성이 **엔티티 2~3개**로 줄었으므로(컨트롤러 + 보드 패널 + 허브 UI),
동접 8~16명도 감당된다. 3D 리그였다면 리그당 수백 엔티티였다.

## 6.3 나머지 7개 퍼즐의 CoreAPI

`Switch_CoreAPI` 를 복제하고 표현 번역만 퍼즐에 맞게 바꾼다. 격자가 있는 퍼즐은
그대로 되고, 아래 셋은 판단이 필요하다.

| 퍼즐 | 격자 | 비고 |
|---|---|---|
| 슬라이드 / 카드 맞추기 | 있음 | 탭 전용. 스위치와 같은 구조 |
| 연결 / 러시아워 / 레이저 | 있음 | 드래그. 칸 단위 입력으로 충분한지 §6.1 확인 후 결정 |
| 정렬 | 없음 (케이스 배열) | 열 하나 = 케이스 하나로 격자에 얹는다 |
| 색 채우기 | 없음 (다이얼) | 격자가 아니다. 별도 UI 가 필요하다 |
