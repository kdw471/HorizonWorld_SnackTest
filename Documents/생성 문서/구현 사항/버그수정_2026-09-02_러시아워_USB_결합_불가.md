# 버그 수정 기록 - 러시아워에서 USB 를 삽입구에 붙여도 클리어되지 않는 문제

- **날짜**: 2026-09-02
- **증상**: USB(목표 오브젝트)를 도착 포인트(삽입구)에 닿게 옮겨도 라운드가 클리어되지 않는다.
- **수정 파일**: `RushHour_Definitions.ts`, `RushHour_DragController.ts`
- **영향 범위**: 러시아워 퍼즐(PUZ_02) 전체. 특히 **기획 CSV(NPUZ_02)로 만든 판은 전부** 클리어가 불가능한 상태였다.
- **회귀 테스트**: `RushHour_Tests.ts` 의 `testCsvDockAndClear()`

---

## 1. 원인 - 밀착 좌표를 판의 바깥 변으로 가정했다

클리어 판정은 `RushHourBoard.isSolved()` 이고, 모든 목표가 **DOCKED**(꽂힘)여야 참이 된다
(모바일 사양 §2 / §11.3). 꽂으려면 먼저 도착 포인트에 **밀착(READY)** 해야 하고, 그 밀착
좌표를 계산하는 곳이 `RushHourDragController.recomputeDockRange()` 였다.

예전 코드는 밀착 좌표를 **플레이 공간(7×7)의 바깥 변**이라고 가정했다.

```ts
// 예전 - isFlushPosition()
if (isNegative) {
    return value === 0;                                  // 좌/상단 변
}
return value + piece.size - 1 === this._board.size - 1;   // 우/하단 변
```

이 가정은 **절차적 생성기가 만든 판에서만** 맞다. 생성기는 도착 포인트를 9×9 **테두리
링**에 놓으므로, USB 가 플레이 공간의 변까지 가면 곧 도착 포인트에 맞닿는다.

그런데 기획 CSV(NPUZ_02)의 도착 포인트는 `A1`~`G7` 로 적혀 있어서, `toFullGridIndex()` 를
거치면 **7×7 플레이 공간 안쪽** 칸이 된다. 그 칸은 USB 가 꽂히는 자리라 보드가
`_blockedCells` 로 막아 두므로, USB 는 **그 앞 칸까지밖에 갈 수 없다.**

```
   CSV 판 (오른쪽 변에 도착 포인트가 있는 경우, 로컬 좌표)

   col:  0   1   2   3   4   5   6
                       [USB][USB][ ▣ ]   ▣ = 도착 포인트 (막힌 칸)
                         ↑         ↑
                    실제 밀착 자리   예전 코드가 밀착이라고 본 자리
```

그래서 `isFlushPosition()` 은 영원히 거짓이 되고, `_dockValue` 가 `undefined` 로 남아
**결합 구간 자체가 열리지 않았다.** 손을 아무리 끌어도 꽂히지 않으니 `isSolved()` 도
영원히 거짓이었다.

## 2. 수정

### 2-1. 밀착 좌표를 도착 포인트에서 거꾸로 푼다

`hasReachedEndPoint()` 가 참이 되는 좌표는 하나뿐이므로, 그 식을 뒤집어 좌표를 직접 구한다.
`RushHour_Definitions.ts` 에 `getFlushAxisValue(piece, endPoint)` 를 추가했다.

| 변 | 조건 (`hasReachedEndPoint`) | 밀착 좌표 (플레이 로컬) |
|---|---|---|
| TOP | `topFull === endPoint.row + 1` | `toPlayLocalIndex(endPoint.row + 1)` |
| BOTTOM | `topFull + size - 1 === endPoint.row - 1` | `toPlayLocalIndex(endPoint.row - size)` |
| LEFT | `leftFull === endPoint.col + 1` | `toPlayLocalIndex(endPoint.col + 1)` |
| RIGHT | `leftFull + size - 1 === endPoint.col - 1` | `toPlayLocalIndex(endPoint.col - size)` |

생성기 판(도착 포인트가 테두리 링)에서도 결과가 예전과 **완전히 같다** - 예를 들어 오른쪽
변의 도착 포인트가 전체 좌표 8이고 USB 길이가 2면 밀착 좌표는 `8 - 2 - 1 = 5` 로, 예전
식의 `value + 2 - 1 === 6` 과 같은 자리다. 즉 이 수정은 CSV 판만 고치고 기존 동작은 건드리지 않는다.

컨트롤러는 이제 그 좌표가 **이번 드래그의 이동 가능 범위 안에 있는지**만 본다.

```ts
const flush = getFlushAxisValue(piece, endPoint);
const canReachFlush = status === EGoalStatus.DOCKED
    || (flush >= this._minValue && flush <= this._maxValue);
```

### 2-2. 도착 포인트에 닿기만 해도 꽂힌다

사양 §9 는 "밀착한 자리에서 슬롯 쪽으로 반 칸 더 끌기" 를 결합 조작으로 정의한다. 그런데
그 반 칸은 **판 밖의 테두리 칸**을 짚어야 하는 조작이라 화면상 눈에 띄지 않는다. 신고 문구가
"삽입구에 닿게 옮겨도 클리어가 되지 않는다" 인 것도 그 때문이다.

그래서 `end()` 에서 스냅한 결과가 READY 면 **손을 떼는 것만으로 결합을 확정**한다.
반 칸 더 미는 기존 조작도 그대로 동작한다.

```ts
// 방금 뽑은(didUndock) 드래그는 제외한다 - 뽑자마자 다시 꽂혀 분리가 불가능해진다
if (didUndock === false && this._board.getGoalStatus(pieceId) === EGoalStatus.READY) {
    didDock = this._board.dock(pieceId);
}
```

분리는 그대로다. 꽂힌 USB 를 반대 방향으로 반 칸 이상 끌면 뽑히고, 그 드래그에서는
자동 결합을 건너뛰므로 뽑자마자 다시 꽂히는 일이 없다.

## 3. 검증

`RushHour_Tests.ts` 에 `testCsvDockAndClear()` 를 추가했다. 기획 CSV 판 중 실제로 풀리는
판을 하나 골라 솔버 해답대로 옮긴 뒤,

1. 도착 포인트가 **플레이 공간 안쪽 칸**인지 확인 (이 판이 문제의 판이 맞는지)
2. 도착만으로는 아직 클리어가 아닌지
3. 밀착 자리에서 손을 떼는 것만으로 결합되는지
4. 결합 후 `isSolved()` 가 참이고 점유 칸이 3칸인지

를 확인한다. 기존 `testDockAndUndock()`(생성기 판 · 반 칸 드래그 · 재분리)도 그대로 통과한다.
