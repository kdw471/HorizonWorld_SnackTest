# 버그수정 2026-09-02 — UI 가 화면을 꽉 채우지 않고 옆으로 월드가 보인다

> 지시: `worker/NextJob.md` 3번 — "메인 메뉴부터 모바일 화면에 꽉 차지 않고 우측에 월드가
> 그려지는데 UI 가 현재 출력되는 화면에 꽉 찰 수 있도록 레이아웃을 수정해줘"
> 관련 문서: `작업기록_2026-09-02_기기별_화면_규격.md` (`PuzzleUI_Layout` 의 시작)

## 1. 증상

메인 메뉴부터 인게임까지, UI 가 화면 한쪽에만 그려지고 **남는 자리로 월드가 보인다.**

## 2. 원인 — 세로 캔버스를 가로 화면에 올렸다

Custom UI 는 `panelWidth` × `panelHeight` 로 **캔버스** 크기를 정하고, Screen Overlay 는
그 캔버스를 **비율을 지키며** 화면에 맞춘다. 비율이 화면과 다르면 남는 쪽이 그대로 비고,
그 틈으로 뒤의 월드가 보인다.

두 패널의 캔버스는 `720 x 1180`(세로 0.61:1)로 못박혀 있었다. 그런데 **Horizon 모바일은
가로 화면**이다(19.5:9 = 약 2.17:1). 세로 판을 가로 화면에 올렸으니 좌우가 크게 남았다.

```
   화면 (가로 2.17 : 1)
┌──────────────────────────────────────┐
│           │  캔버스   │              │
│   월드    │ 0.61 : 1  │    월드      │   ← 비율이 달라 남은 자리
│           │           │              │
└──────────────────────────────────────┘
```

## 3. 고친 방법 — 캔버스를 화면 비율에 맞춘다

`PuzzleUI_Layout.resolveCanvas(screenWidth, screenHeight)` 를 새로 두고, 두 패널이
`initializeUI()` 에서 **플레이어의 실제 화면 크기**(`player.screenWidth/screenHeight`)로
캔버스를 다시 잡는다. 비율이 같아지면 남는 자리가 없다.

```ts
this._canvas = resolveCanvas(player.screenWidth.get(), player.screenHeight.get());
this.panelWidth = this._canvas.width;
this.panelHeight = this._canvas.height;
```

### 3.1 세로는 고정, 가로만 늘인다

`PUZZLE_UI_CANVAS_HEIGHT`(1180)는 그대로 두고 **가로만** 화면 비율에 맞춰 늘인다.
레이아웃의 뼈대가 전부 세로 비율(위쪽 HUD 자리 / 본 격자 / 보조 레이아웃)이기 때문이다.
세로가 고정이면 기기가 바뀌어도 그 비율이 유지되고, 픽셀로 못박아 둔 격자 한 변도
계산이 흔들리지 않는다.

비율은 `0.4 ~ 2.6` 으로 묶는다. 화면 크기를 읽지 못하면(0·NaN) 예전 세로 판으로 떨어진다.

### 3.2 두 패널이 같은 캔버스를 쓴다

보드 패널과 허브 패널은 같은 플레이어를 보고 같은 함수를 부르므로 캔버스가 언제나 같다.
이것이 중요한 이유는 Custom UI 의 `%` 가 **캔버스 기준**이라, 캔버스가 어긋나면 HUD 바가
보드 위로 파고들기 때문이다.

`panelWidth` / `panelHeight` 는 상위 클래스에서 `readonly` 지만, 두 패널이 **`readonly` 를
떼고 다시 선언**해 `initializeUI()` 안에서 대입한다. 패널이 만들어지기 전이므로
"초기화 뒤에는 바꿀 수 없다" 는 제약에 걸리지 않는다.

## 4. 가로 화면에 맞춘 두 가지 조정

캔버스만 넓히면 화면은 채워지지만 **안이 헐거워진다.** 둘을 함께 손봤다.

### 4.1 메인 메뉴 — 세로 2열 x 4행 / 가로 4열 x 2행

가로 화면에서 2열을 유지하면 버튼이 화면 폭만큼 길쭉해져 한 화면에 다 들어가지 않는다.
`getCatalogColumns(canvas)` 가 열 수를 정하고, 행 수·버튼 높이·글자 크기가 거기서 따라온다.

```
세로 화면            가로 화면
┌────┬────┐         ┌───┬───┬───┬───┐
│ 1  │ 2  │         │ 1 │ 2 │ 3 │ 4 │
├────┼────┤         ├───┼───┼───┼───┤
│ 3  │ 4  │         │ 5 │ 6 │ 7 │ 8 │
├────┼────┤         └───┴───┴───┴───┘
│ 5  │ 6  │
├────┼────┤
│ 7  │ 8  │
└────┴────┘
```

### 4.2 인게임 — 격자에 세로를 조금 더 준다

본 격자는 정사각형이라 **짧은 변**을 따른다. 가로 화면에서는 언제나 세로가 한계이므로,
세로 화면 비율(격자 55% / 보조 28%)을 그대로 두면 격자만 작아진다.
`fitBoardAreaToCanvas()` 가 가로 화면에서만 보조 레이아웃에서 8%p 를 떼어 격자에 준다
(보조 레이아웃은 16% 밑으로 내려가지 않는다). 세로 화면에서는 아무것도 바꾸지 않는다.

# 2차 — 캔버스를 맞췄는데도 오른쪽으로 월드가 보인다

> 지시: "모바일 화면으로 확인했을 때 여전히 UI 패널 레이아웃이 화면을 꽉 채우지 않고
> 오른쪽 사이드 쪽으로 월드 레벨이 보이는데, 메인 패널 레이아웃 구조 로직에 문제가 있는지
> 검토해줘"

1차에서 캔버스 비율은 맞췄지만 증상이 남았다. **메인 패널의 배치 구조 자체에 결함이
둘 더 있었다.** 둘 다 캔버스를 넓힐수록 나빠지는 것들이라, 1차 수정이 오히려 드러냈다.

## 8. 결함 A — 배경이 패널 끝까지 칠해지지 않았다

안전 여백(노치·홈 인디케이터·Horizon 이동 버튼 자리)을 **뿌리 View 의 `padding`** 으로
걸어 두었다. 그런데 배경색은 뿌리가 아니라 **각 화면**이 칠한다. 화면들은 뿌리의 padding
**안쪽**에 놓이므로, 패널 가장자리 한 줄이 통째로 투명하게 남았다.

```
이전                                   지금
┌ 뿌리 (padding, 배경 없음) ─────┐      ┌ 뿌리 (여백 없음, 배경 없음) ──┐
│ ░░░░░░ 투명 → 월드가 비친다 ░░ │      │████ 화면 (배경 + 자기 padding)│
│ ░ ┌ 화면 (배경) ──────────┐ ░ │      │██ ┌ 내용 ────────────────┐ ██│
│ ░ │        내용          │ ░ │      │██ │      내용            │ ██│
│ ░ └──────────────────────┘ ░ │      │██ └──────────────────────┘ ██│
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │      │██████████████████████████████│
└──────────────────────────────┘      └──────────────────────────────┘
```

여백을 **각 화면 안으로** 옮겼다(`screenPadding()`). 배경은 패널 끝까지 칠해지고,
글자와 버튼만 안전 영역 안으로 들어온다. 뿌리에는 이제 여백을 주지 않는다.

뿌리를 통째로 칠하지 않은 이유는 **인게임에서 투명해야 하기 때문**이다. 허브 패널과 보드
패널은 서로 다른 gizmo 라, 허브 뿌리를 불투명하게 칠하면 뒤의 보드가 가려진다.
배경을 칠하는 것은 메뉴·상세·일시정지·결과 네 화면뿐이고, HUD 바는 예전처럼 투명하다.

보드 패널은 **뿌리가 직접 배경을 칠하고 있어서** 이 문제가 없었다. 허브 패널만의 결함이다.

## 9. 결함 B — 퍼센트 여백이 세로에도 *가로* 를 기준으로 계산된다

Custom UI 의 배치는 Yoga(CSS Flexbox) 규칙을 따른다. 거기서 **`margin` 과 `padding` 의
퍼센트는 네 방향 모두 부모의 *가로* 를 기준으로 계산된다.** `marginTop: '26%'` 는
"높이의 26%" 가 아니라 **"폭의 26%"** 다.

세로 캔버스(720 x 1180)에서는 우연히 그럴듯한 값이 나왔다. 그러나 1차 수정으로 캔버스가
가로로 넓어지자(2557 x 1180) 세로 여백이 전부 부풀었다.

| 자리 | 의도 | 세로 캔버스 | **가로 캔버스** |
|---|---|---|---|
| 뿌리 `paddingTop: 3%` | 35px | 22px | **77px** |
| 뿌리 `paddingBottom: 6%` | 71px | 43px | **153px** |
| 일시정지 제목 `marginTop: 26%` | 307px | 187px | **665px** |
| 결과 제목 `marginTop: 24%` | 283px | 173px | **614px** |

일시정지 제목이 665px 아래에서 시작하면 그 밑의 버튼 세 개는 화면 밖이다.
같은 이유로 뿌리의 좌우 padding 도 폭의 4% = **102px** 씩 잡아먹어, 결함 A 의 투명한
띠가 그만큼 넓어졌다. **"오른쪽으로 월드가 보인다" 의 직접적인 원인이 이것이다.**

세로 여백을 전부 픽셀로 바꿨다.

```ts
verticalPixels(canvas, 26)   // 캔버스 세로의 26% 를 픽셀로 -> 폭이 아무리 넓어도 307px
```

`width` / `height` 의 퍼센트는 각자 축을 따르므로 그대로 둔다. **함정은 `margin` 과
`padding` 뿐이다.** 보드 패널의 안전 여백과 세로 마진도 같은 이유로 픽셀로 바꿨다 -
그쪽은 눈에 덜 띄었지만 `computeBoardGeometry()` 가 쓰는 세로 예산과 어긋나고 있었다.

## 10. 결함 C 대비 — 캔버스 크기를 직접 못박는 탈출구

`panelWidth`/`panelHeight` 를 **런타임이 언제 읽는지** 공식 문서에 없다. `initializeUI()`
안에서만 대입하면 그보다 먼저 읽는 구현에서는 반영되지 않는다. 그래서 둘을 더했다.

1. `preStart()` 에서도 같은 값을 대입한다 (같은 값을 두 번 넣는 것이라 부작용이 없다)
2. 두 패널에 `canvasWidth` / `canvasHeight` prop 을 두어 **에디터에서 직접 못박을 수 있게** 했다
   (둘 다 0 이면 화면 비율에서 자동). `player.screenWidth/screenHeight` 가 실제 화면과
   다르게 오는 기기를 만났을 때의 탈출구다. **두 패널에 같은 값을 넣어야 한다.**

## 12. 인월드에서 확인할 것

시작 시 두 패널이 각각 자기가 잡은 캔버스를 콘솔에 남긴다. **둘이 같아야 한다.**

```
[PuzzleHub] Layout for Mobile: canvas 2557x1180 (landscape), 4 menu columns.
[PuzzleBoardUIPanel] Layout for Mobile: canvas 2557x1180 (landscape), grid 704px inside ...
```

- 두 줄의 `canvas` 가 다르면 HUD 바와 보드가 어긋난다 (같은 플레이어를 보므로 원래 같아야 한다)
- 여전히 옆으로 월드가 보이면 `screenWidth/screenHeight` 가 화면과 다르게 오는 것이다.
  그 경우 **두 패널의 `canvasWidth`/`canvasHeight` prop 에 실측 값을 같이 넣는다** (§10).
  로그의 `canvas WxH` 가 그 값으로 바뀌었는데도 여백이 남으면, 남은 원인은 Screen Overlay
  자체의 배치이지 이 레이아웃이 아니다.
