## 1. 원인 — 캔버스 정규화와 실제 해상도의 어긋남

`player.screenWidth/screenHeight` 는 **렌더러블 화면의 실제 픽셀**이고
(`horizon_core.d.ts` 문서), Screen Overlay 패널도 실제 해상도로 그려진다.

그런데 `resolveCanvas()` 는 캔버스 세로를 **1180 으로 정규화**하고 가로만 비율에 맞추고
있었다. 그래서 세로 2556px 폰에서는:

- **픽셀로 계산한 크기 전부** (격자 한 변, 트레이 슬롯, 리셋 버튼, 글자 상한...)가
  `1180 / 2556 ≈ 0.46배`, 즉 **절반 이하로** 그려졌다.
- **퍼센트 기반 크기** (보조 레이아웃 밴드의 높이·폭 등)만 멀쩡했다 — `%` 는 해상도와
  무관하기 때문이다. 스크린샷에서 "아래 밴드는 꽉 차는데 격자만 작다" 가 그 증거다.

데스크톱(~1080px 세로)은 우연히 1180 과 비슷해서 어긋남이 눈에 띄지 않았다.
크기 규격을 아무리 키워도 폰에서 작아 보였던 이유다.

## 2. 수정

| 파일 | 내용 |
|---|---|
| `PuzzleUI_Layout.ts` | `resolveCanvas()` 가 **화면 해상도를 그대로** 캔버스로 쓴다 (세로 320~4320 안전망, 비율 0.4~2.6 유지). `PUZZLE_UI_CANVAS_HEIGHT`(1180) 는 기본값 + **기준 자**로만 남는다 |
| `PuzzleUI_Layout.ts` | `canvasPixelScale(canvasHeight)` 추가 — 기준 캔버스(1180) 픽셀로 튜닝한 상수를 실제 캔버스로 환산하는 배율. `fitFontSize` 에 `pixelScale` 옵션 추가 (글자 min/max 가 1180 기준이라 안 곱하면 고해상도에서 글자가 상한에 걸려 깨알이 된다). 트레이 화살표 폭 한계도 배율 적용 |
| `PuzzleBoardUI_Panel.ts` | `pxScale`/`px()` 헬퍼 추가. 글자 min/max, 강조 테두리 두께, 부품 무늬 테두리, 고리, 모서리 둥글기, 슬롯 간격, 집은 조각 띄우기 한계(`GRAB_LIFT_*`)에 배율 적용 |
| `PuzzleUI_MainPanel.ts` | 모든 `fitFontSize` 에 `pixelScale` 적용 |
| `PuzzleUI_Tests.ts` | 캔버스 계약 테스트를 새 규약으로 교체 + **실기 회귀 테스트**: 1179×2556 폰에서 레이저 격자가 화면 폭 80% 이상, 칸 120px 이상 |

## 3. 결과 (실측 해상도로 검증)

| 해상도 | 레이저 7×7 칸 한 변 | 격자 폭 / 화면 폭 |
|---|---|---|
| 아이폰 세로 1179×2556 | **151px** (예전 ~70px 상당) | **90%** (예전 ~41%) |
| 아이폰 가로 2556×1179 | 114px | 31% (세로가 한계 — 정상) |
| 데스크톱 2340×1080 | 104px | 31% (기존과 사실상 동일) |

## 4. 주의

- `player.screenWidth/Height` 가 실제와 다른 기기를 만나면 여전히 에디터의
  `canvasWidth`/`canvasHeight` prop 이 탈출구다 — **두 패널에 같은 값**을 넣는다.
- 앞으로 픽셀 상수를 새로 만들 때는 "이 값은 어느 캔버스 기준인가" 를 생각한다.
  기준 캔버스(1180) 픽셀로 튜닝했다면 `canvasPixelScale`(패널에서는 `px()`)을 곱한다.
  `%` 나 `verticalPixels()` 로 만든 값은 그대로 안전하다.
