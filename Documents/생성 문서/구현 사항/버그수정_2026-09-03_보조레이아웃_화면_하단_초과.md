# 버그수정 2026-09-03 — 화면 비율 수정 뒤 레이아웃 하단이 모바일 화면을 넘는다

> 지시: "화면 비율 조정하는 수정을 하고 나서 레이아웃 하단부가 모바일 화면의 하단을
> 초과하는 현상이 발생했어"
> 관련 문서: `작업기록_2026-09-02_기기별_화면_규격.md` (원인이 된 앞선 수정)

## 1. 증상

캔버스를 실제 화면 해상도로 잡는 수정 이후, 보드 화면의 **보조 레이아웃(트레이·Reset)
하단이 모바일 화면 아래로 밀려 나갔다.**

## 2. 원인 — 자식의 `%` 높이는 부모의 padding 을 모른다

`PuzzleBoardUIPanel` 의 뿌리 View 는 안전 여백(노치·홈 인디케이터·Horizon 이동 버튼)을
**px `padding`** 으로 물고 있다. 그런데 그 안의 세 세로 영역(HUD 자리 8% · 본 격자 68%
· 보조 레이아웃 24%)은 `%` 문자열 높이였다.

Yoga 는 자식의 `%` 높이를 **padding 을 뺀 내용 상자가 아니라 부모 전체 높이** 기준으로
계산한다. 세 영역의 합이 100% 이므로, 위아래 안전 여백 픽셀만큼이 정확히 화면 밖으로
밀려난다.

이 어긋남은 예전부터 있었지만, 캔버스가 720×1180 고정에서 **실제 화면 해상도**로
바뀌면서(`PuzzleUI_Layout.resolveCanvas`) 안전 여백 픽셀이 커져(모바일 세로 9% ≒
가로 화면 1080px 기준 약 97px) 눈에 띄게 됐다.

## 3. 고친 방법

세 영역의 높이를 **안전 여백을 뺀 내용 높이에서 뽑은 픽셀**로 준다
(`PuzzleBoardUI_Panel.areaHeightPixels()`).

```
내용 높이 = 캔버스 세로 - 안전 여백(위) - 안전 여백(아래)
영역 높이 = floor(내용 높이 × 비율%)
```

이는 `computeBoardGeometry()` 가 격자 예산으로 쓰는 자(`usableHeight`)와 같으므로,
격자 크기 계산과 실제 컨테이너 크기가 처음으로 정확히 일치한다.

## 4. 바뀐 파일

| 파일 | 내용 |
|---|---|
| `PuzzleBoardUI_Panel.ts` | `areaHeightPixels()` 추가, `createTopInset` / `createBoardArea` / `createAuxArea` 의 `%` 높이를 px 로 |

## 5. 검증

타입 체크·에디터 제약 검사 에러 0건, 보드 UI 128 / 메인 UI 224 / 레이저 110 PASS.
인월드에서는 모바일 실기로 **보조 레이아웃 하단이 화면 안에 들어오는지**,
Reset 버튼이 Horizon 이동 버튼과 겹치지 않는지 본다.
