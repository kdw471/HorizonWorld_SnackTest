## 1. 상:하 = 70:30 (옵션)

보드 패널(`PuzzleBoardUI_Panel`)의 **에디터 prop 셋**이 세로 분할을 정한다.
에디터에서 gizmo 를 선택하면 그대로 조정할 수 있다 — 코드 기본값은 에디터가 비워 둔
경우에만 쓰인다.

| prop | 기본값 | 뜻 |
|---|---|---|
| `topInsetPercent` | 8 | 위쪽 여백 |
| `boardAreaPercent` | **64** | 본 격자 영역 (70:30 의 70) |
| `auxAreaPercent` | **28** | 보조 레이아웃 (70:30 의 30) |

64:28 = 69.6:30.4 — 위쪽 여백 8% 를 뺀 나머지를 70:30 으로 나눈 값이다.

**모바일 기기 보정(`boardAreaBonusPercent`)은 0 으로 내렸다.** 분할이 설계자가 정하는
옵션이 된 이상, 기기 보정이 몰래 비율을 흔들면 "옵션이 안 먹는다" 가 되기 때문이다.
예전 보정 몫은 위 기본값에 이미 들어가 있다.

## 2. 레이아웃 비율을 정하는 로직 지도

적용 순서대로:

1. **분할 기본값/옵션** — `PuzzleBoardUI_Panel.ts` `propsDefinition`
   (`topInsetPercent`/`boardAreaPercent`/`auxAreaPercent`)
2. **캔버스(화면 해상도)** — `PuzzleUI_Layout.ts` `resolveCanvas()`
   (에디터 override 는 `canvasWidth/Height` prop → `makeCanvas()`)
3. **비율 합 안전망** — `PuzzleUI_Layout.ts` `clampBoardArea()`
4. **가로 화면 보정** — `PuzzleUI_Layout.ts` `fitBoardAreaToCanvas()`
   (가로 화면일 때만 보조에서 최대 8% 를 격자로)
5. **기기 보정** — `PuzzleUI_Layout.ts` `fitBoardAreaToProfile()` + `PROFILES`
   (모바일 안전 여백·글자 배율·`boardWidthUsage`. 보너스는 현재 0)
6. **픽셀 확정** — `PuzzleUI_Layout.ts` `computeBoardGeometry()` (보드 패널 크기,
   트레이/리셋), `computeGridPixels()` (정사각 칸 한 변)
7. 위 전부를 잇는 곳 — `PuzzleBoardUI_Panel.ts` `resolveLayout()`

## 3. "화면 위쪽 절반에만 그려진다" 추적 — 디버그 오버레이

실기 스크린샷을 실측한 결과, 모든 픽셀 크기·위치가 **우리가 계산한 캔버스(1179×2556)를
화면 폭에 맞춰 약 0.46배로 줄인 상단 정사각 영역** 안에 그려진 것과 일치했다.
즉 이 기기에서 Screen Overlay 가 세로 화면 전체가 아니라 상단 정사각형에 캔버스를
맞추는 것으로 보인다 (가설 - 아래 오버레이로 확정한다).

`PuzzleBoardUI_Panel` 에 **`showLayoutDebug` prop** (기본 꺼짐)을 추가했다. 켜면 화면
왼쪽 아래에 한 줄이 뜬다:

```
screen 1179x2556 | canvas 1179x2556 portrait Mobile | board 1061x1445 | cell 151 | area 8/64/28
```

- `screen` = `player.screenWidth/Height` 원본 읽기값
- `canvas` = `resolveCanvas` 결과 (= 패널 크기)
- `board`/`cell` = 계산된 보드 패널과 격자 칸 (px)

실기에서 이 줄을 스크린샷으로 찍으면, 화면 읽기값이 잘못인지 / 캔버스 매핑이 잘못인지
바로 갈린다. 콘솔 로그(`[PuzzleBoardUIPanel] Layout for ...`)에도 같은 값이 나간다.
