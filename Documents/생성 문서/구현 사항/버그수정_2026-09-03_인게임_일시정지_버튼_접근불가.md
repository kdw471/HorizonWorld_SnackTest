# 버그수정 2026-09-03 — 인게임에서 일시정지 버튼이 보이지 않는다

> 지시: "게임 일시정지 버튼이 보이지 않는데 화면 절반 상반부와 하반부의 중간에 Menu 버튼
> 하나 추가하여 터치시 게임이 일시정지 되고 해당하는 UI가 표시될 수 있게"
> 관련 문서: `작업기록_2026-09-02_재입장과_시스템메뉴.md` (시스템 메뉴가 생긴 자리),
> `작업기록_2026-09-02_퍼즐_공통_UI_레이아웃.md` (두 패널이 세로를 나눠 갖는 규칙)

## 1. 증상

퍼즐을 푸는 동안 **허브 상단 바의 `Pause` 버튼이 화면에 나타나지 않는다.** 눌러 볼 수가
없으니 시스템 메뉴(Resume / Restart / Return to Main)에도 들어갈 수 없고, 레벨을 끝내거나
시간이 다 갈 때까지 빠져나올 방법이 없다.

## 2. 원인 — 인게임 화면은 보드 패널이 통째로 덮는다

화면에 겹쳐 뜨는 Screen Overlay 패널이 둘이다.

| 패널 | 인게임에서 그리는 것 |
|---|---|
| `PuzzleUI_MainPanel` (허브) | 상단 바만 — 레벨 · 남은 초 · **Pause** |
| `PuzzleBoardUI_Panel` (보드) | 격자 · 보조 레이아웃 |

원래 계획은 보드 패널이 위쪽 `topInsetPercent`(14%)를 비워 두고 **그 자리에 허브의 상단
바가 앉는 것**이었다. 그러나 보드 패널은

- 뿌리 View 가 `width/height 100%` 에 **불투명한 배경**을 칠하고,
- 그 위에 화면 전체를 덮는 **뗌 마감 레이어**(`createReleaseCatcher()`)를 깔아 둔다.

즉 "비워 둔다" 는 것은 *그 자리에 격자를 그리지 않는다* 는 뜻일 뿐, 그 영역도 보드 패널이
차지한다. 두 Screen Overlay 중 보드 쪽이 위에 오면 상단 바는 **보이지도, 눌리지도 않는다.**
겹침 순서는 에디터의 gizmo 배치에 달려 있어 코드로 보장할 수 없다.

같은 사정이 반대로 필요한 곳도 있다 — 일시정지하면 `*_CoreAPI.pause()` 가 보드를 내리는데
(`PuzzleBoardStage.unmount()`), 그래야 허브의 일시정지 오버레이가 화면에 드러난다.
보드가 허브 위에 온다는 것이 이미 그 코드의 전제였던 셈이다.

## 3. 고친 방법 — 일시정지 버튼을 **보드 패널 쪽에** 하나 더 둔다

상단 바의 `Pause` 는 그대로 두고, 확실히 보이는 쪽(보드 패널)에 같은 기능의 `Menu` 버튼을
띄운다. 자리는 지시대로 **화면을 위아래로 반 나눈 경계, 오른쪽 끝**이다.

```
┌──────────────────────────┐
│ LV 3/24   07   [Pause]   │  ← 허브 상단 바 (보드에 가려 안 보일 수 있다)
│ ┌──────────────────────┐ │
│ │                      │ │
│ │       본 격자         │[Menu]  ← 세로 50%, 오른쪽 끝 (새로 넣은 것)
│ │                      │ │
│ └──────────────────────┘ │
│ ┌──────────────────────┐ │
│ │  트레이 · 미니격자 · Reset │ │
│ └──────────────────────┘ │
└──────────────────────────┘
```

- **크기** 기기 프로필의 최소 버튼 높이를 따르되 8~12% 로 묶는다 (모바일 12%). 가로는
  높이의 1.7배인 알약 모양이다. 모바일에서 엄지로 누를 만하면서, 그보다 커지면 격자를
  필요 이상으로 가린다 (PUZ_00 §8).
- **자리** 격자가 모바일에서 폭을 다 쓰므로 어디에 두든 칸 몇 개는 가린다. 가장자리가
  판의 중심에서 가장 멀어 방해가 가장 적다.
- **보드가 없으면 사라진다** `_hasBoard` 가 꺼지면 `display: none` 이다. 일시정지하면
  보드가 내려가므로 이 버튼도 함께 사라지고, 그 자리에 허브의 시스템 메뉴가 뜬다.
- **끌던 조각을 이 버튼 위에서 떼도 마감된다** 리셋 버튼과 같이 `onAuxAreaRelease()` 를
  물린다. 격자 위에 떠 있으므로 이것이 없으면 아래 칸의 뗌이 오지 않는다.

### 3.1 두 패널을 잇는 통로 — `PuzzleBoardStage.PAUSE_REQUESTED`

보드 패널은 허브의 모델을 모른다(`PUZ_00 §7.1` 로직과 표현의 분리). 둘 사이에 이미 있는
유일한 통로가 스테이지라, 거기에 이벤트를 하나 더 얹었다.

```
[보드 패널] Menu 누름
    -> PuzzleBoardStage.requestPause()
    -> PAUSE_REQUESTED
    -> [허브 패널] PuzzleHubModel.pauseGame()      ← 판단은 여전히 모델 하나에만 있다
    -> *_CoreAPI.pause()  세션 정지 + 보드 내림
    -> 허브의 시스템 메뉴가 드러난다
```

버튼은 "눌렸다" 만 나른다. 인게임이 아닐 때 요청을 무시하는 것도 예전 그대로 모델의 몫이다.
듣는 허브가 하나도 없으면 `mount()` 와 같은 이유로 콘솔에 한 번 알린다 — 인월드에서 그
경고가 뜨면 허브 패널이 없거나 소유권이 넘어오지 않은 것이다.

스테이지는 모듈 싱글턴이라 패널보다 오래 산다. 그래서 허브는 구독을 `SubscriptionBag` 에
담아 `dispose()` 에서 끊는다 — 재입장으로 패널이 다시 만들어질 때 버려진 모델을 가리키는
구독이 겹쳐 쌓이지 않게 한다.

## 4. 바뀐 파일

| 파일 | 내용 |
|---|---|
| `PuzzleBoardUI_Definitions.ts` | `PUZZLE_BOARD_MENU_LABEL` 추가 |
| `PuzzleBoardUI_Presenter.ts` | 스테이지에 `PAUSE_REQUESTED` + `requestPause()` |
| `PuzzleBoardUI_Panel.ts` | `createMenuButton()` — 세로 50% · 오른쪽 끝의 떠 있는 버튼 |
| `PuzzleUI_MainPanel.ts` | `subscribeToBoardStage()` — 요청을 받아 `pauseGame()`, `dispose()` 에서 구독 해제 |
| `PuzzleBoardUI_Tests.ts` | 스테이지 일시정지 요청 검증 4건 |

퍼즐 로직은 한 줄도 건드리지 않았다. 상단 바의 `Pause` 도 그대로 남는다 — 겹침 순서가
반대인 기기/설정에서는 그쪽이 보인다.

## 5. 검증

| 검증 | 기대 |
|---|---|
| 듣는 허브 없이 `requestPause()` | 조용히 버려진다 (경고만) |
| 구독 후 `requestPause()` | 요청이 한 번 간다 |
| 두 번 누름 | 누를 때마다 간다 |
| 구독을 끊은 뒤 | 더 이상 오지 않는다 |

보드 UI 122 PASS / 0 FAIL, 메인 UI 허브 183 PASS / 0 FAIL.
타입 체크(§1)와 에디터 제약 검사(§2) 모두 에러 0건.

## 6. 인월드에서 확인할 것

1. 퍼즐을 시작하면 화면 오른쪽 중간에 `Menu` 가 떠 있는지
2. 누르면 **남은 시간이 멈추고** Resume / Restart / Return to Main 이 뜨는지
3. `Resume` 으로 돌아왔을 때 시간이 이어서 흐르고 `Menu` 가 다시 나타나는지
4. 격자를 끌다가 `Menu` 위에서 손을 떼도 조각이 손가락에 붙어 남지 않는지

상단 바의 `Pause` 가 보이는지도 함께 본다. 보인다면 두 패널의 겹침 순서가 반대라는 뜻이고,
그때는 두 버튼이 같이 있어도 무해하다.
