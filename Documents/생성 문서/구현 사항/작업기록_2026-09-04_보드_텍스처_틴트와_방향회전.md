# 작업기록 — 보드 텍스처에 색을 입히고, 방향대로 돌리고, 글자는 물러나게

> 관련 문서: `작업기록_2026-09-02_퍼즐_요소_텍스처_파라미터화.md` (텍스처 키·라이브러리 구조),
> `작업기록_2026-09-03_퍼즐별_세부이슈_정리.md` (크리스탈 방향 표시의 이력)

## 1. 배경

레이저 퍼즐에 오브젝트 그림(텍스처)을 끼우고 나서 세 가지가 남았다.

1. 그림 **위에 글자가 겹쳐** 그림이 무엇인지 알아보기 어렵다
2. 그림이 **한 색**이라 빨강 수신체와 파랑 수신체가 화면에서 같아 보인다
3. 삼각형·T자 크리스탈은 **방향이 곧 동작**인데 그림은 한 방향으로만 그려져 있다

셋 다 "그림이 색과 글자를 대신해야 하는데 아직 못 하고 있다" 는 한 문제의 세 얼굴이다.

---

## 2. 그림이 있으면 글자는 그리지 않는다

글자(`L`·`T`·`E`·`R`·`!`)는 원래 **그림이 없을 때 종류를 알리는 대체 표시**였다.
그림을 끼운 자리에서는 역할이 끝났으므로 물러난다.

```ts
private createLabelVisibility<T>(binding, getLabel, getTexture) {
    const library = PuzzleTextureLibrary.instance;
    return Binding.derive(
        [binding, this._textureEpoch],
        (view, _epoch) => getLabel(view) !== '' && library.resolve(getTexture(view)) === null,
    );
}
```

- 판단 기준은 "텍스처 키가 붙어 있는가" 가 아니라 **"그 키에 에셋이 실제로 등록됐는가"**다.
  그림을 그리는 `createTextureLayer()` 와 같은 `library.resolve()` 를 쓰므로,
  그림이 나오는 자리에서만 정확히 글자가 사라진다.
- 텍스처 세대(`_textureEpoch`)에서 같이 파생하는 이유도 그림과 같다 - CoreAPI 가 패널보다
  늦게 에셋을 등록해도 그때 글자가 물러난다.
- 에셋을 비워 둔 요소는 예전 그대로 색 + 글자로 그려진다. **그림은 여전히 선택 사항이다.**

칸과 트레이 슬롯에 같은 규칙을 걸었다.

---

## 3. 그림에 색을 입힌다 (틴트)

칸 스냅샷에 `tint` 를 추가했다. 그림은 이 색으로 `multiply` 되어 물든다.

```ts
/** 그림을 물들일 색. 기본값 BOARD_COLOR_NO_TINT(흰색)는 원본 그대로다 */
tint: PuzzleBoardColor,
```

### 3.1 왜 `fill` 을 그대로 쓰지 않았는가

패널에는 예전부터 `tintTexturesWithFill` prop 이 있었다. 그런데 `fill` 은 **그림이 없을 때의
바탕색**이라 테두리(0.10)·배치 영역(0.19)처럼 아주 어두운 값이 들어간다. 그것을 그대로
그림에 곱하면 판 그림이 새까매진다. 틴트는 반대로 **그림에 입히고 싶은 색**이라 성격이
다르므로 칸마다 따로 준다. 기존 prop 은 회색조 한 장으로 눌림/안 눌림 같은 *상태*를 그리던
퍼즐을 위한 것이라 그대로 두고, prop 이 꺼져 있을 때 `tint` 가 쓰인다.

기본값이 흰색이고 흰색을 곱하면 원본 그대로이므로, **틴트를 쓰지 않는 나머지 7개 퍼즐은
아무것도 달라지지 않는다.**

### 3.2 레이저가 색을 주는 자리

| 자리 | 틴트 | 이유 |
|---|---|---|
| 발사체·수신체 | 자기 광선 색 (꺼져 있으면 0.4배로 어둡게) | 그림 한 장으로 색깔별·상태별 오브젝트가 다 나온다 |
| 중계체 | 노랑 (경유 전에는 어둡게) | 위와 같다 |
| 해골 | 해골색 | |
| 크리스탈 | 크리스탈 색 (고정 크리스탈은 회색) | 고정이라 옮길 수 없다는 것이 그림에서도 보인다 |
| 광선이 지나간 빈 칸 | 광선 색 × 0.55 | **판 그림이 깔려 있으면 색만 바꿔서는 광선이 그림에 가려 보이지 않는다** |
| 테두리·배치 영역 바탕 | 없음 (흰색) | 판 그림은 원본 그대로 |

마지막 줄이 중요하다. 바탕에 그림이 깔린 뒤로는 `fill` 색이 그림에 완전히 덮이므로,
광선을 그리려면 **그림째 물들이는 수밖에 없다.**

틴트도 무늬(`glyph`)와 같은 규칙으로 **매 프레임 지운다** - `Laser_CoreAPI.setCell()` 에서
지정하지 않은 칸은 흰색으로 돌아간다. 그러지 않으면 광선이 지나갔던 칸이 계속 물들어 있다.

## 4. 방향이 있는 부품은 그림째 돌린다

삼각형은 직각 코너가, T자는 막힌 변이 어디냐에 따라 동작이 다르다. 예전에는 **글자**를
돌려서 그 방향을 알렸는데(§2 로 글자가 사라졌다), 이제 그림이 같은 각도로 돌아간다.

```ts
transform: [{ rotate: binding.derive((view) => getGlyphRotation(view.glyph)) }],
```

각도 규칙은 글자를 돌리던 것과 **완전히 같다**(`getGlyphRotationDegrees`). 방향이 없는 칸은
0도라 그대로다. 그래서 그림에 요구되는 조건은 하나뿐이다 - **기준 방향으로 그려 넣을 것.**

| 그림 | 기준 방향 (0도) |
|---|---|
| `crystalTriangleTexture` | 직각 코너가 **좌하단** (글자 `L` 과 같은 모양) |
| `crystalTeeTexture` | 막힌 변이 **위쪽** (글자 `T` 와 같은 모양) |

같은 내용을 에디터에서도 보이도록 `Laser_CoreAPI` 의 prop 주석에 적어 두었다.

막힌 변에 두꺼운 테두리를 그리는 무늬 판(`createGlyphFrame`)은 그대로 남겼다. 회전한
그림과 같은 방향을 가리키므로 서로 어긋나지 않고, 그림을 안 끼운 요소에는 여전히
유일한 방향 표시다.
