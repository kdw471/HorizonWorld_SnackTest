## 2. 왜 손가락을 그대로 따라가지 못하는가

`horizon/ui` 의 `Pressable` 콜백은 **좌표를 주지 않는다.** 타입이 `Callback = (player: Player) => void`
하나뿐이라, 어느 칸에 들어왔는지(`onEnter`)만 알 수 있고 칸 안 어디를 짚었는지는 알 수 없다.

```ts
// types/horizon_ui.d.ts
export declare type PressableProps = {
    onEnter?: Callback;   // Callback = (player: Player) => void
    onPress?: Callback;
    ...
};
```

그래서 손가락을 픽셀 단위로 따라다니는 실루엣은 만들 수 없다. **칸 단위로 따라오게** 하고,
대신 따라오는 조각을 확실히 눈에 띄게 만드는 쪽을 택했다.

> 격자 전체를 덮는 오버레이 `View` 를 하나 띄워 부드럽게 미끄러지게 하는 방법도 검토했지만
> 버렸다. Custom UI 에는 `pointerEvents` 가 없어서, 격자를 덮은 View 가 아래 칸의 `Pressable`
> 입력을 삼키면 **드래그 자체가 죽는다.** 인월드에서만 확인되는 위험이라 감수할 이유가 없다.
> 지금은 광채 고리를 각 칸 `Pressable` 의 **자식**으로 둔다 - 자식은 입력을 가로채지 않는다.

## 3. 공용 어휘 — `EBoardCellAccent`

칸 하나가 **조작의 어느 단계에 있는지**를 나타내는 값을 `PuzzleBoardUI_Definitions.ts` 에 새로 두었다.

| 값 | 뜻 | 화면 |
|---|---|---|
| `NONE` | 조작과 무관 | 평소 그대로 |
| `GRABBED` | 손가락에 붙어 따라오는 조각 | 1.1배로 커지고, 그림자가 깔리고, 집는 순간 광채 고리가 터진다 |
| `GHOST` | 집어 든 조각이 **원래 있던 자리** | 0.86배로 줄고 불투명도 0.3 - 실루엣만 남는다 |
| `DROP_VALID` | 지금 놓으면 여기 들어간다 | 초록 테두리 |
| `DROP_INVALID` | 여기에는 놓을 수 없다 | 빨강 테두리 |
| `PATH` | 조각이 지나갈 수 있는 길 | 파란 테두리 |

### `isHighlighted` 와는 다른 축이다

`isHighlighted` 는 퍼즐의 **상태**를 알린다 - 레이저의 켜진 수신체, 카드의 뒤집힌 패,
정렬의 완성된 케이스. `accent` 는 **지금 손가락이 무엇을 하고 있는지**를 알린다.
둘은 같은 칸에 동시에 붙을 수 있고, 테두리를 다툴 때는 `accent` 가 이긴다
(집어 든 조각이 상태 표시에 가려지면 정작 보여야 할 것이 안 보인다).

## 4. 퍼즐별 구현

### PUZ_02 러시아워 — 실루엣 + 이동 가능 구간

```
집기 전                 끌고 있는 중
┌───┬───┬───┐          ┌───┬───┬───┐
│   │   │   │          │ · │ · │ · │  ← PATH: 이 축에서 갈 수 있는 빈 칸
├───┼───┼───┤          ├───┼───┼───┤
│▓▓▓│▓▓▓│   │          │░░░│░░░│   │  ← GHOST: 원래 있던 자리 (실루엣)
├───┼───┼───┤          ├───┼───┼───┤
│   │   │   │          │███│███│   │  ← GRABBED: 손가락을 따라온 조각 (커지고 빛난다)
└───┴───┴───┘          └───┴───┴───┘
```

- 실루엣 자리는 `_originRow/_originCol` 에 담는다. 미리보기가 아직 원래 자리면 그리지 않는다
  (같은 칸에 실루엣과 본체가 겹치면 집었다는 느낌 대신 색만 흐려진 것처럼 보인다)
- 길은 `board.getMaxSteps()` 를 그대로 쓰므로 **실제로 갈 수 있는 만큼만** 그려진다
- 축이 아직 정해지지 않은 1x1(FREE) 오브젝트는 길을 그리지 않는다

### PUZ_01 레이저 — 크리스탈이 손가락에 달라붙는다

가장 크게 바뀐 퍼즐이다. `LaserCoreAPI` 가 드래그 상태를 직접 들고 있게 했다.

- 트레이 슬롯에서 집으면 → 그 슬롯이 `GHOST` 가 되어 "꺼냈다" 가 보인다
- 필드에서 집으면 → 원래 칸이 `GHOST` 가 된다 (보드는 손을 뗄 때까지 크리스탈을 그 자리에 두므로,
  이렇게 하지 않으면 크리스탈이 **둘로 보인다**)
- 손가락이 올라간 칸에 크리스탈을 그린다 → `GRABBED`
- 놓을 수 없는 칸이면 → `DROP_INVALID` (빨간 테두리). 세션의 `isValidTarget` 을 그대로 옮겼다

실루엣 자리는 손가락이 닿은 칸이 아니라 **크리스탈이 실제로 놓여 있던 칸**이다.
히트박스 보정(§8) 때문에 둘이 한 칸 어긋날 수 있다.

### PUZ_03 정렬 — 집은 건전지가 케이스 위에 떠서 따라다닌다

```
집기 전                     3번 케이스 위로 끌고 간 중
 1    2    3                 1    2    3
┌──┐ ┌──┐ ┌──┐             ┌──┐ ┌──┐ ┌──┐
│  │ │  │ │  │             │  │ │  │ │██│  ← GRABBED: 따라온 건전지
│██│ │  │ │  │             │░░│ │  │ │██│  ← GHOST: 덜어낸 자리
│██│ │  │ │▒▒│             │░░│ │  │ │▒▒│
│▒▒│ │▒▒│ │▒▒│             │▒▒│ │▒▒│ │▒▒│
└──┘ └──┘ └──┘             └──┘ └──┘ └──┘
```

화면에서는 집은 만큼을 출발 케이스에서 **덜어내고**, 손가락이 올라간 케이스의 스택 위에
그 건전지들을 얹어 그린다. 얹을 자리가 모자라면(케이스가 거의 찼다) 위쪽에 겹쳐 그리고
빨간 테두리를 붙인다 - 화면 밖으로 잘려 아무것도 안 보이는 것보다 "여기엔 안 들어간다" 가
그대로 읽힌다.

### PUZ_05 연결 — 그리는 머리가 떠오른다

경로의 머리에 `GRABBED` 를 준다. 손가락이 머리를 가려도 커진 만큼 밖으로 삐져나와
어디까지 그렸는지 보인다.

### 탭으로 푸는 넷 (PUZ_04·06·07·08) — 프레젠터가 공짜로 준다

"짚고 있는 칸은 눌린 티가 나야 한다" 는 퍼즐과 무관한 공통 규칙이다. 8개가 저마다
구현하면 같은 코드가 여덟 번 생기므로, **프레젠터가 한 번만 알리고 패널이 그린다.**

```ts
// PuzzleBoardUI_Presenter.ts
public readonly PRESS_CHANGED = new EventPublisher<PuzzleBoardPressHighlight>();
```

`*_CoreAPI` 는 아무것도 하지 않아도 된다. 이 넷은 **한 줄도 바뀌지 않았다.**

## 5. 왜 누름 표시를 칸 스냅샷에 넣지 않았나

넣었다면 이렇게 깨진다.

```
손가락 down  ─▶ 칸에 GRABBED 를 쓴다
세션이 반응  ─▶ CoreAPI 가 applyGridVisuals() 로 판을 다시 칠한다
                 └─▶ accent 가 NONE 으로 덮여 누름 표시가 사라진다
```

그래서 누름 표시는 칸 스냅샷과 **따로** 다니고, 패널이 렌더 시점에 둘을 합친다.

```ts
// PuzzleBoardUI_Panel.ts
const accent = Binding.derive(
    [cellBinding, this._pressedSlot],
    (cell, pressed) => mergePressAccent(cell.accent, pressed === slot),
);
```

`mergePressAccent()` 는 **퍼즐이 준 강조를 언제나 우선**한다. 러시아워에서 집어 든
오브젝트가 단순한 누름 표시에 덮이면 안 되기 때문이다.

## 6. 광채 고리는 하나를 나눠 쓴다

`AnimatedBinding` 을 칸마다 두면 9×9 = 81 개가 되고, 러시아워처럼 여러 칸을 한꺼번에
집는 퍼즐에서는 칸 수만큼 애니메이션이 **따로따로** 돌아 박자가 어긋난다.

그래서 패널에 **하나만** 둔다. 고리를 보일지 말지만 각 칸이 정하고, 크기와 진하기는
공유 값에서 온다. 고리는 `GRABBED` 인 자리가 처음 생길 때 한 번 터지고, 마지막 하나가
사라질 때 원래대로 돌아간다 (`_grabbedCount`).

> 처음에는 잡고 있는 내내 맥박이 뛰게 했는데 그것이 조작을 무겁게 만들었다. 8장 (3) 참고.

## 8. 2차 수정 — 반응 속도와 매끄러움

> 지시: "인터랙션이 전체적으로 반응속도도 느리고 매끄럽지 않다. 꾹 누른 상태에서
> 오브젝트를 잡고 이동하고, 손을 뗐을 때 바로 오브젝트가 뗀 위치에 멈춰 있게 해달라."

1차 구현을 인월드에서 만져 보니 **7장에서 "확인할 것" 으로 적어 둔 위험 두 개가 실제로
터졌다.** 원인은 넷이었고 전부 표현 계층에 있었다.

### (1) 확대가 입력 판정 영역까지 넓혔다 — 끈적이는 느낌의 주범

집은 칸에 `transform: scale` 을 걸었는데, 그것이 `Pressable` **자기 자신**에 붙어 있었다.
1.1배로 커진 칸이 이웃 칸을 덮으니 이웃의 `onEnter` 가 늦게 떴다. 손가락은 이미 옆 칸에
가 있는데 조각이 따라오지 않는다.

`Pressable` 을 **격자 한 칸의 자리만 지키는 투명한 껍데기**로 두고, 색·테두리·그림자·확대는
그 안의 "얼굴" `View` 가 맡게 나눴다. 얼굴이 아무리 커지고 작아져도 입력 영역은 칸 하나 그대로다.

```
Pressable  ← 크기를 바꾸는 스타일을 절대 걸지 않는다 (입력 판정 영역)
  ├── View "고리"   절대 위치, GRABBED 일 때만
  └── View "얼굴"   색·테두리·그림자·transform (보이는 것 전부)
        └── Text
```

### (2) 칸 사이 간격이 죽은 영역이었다 — 깜빡임의 주범

간격을 `margin` 으로 냈더니 그 틈이 **어느 칸에도 속하지 않았다.** 옆 칸으로 끌고 갈 때
손가락이 틈 위를 지나는 동안 "판 밖" 으로 읽혀, 끌던 조각이 사라졌다 나타났다.

`margin` 을 `padding` 으로 바꿔 간격까지 칸의 입력 영역에 넣었다. 이웃 칸끼리 맞닿으므로
손가락은 언제나 어느 한 칸 위에 있다. 그래도 `onExit` 가 `onEnter` 보다 먼저 도착하는
순간이 남을 수 있어, 레이저와 정렬은 **드래그 중의 "판 밖" 을 무시**한다 (러시아워·연결은
원래 그랬다). 진짜로 밖에 놓았는지는 손을 뗄 때 뗀 칸으로 판정하므로 규칙은 그대로다.

### (3) 잡고 있는 내내 애니메이션이 돌았다

광채 고리를 `Animation.repeat` 으로 계속 뛰게 했더니, 공유 보간 값이 **매 프레임 89개 노드**
(9×9 칸 + 8 슬롯)를 다시 그렸다. 지금은 집는 순간 180ms 동안 **한 번만** 터지고 고요한
고리로 남는다. 손가락이 닿자마자 무언가 튀어나오는 것이 오히려 반응이 빠르다는 인상을 준다.

### (4) 한 칸 안에서 움직여도 판을 통째로 다시 칠했다

`onCellMove` 마다 `applyGridVisuals()` / `applyBoardVisuals()` 를 불렀다. 러시아워는 81칸을
훑으며 오브젝트마다 점유 칸과 이동 가능 범위를 다시 구하고, 레이저는 49칸을 칠하고 광선
구간을 되짚는다. **화면이 바뀌지 않는데도** 그것을 돌리고 있었다.

세 퍼즐 모두 `trackDragTo()` 로 모아, 미리보기 자리나 놓을 수 있는지가 **실제로 바뀐 경우에만**
다시 그린다.

### (5) 손을 뗀 자리에 멈추지 않았다

러시아워는 `onCellUp` 이 **뗀 칸을 버리고** 곧바로 `endDrag()` 를 불렀다. 그러면 마지막
`onCellMove` 가 기록한 자리로 스냅된다 — 빠르게 끌다 놓으면 손가락이 지나온 칸에 조각이 남는다.
연결 퍼즐도 같은 이유로 선이 손가락보다 한두 칸 뒤에서 끊겼다.

네 퍼즐 모두 **뗀 칸을 마지막으로 한 번 더 반영한 뒤** 확정한다.

| 퍼즐 | 전 | 후 |
|---|---|---|
| 러시아워 | `onCellUp: () => onDragEnd()` | `onCellUp: (cell) => onDragEnd(cell)` |
| 연결 | `onCellUp: () => onDrawEnd()` | `onCellUp: (cell) => onDrawEnd(cell)` |
| 레이저 | 이미 반영 | `trackDragTo(cell)` 로 통일 |
| 정렬 | `endDrag(caseIndex)` 만 | `trackDragTo` + `endDrag` |

## 10. 3차 수정 — 남아 있던 지연 요소

> 지시: "지금도 여전히 인터랙션에 지연시간이 존재하는 느낌이다. 관련 파라미터가 있으면
> 줄이고, 로직상 다른 곳에도 지연에 영향이 있는 요소가 있으면 지연이 최대한 느껴지지
> 않게 수정해달라."

코드 전반을 다시 훑어 입력 경로에 남아 있던 지연을 셋 찾았다. 매 프레임 도는 것은 없었다 -
타이머(`TIME_CHANGED`)는 초가 바뀔 때만 발행되고, 애니메이션은 집는 순간 한 번뿐이다.

### (1) 시작 배너가 입력을 약 1초 잠갔다 — 가장 컸다

레벨이 시작되면 `GameStart` 배너가 완전히 보이는 0.6초 + 페이드 0.4초 = **약 1초 동안
보드 입력이 통째로 막혔다** (`canAcceptInput()` 이 배너 표시와 묶여 있었다). 시작하자마자
조각으로 손이 가는 플레이어에게는 첫 터치가 그냥 삼켜지고, 그것이 "반응이 느리다" 로 읽힌다.

두 가지로 줄였다.

- **입력 잠금과 배너 표시를 분리했다** (`PuzzleBoardPresenter.unlockIntroInput()`).
  배너는 보조 레이아웃 자리에 떠서 판을 가리지 않으므로, 페이드가 시작되는 순간
  입력을 먼저 연다. 배너는 계속 잦아들면서 사라진다.
- 기본값을 줄였다: `introSeconds` 0.6 → **0.45**, `introFadeSeconds` 0.4 → **0.3**.

입력 잠금이 1.0초 → **0.45초**가 됐다. **에디터 gizmo 에 이 prop 을 직접 넣어 두었다면
그 값이 이기므로, 낡은 값이 남아 있지 않은지 확인한다.**

### (2) 슬라이드·카드가 릴리즈를 기다렸다

두 퍼즐이 `onCellTap`(누르고 **떼야** 확정)으로 묶여 있었다. 손가락이 떨어질 때까지의
시간(대략 0.1초)이 매 탭마다 지연으로 얹힌다. `onCellDown`(누르는 순간)으로 바꿨다 -
색 채우기가 STOP 버튼을 `onPress` 로 받는 것과 같은 원칙이다.

| 퍼즐 | 전 | 후 |
|---|---|---|
| 슬라이드 | `onCellTap` → `pressPiece` | `onCellDown` → `pressPiece` |
| 카드 맞추기 | `onCellTap` → `revealTile` | `onCellDown` → `revealTile` |

탭을 시작하고 칸 밖으로 미끄러져 취소하는 동작은 사라지지만, 이 두 퍼즐의 탭은 무르기가
없는 단순 조작이라 취소보다 즉답이 중요하다. 스위치는 "누른 칸에서 떼야 확정" 이
게임 규칙(PUZ_08 M2)이라 그대로 둔다.

### (3) 확인한 것 - 더 줄일 것이 없던 자리

| 자리 | 확인 결과 |
|---|---|
| 드래그 이동 경로 | `trackDragTo()` 가 자리·유효성이 바뀐 경우에만 다시 그린다 (8장 (4)) |
| 누름 표시 | 자리별 Binding 플래그라 짚은 자리가 옮겨져도 두 자리만 갱신된다 |
| 타이머 HUD | 세션이 초가 바뀔 때만 `TIME_CHANGED` 를 발행한다 |
| 상시 애니메이션 | 없음 - 고리는 고정 진하기, 배너 페이드는 레벨 시작 한 번뿐 |
| 색 채우기 STOP | 이미 `onPress` (릴리즈를 기다리지 않는다) |

검증: 타입 체크·에디터 제약 검사 에러 0건 (`Documents/SampleHtml/game.ts` 의 DOM 오류는
참고용 샘플의 기존 문제로 무관), 전체 테스트 **1,373 PASS / 0 FAIL** (배너 조기 해제
검사 3건 추가).
