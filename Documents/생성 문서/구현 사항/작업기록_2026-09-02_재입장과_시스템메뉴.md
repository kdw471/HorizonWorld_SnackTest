## 1. 재입장하면 직전 레벨이 다시 뜨던 이유

퍼즐 허브의 두 접점은 **모듈 싱글턴**이다.

| 싱글턴 | 무엇을 들고 있나 |
|---|---|
| `PuzzleHubRegistry.instance` | 퍼즐별 구동 핸들 |
| `PuzzleBoardStage.instance` | **지금 화면에 올라가 있는 보드 하나** |

플레이어가 월드를 나가면 엔티티 소유권이 서버로 돌아가고, 다시 들어오면
`Puzzle_LocalOwnership` 이 소유권을 넘기면서 패널과 `*_CoreAPI` 가 다시 만들어진다. 그런데
**싱글턴은 그 사이에 초기화되지 않는다.** 그래서 스테이지에는 앞선 생에서 올려 둔
프레젠터가 그대로 남아 있다.

보드 패널은 붙자마자 그것을 집어 그린다.

```ts
// PuzzleBoardUI_Panel.connectStage() - CoreAPI 가 먼저 mount() 했을 수 있으므로
const current = stage.current;
if (current !== undefined) {
	this.attachPresenter(current);
}
```

이 경로가 원래는 "CoreAPI 등록 순서가 보장되지 않는다" 를 메우려는 것이었는데, 재입장에서는
**직전에 풀던 판을 다시 띄우는 경로**가 되어 버렸다.

### 수정 - 허브가 새로 시작할 때 한 번 정리한다

`PuzzleUI_MainPanel.initializeUI()` 마지막에 `bootToMainMenu()` 를 부른다.

```ts
private bootToMainMenu(): void {
	// 어느 쪽이 먼저 살아나는지 보장되지 않으므로 둘 다 친다.
	this._model?.resetToMainMenu();          // 남은 핸들을 abort + 화면을 메인 메뉴로
	PuzzleBoardStage.instance.reset();       // 핸들이 바뀐 뒤에도 남아 있는 보드를 내린다
}
```

새로 붙인 것은 셋이다.

- `PuzzleHubRegistry.abortAll()` — 등록된 모든 핸들을 대기 상태로 되돌린다. 재등록으로 핸들이
  교체되기 전에 남아 있던 세션도 함께 정리된다.
- `PuzzleHubModel.resetToMainMenu()` — `quitToMenu()` 와 달리 **어느 화면에서든 무조건**
  메인 메뉴로 맞춘다. 진행 중이던 레벨 표시와 마지막 결과도 지운다.
- `PuzzleBoardStage.reset()` — 올라가 있던 보드를 무조건 내린다.

**진행도는 이 정리에 포함되지 않는다.** 클리어 기록은 `PuzzleProgressTracker` 가 따로 들고
있고, 영구 변수를 쓰도록 설정되어 있으면 `createProgressTracker()` 가 재입장 때 다시 읽는다.
그래서 "메인 메뉴로 들어오되 저장된 진도는 그대로" 가 된다.

> 영구 변수 그룹이 없는 월드에서는 메모리 저장으로 떨어져 진행도가 세션 동안만 유지된다.
> 어느 쪽으로 붙었는지는 시작 시 콘솔에 찍힌다 (`PuzzleUI_PersistentProgress.ts` 머리말).

`*_CoreAPI` 의 `autoStart` 는 이 정리에 걸릴 수 있다. 원래 그 옵션은 허브 없이 퍼즐 하나만
시험할 때 쓰는 개발용이고 기본값도 꺼짐이다 - 게임은 언제나 메인 메뉴에서 시작한다.

## 2. 시스템 메뉴

인게임 상단 바 오른쪽 버튼(라벨 `MENU`)을 누르면 뜬다. 예전에는 Resume / Quit 두 개였다.

```
        ┌────────────────────────┐
        │        Paused          │
        │  ┌──────────────────┐  │
        │  │      Resume      │  │  닫고 다시 푼다 (시간이 이어서 흐른다)
        │  ├──────────────────┤  │
        │  │  Restart Level   │  │  이 레벨을 처음부터 - 타이머도 초기화
        │  ├──────────────────┤  │
        │  │  Return to Main  │  │  메인 메뉴로 (퍼즐은 버려진다)
        │  └──────────────────┘  │
        └────────────────────────┘
```

### 타이머는 이미 멈춘다

버튼은 `PuzzleHubModel.pauseGame()` 을 부르고, 그것이 핸들을 거쳐 세션의 `pause()` 까지
내려간다. 세션이 `PAUSED` 가 되면 `update()` 가 남은 시간을 줄이지 않는다. 각 `*_CoreAPI`
의 `pause()` 는 보드를 화면에서 내리므로 이 오버레이가 가려지지도 않는다.

### Restart Level - 새로 붙인 동작

`PuzzleHubModel.restartLevel()` 을 추가했다. 보조 레이아웃의 Reset 버튼과 다르다.

| | 판 | 남은 시간 |
|---|---|---|
| Reset (보조 레이아웃) | 되돌린다 | **유지** |
| Restart Level (시스템 메뉴) | 레벨을 다시 연다 | **초기화** |

Reset 이 시간을 되돌리지 않는 것은 그것이 곧 무한 연장이 되기 때문이고, Restart Level 은
레벨을 다시 시작하는 것이므로 시간도 처음으로 돌아가는 것이 맞다.

**일시정지 중에도 통해야 한다** - 그 버튼이 떠 있는 곳이 바로 일시정지 화면이다. 세션의
`startLevel()` 이 상태를 통째로 다시 잡으므로(`beginQuest()` → `startRound()` → `PLAYER_INPUT`)
멈춰 있던 상태도 그대로 풀리고, 모델이 화면을 인게임으로 되돌린다.

### Return to Main

기존 `quitToMenu()` 그대로다. 라벨만 `Quit` 에서 바꿨다.

## 3. 검증

`PuzzleUI_Tests.ts` 의 `testModelRestartAndBoot()`.

- Restart Level 이 메인 메뉴·상세 화면에서는 거절되고, **일시정지 중에는 같은 레벨을 다시 여는지**
- 다시 연 뒤 화면이 인게임으로 돌아오는지
- `resetToMainMenu()` 가 어느 화면에서든 메인 메뉴로 맞추고 돌던 퍼즐을 abort 하는지
- 그 정리 뒤에도 **진행도가 그대로 남는지**, 진행 중이던 레벨 표시는 지워지는지
- 정리 뒤 잔여 이벤트가 화면을 되돌리지 못하는지

`PuzzleBoardUI_Tests.ts` 의 `testStage()` 에는 `reset()` 이 올라가 있던 보드를 내리고 빈
상태에서는 아무 일도 하지 않는지를 더했다.
