# 작업기록 2026-09-02 — 퍼즐 요소에 텍스처 입히기 (에디터 prop)

> 지시: `worker/NextJob.md` 1번 — "각 퍼즐의 요소들에 특정 텍스쳐를 입히고 싶은데,
> 파라미터로 넣어줄 수 있게 로직을 수정해줘"
> 관련 문서: `작업기록_2026-09-02_퍼즐_공통_UI_레이아웃.md` (보조 레이아웃·트레이),
> `../가이드/에디터_퍼즐_셋업.md` (에디터에서 끼우는 법)

8개 퍼즐의 판 위 요소(키 캡·크리스탈·카드·배터리 …)에 **PNG 텍스처를 입힐 수 있게** 했다.
텍스처는 각 `*_CoreAPI` 의 **에디터 prop** 으로 넣고, **비워 두면 예전처럼 색으로 그려진다.**

---

## 1. 왜 이 구조인가 — 키와 그림을 갈라 놓았다

순수 계층(`PuzzleBoardUI_Definitions`)은 `horizon/*` 를 import 할 수 없다. Node 테스트가
통째로 돌지 않기 때문이다 (PUZ_00 §7.1). 그런데 `ImageSource` 도 `TextureAsset` 도 전부
`horizon/*` 에 있다.

그래서 **색과 똑같은 방식**을 썼다. 색을 `Color` 가 아니라 `{r,g,b}` 로 들고 다니듯,
텍스처는 `TextureAsset` 이 아니라 **논리적인 이름(키)** 으로 들고 다닌다.

```
*_CoreAPI                     PuzzleBoardUI_TextureLibrary          PuzzleBoardUI_Panel
  에디터 prop 의 Asset   ──register('switch.pressed', asset)──▶  ──resolve(키)──▶ Image
        │
        └─ setCell(cell, { texture: 'switch.pressed' })  ──▶  순수 계층에는 문자열만 남는다
```

| 계층 | 아는 것 |
|---|---|
| `PuzzleBoardUI_Definitions` (순수) | 키 문자열뿐. `PuzzleTextureKey` / `NO_TEXTURE` / `textureKey()` |
| `PuzzleBoardUI_TextureLibrary` (표현) | 키 → `ImageSource`. 이 파일만 `horizon/ui` 를 안다 |
| `PuzzleBoardUI_Panel` (표현) | 칸을 그릴 때 키를 그림으로 바꿔 얹는다 |
| `*_CoreAPI` | 자기 요소의 키를 정하고 에디터 prop 의 애셋을 붙인다 |

**등록되지 않은 키는 조용히 무시된다.** 에디터에서 prop 을 비워 두는 것이 정상 상태이므로,
없는 그림을 오류로 다루지 않는다. 그 요소는 예전 그대로 `fill` 색으로 그려진다.

---

## 2. 어디에 그림이 들어가는가

칸(`cell.texture`) · 트레이 슬롯(`item.texture`) · 판 배경(`view.boardTexture`) 셋이다.

```
┌─ 판 배경 (boardTexture) ─────────┐   ← 칸 사이 간격으로 비쳐 보인다.
│  ┌────┐ ┌────┐ ┌────┐            │     나무판·회로기판처럼 판 전체의 재질
│  │ 칸 │ │ 칸 │ │ 칸 │            │
│  └────┘ └────┘ └────┘            │   ← 칸: 색 위에 그림, 그림 위에 글자
└──────────────────────────────────┘
┌─ 트레이 ─────────────┬─ Reset ──┐   ← 슬롯도 칸과 같은 규칙
└──────────────────────┴──────────┘
```

칸 안의 층 순서는 **색 → 그림 → 글자** 다. 그림을 넣어도 라벨(숫자·기호)은 위에 남아 읽힌다.
방향 무늬(`glyph`)의 테두리도 그대로 그려지므로, 레이저 크리스탈에 그림을 입혀도
"어느 변이 막혔는지" 는 사라지지 않는다.

### 2.1 회색조 한 장으로 여러 상태 그리기

보드 패널의 `tintTexturesWithFill` 을 켜면 그림이 **칸 색으로 물든다**(`tintOperation: multiply`).
스위치 키 캡 그림 한 장으로 눌림(초록)과 안 눌림(빨강)을 모두 그릴 수 있다.
이미 색이 칠해진 그림을 쓸 거면 꺼 둔다 (기본값 꺼짐).

---

## 3. 퍼즐별 텍스처 prop

전부 선택이다. 비워 둔 prop 은 색으로 그려진다. 키는 `퍼즐.요소` 꼴이다.

| 퍼즐 | prop |
|---|---|
| PUZ_01 레이저 | `crystalTexture` `fixedCrystalTexture` `relayTexture` `skullTexture` `gimmickTexture`(발사체·수신체) `placementTexture` `borderTexture` `boardTexture` |
| PUZ_02 러시아워 | `goalPieceTexture` `blockerPieceTexture` `emptyTexture` `borderTexture` `boardTexture` |
| PUZ_03 정렬 | `batteryTexture` `unknownTexture` `emptySlotTexture` `lockedSlotTexture` `boardTexture` |
| PUZ_04 색 채우기 | `cleanTexture` `contaminatedTexture` `inactiveTexture` `needleTexture` `boardTexture` |
| PUZ_05 연결 | `nodeTexture`(전구) `pathTexture`(지나간 칸) `emptyTexture` `boardTexture` |
| PUZ_06 카드 맞추기 | `hiddenTexture` `revealedTexture` `matchedTexture` `bombTexture` `boardTexture` |
| PUZ_07 슬라이드 | `pieceTexture` `emptyTexture` `boardTexture` |
| PUZ_08 스위치 | `pressedTexture` `unpressedTexture` `maskOnTexture` `maskOffTexture` `boardTexture` |

각 CoreAPI 는 시작할 때 몇 개가 등록됐는지 콘솔에 남긴다.

```
[SwitchCoreAPI] Registered 2 textures. Elements without one are drawn with a flat colour.
```

### 3.1 상태가 갈리는 자리는 색과 같은 갈래를 탄다

그림 선택은 **이미 있던 색 선택 코드 옆에 나란히** 놓았다. 예를 들어 카드 맞추기는
`getTileColor()` 와 똑같은 조건의 `getTileTexture()` 를 둔다. 색과 그림이 어긋날 수 없다.

색을 덮어쓰는 자리(레이저의 광선 구간, 러시아워의 도착 포인트)는 **그림을 지정하지 않는다.**
그러면 바탕에서 칠해 둔 그림이 그대로 남아, 광선이 지나가도 판 무늬가 유지된다.

---

## 4. 등록 순서를 신경 쓰지 않아도 되는 이유

`*_CoreAPI` 의 `start()` 와 패널의 `initializeUI()` 중 **어느 쪽이 먼저 도는지는 보장되지
않는다.** 패널이 먼저 그려졌다면 그 시점에는 아직 등록된 그림이 없다.

그래서 `Image` 의 `source` 를 **칸 스냅샷과 "텍스처 세대" 둘 다에서** 파생시켰다.

```ts
Binding.derive([cellBinding, this._textureEpoch], (cell, _epoch) => library.resolve(cell.texture))
```

라이브러리가 `CHANGED` 를 내면 패널이 세대를 하나 올리고, 이미 그려진 칸들의 그림이 다시
계산된다. **칸 내용은 건드리지 않으므로** 드래그 중에 등록이 끼어들어도 조작이 끊기지 않는다.

## 6. 에디터에서 하는 일

```
1. PNG 를 애셋 라이브러리에 올린다 (Texture 애셋이 된다)
2. PuzzleController 의 <요소>Texture prop 에 그 애셋을 끼운다
3. 회색조 한 장으로 여러 상태를 그릴 거면 BoardPanel 의 tintTexturesWithFill 을 켠다
```

**아무것도 하지 않아도 게임은 그대로 돌아간다.** 그림이 없으면 색으로 그려질 뿐이다.
