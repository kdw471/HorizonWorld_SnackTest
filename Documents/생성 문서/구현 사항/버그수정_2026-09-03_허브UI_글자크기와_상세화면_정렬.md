# 버그수정 2026-09-03 — 허브 UI 의 글자 크기와 상세 화면 정렬

> 신고 (실기 스크린샷 2장): "메인 메뉴 폰트가 너무 작다", "퍼즐을 고르면 Start/Continue/Return 이
> 위쪽에 몰려 있다. 세로 가운데로, 메인 메뉴와 비슷한 레이아웃이면 좋겠다"
> 뿌리가 같은 문제: `작업기록_2026-09-03_보드UI_상대배치_전면개편.md` §1 (보드 패널의 같은 단위 문제)

---

## 1. 두 증상의 뿌리는 하나였다

보드 패널에서 잡은 것과 **같은 단위 문제**다. 패널이 실제로 그려지는 좌표계는 디바이스
실픽셀(1179x2556)인데 `player.screenWidth/screenHeight` 는 긴 변을 1280 으로 정규화한
값(590x1280)을 준다. 허브 패널은 그 읽기값을 두 곳에 쓰고 있었다.

| 쓰인 곳 | 증상 |
|---|---|
| `fitFontSize` 의 `pixelScale` = `canvasPixelScale(canvas.height)` | 글자 한계(min/max)가 **절반**으로 환산되어 모든 글자가 상한에 걸린 채 깨알이 되었다 |
| `vh(percent)` = `verticalPixels(canvas, percent)` | 세로 여백이 **절반**으로 그려졌다. 상세 화면의 `marginTop: vh(12) + vh(30)` = 42% 가 실제로는 약 20% 로 나와, 세 버튼이 화면 위쪽에 몰리고 아래 절반이 통째로 비었다 |
| `screenPadding()` 의 안전 여백 | 역시 절반이라 상세 화면의 제목이 노치 뒤로 잘려 들어갔다 (스크린샷 2 의 위쪽 잘린 글자) |

즉 "글자가 작다" 와 "버튼이 위로 몰렸다" 는 같은 원인의 두 얼굴이었다.

## 2. 고친 것

### 좌표 단위 도입 (보드 패널과 같은 방식)

- `screenPixelRatio` prop 추가 (기본 2). **보드 패널과 같은 값을 넣어야 한다.**
- `screenUnitsHeight` = 읽기값 세로 × 배율 → 화면 세로를 좌표 단위로
- `pxScale`/`px()` 를 그 위에 얹고, `vh()` 도 좌표 단위로 계산
- `_usableHeight` 와 `_safeArea` 도 좌표 단위로 (안전 여백은 계산 후 배율을 곱한다)
- 카탈로그 카드의 글자 세 줄이 아직 `canvasPixelScale(canvas.height)` 를 직접 쓰고 있었다 —
  전부 `this.pxScale` 로. **이것이 메인 메뉴 글씨가 작던 직접 원인이다.**
- 모서리 둥글기(`borderRadius: 12/14/10`)도 좌표 단위로 — 절반이면 카드가 각져 보인다

prop 은 **`resolveLayout()` 에서 한 번만** 읽어 `_pixelRatio` 필드에 넣는다. 필드
초기화에서 `this.props` 를 읽으면 컴포넌트가 아예 만들어지지 않기 때문이다
(`작업기록_2026-09-03_보드UI_상대배치_전면개편.md` §5 에서 실제로 겪었다).

### 상세 화면을 세로 가운데로

컨테이너에 `flexDirection: 'column'` + `justifyContent: 'center'` 를 주고, 위에서 밀어
내리던 `marginTop: vh(12)`(제목)과 `vh(30)`(버튼 묶음)을 걷어냈다. 버튼 묶음에는 제목
덩어리와 분리되어 보일 만큼의 틈(`vh(5)`)만 남겼다.

**픽셀로 밀어 내리는 대신 흐름의 정렬로 가운데를 잡는 것**이 요점이다. 그러면 배율이나
화면 크기와 무관하게 언제나 가운데에 온다 — 메인 메뉴의 격자가 그렇게 보이는 것과 같은 이유다.

## 3. 곁다리로 함께 제자리를 찾은 것

일시정지 오버레이(`marginTop: vh(26)`)와 결과 화면(`vh(24)`)은 **화면 세로 대비 %** 라
계산 자체는 옳았는데, `vh()` 가 절반을 돌려주는 바람에 의도한 26%/24% 가 아니라 12% 쯤에
그려지고 있었다. 단위를 고치면서 원래 의도한 자리로 돌아왔다. 넘침은 없다 —
결과 화면이 24% + 제목·설명 + 버튼 셋(각 11% + 여백 4%) = 약 74% 다.

두 화면도 상세 화면처럼 완전히 가운데로 모을 수 있지만, 지금은 의도한 자리에 있으므로
그대로 두었다.

## 4. 검증

| 검사 | 결과 |
|---|---|
| `tsc --noEmit --skipLibCheck` | 에러 0 |
| 에디터 제약 재현 (`--target ES5 --lib ES2020`) | 에러 0 |
| Node 테스트 — 메인 UI + 보드 UI | 380 PASS / 0 FAIL (글자 크기 회귀 3건 신규) |

새로 못박은 회귀 테스트는 이렇다.

- 좌표 단위 기준 배율이 읽기값 기준 배율보다 **1.9배 이상** 크다
- 실측 폰에서 카탈로그 카드 제목이 **화면 세로의 2% 이상** (2556px 화면에서 약 51px —
  팔 길이에서 읽히는 최소선)
- **같은 계산을 읽기값 배율로 하면 그 선에 못 미친다** — 신고된 증상 자체를 테스트로 박아 두어,
  누가 배율 기준을 되돌리면 바로 빨간불이 켜진다

## 5. 에디터에서 할 일

허브 패널(`PuzzleUI_MainPanel`)에도 **`screenPixelRatio` 를 보드 패널과 같은 값으로** 둔다.
기본값 2 가 실측 iPhone 기준이므로 보통은 건드릴 것이 없다. 다른 기기에서 글자만 크거나
작으면 그 기기에서 다시 잰다 — 재는 법은 `가이드/에디터_퍼즐_셋업.md` 의 prop 표에 있다.
