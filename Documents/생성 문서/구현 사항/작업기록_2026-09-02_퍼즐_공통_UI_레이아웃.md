## 2. 화면 구성

두 개의 Custom UI 패널이 **세로 비율로 자리를 나눠 갖는다.** 둘 다 Screen Overlay 라
겹칠 수 있으므로, 보드 패널이 위쪽 `topInsetPercent`(기본 11%)를 비워 두고 그 자리에
허브 패널의 HUD 바가 앉는다.

```
┌────────────────────────────────────────┐
│  LV 3 / 24            07          [II] │  ← PuzzleUI_MainPanel (HUD 바, 7%)
│  ┌──────────────────────────────────┐  │
│  │                                  │  │
│  │        본 격자 (정사각형)          │  │  ← PuzzleBoardUI_Panel
│  │                                  │  │     boardAreaPercent 55%
│  └──────────────────────────────────┘  │
│  ┌──────────────────────────────────┐  │
│  │ [크리스탈 트레이] [미니격자] [Reset] │  │     auxAreaPercent 28%
│  └──────────────────────────────────┘  │
└────────────────────────────────────────┘
```

레벨이 시작되면 아래 칸이 이렇게 바뀐다.

```
레벨 시작 ──▶ ┌──────────────┐  introSeconds ┌───────────────────────┐
              │  GameStart   │ ────────────▶ │ 트레이 · 미니격자 · Reset │
              └──────────────┘  (배너 소멸)   └───────────────────────┘
```

배너가 떠 있는 동안 보조 레이아웃은 `display: none` 이다. **"배너가 사라진 뒤에 나타난다"**
는 요구를 두 `display` 를 서로 반대로 두는 것으로 지켰다.

## 3. 보조 레이아웃에 무엇이 들어가는가

세 자리가 있고, 퍼즐마다 쓰는 자리가 다르다. **리셋 버튼만 8종 공통**이다.

| 자리 | 타입 | 쓰는 퍼즐 | 내용 |
|---|---|---|---|
| 오브젝트 트레이 | `PuzzleBoardItemView[]` | PUZ_01 레이저 | 아직 배치하지 않은 크리스탈. **누를 수 있다** |
| 정보 미니 격자 | `PuzzleBoardSideView` | PUZ_08 스위치 | 이번 라운드의 동시 눌림 영역 3×3. 표시 전용 |
| 리셋 버튼 | — | 8종 전부 | 판을 풀기 전 상태로 (§5) |

나머지 여섯 퍼즐은 판 안에서 모든 것이 끝나므로 트레이도 미니 격자도 쓰지 않는다.
그 경우 보조 레이아웃에는 리셋 버튼만 남는다.

### 3.1 레이저 인벤토리가 격자 밖으로 나왔다

예전에는 보조 격자가 **표시 전용이라 누를 수 없어서**, 인벤토리를 본 격자의 9번째 열에
끼워 넣었다 (7열 + 여백 1열 + 인벤토리 1열).

```
이전   col  0 1 2 3 4 5 6   7    8        지금   ┌ 본 격자 7×7 ┐
            └─ 전체 7×7 ─┘  빈칸  인벤토리         └────────────┘
                                                 ┌ 트레이: 크리스탈 · Reset ┐
                                                 └────────────────────────┘
```

트레이가 입력을 받게 되면서 그 여분 열이 사라졌고, **본 격자가 기획 그대로 7×7 정사각형**이
됐다 (`BOARD_COL_COUNT` = `LASER_FULL_GRID_SIZE`).

## 4. 누름의 출발지가 둘이 됐다

`PuzzleBoardPresenter` 가 들고 있던 "지금 누르고 있는 칸"(`_pressedCell: number`)을
"지금 누름이 시작된 자리"(`_press: PuzzleBoardPressOrigin`)로 넓혔다.

```ts
type PuzzleBoardPressOrigin =
    | { kind: 'cell', index: number }
    | { kind: 'item', index: number };
```

이후 경로는 하나로 합쳐진다 — 세션은 드랍 지점만 알면 되므로 출발지를 구분하지 않는다.

```
itemDown(slot) ─┐
                ├─▶ pointerEnter(cell) ... ─▶ pointerUp() ─▶ onCellUp(뗀 칸)
pointerDown(cell) ┘
```

그 위에 편의 콜백이 둘 붙는다.

| 상황 | 추가로 나가는 콜백 |
|---|---|
| 칸에서 시작해 **같은 칸**에서 뗐다 | `onCellTap(cell)` (기존) |
| 슬롯에서 시작해 **판 밖**에서 뗐다 | `onItemTap(slot)` — 끌지 않고 툭 누른 경우 |

단일 터치 강제(PUZ_00 §8.1)도 둘을 합쳐 하나로 센다. 슬롯을 집고 있는 동안 칸의 `down` 은
무시되고, 그 반대도 마찬가지다.

## 5. 리셋 — 판은 되돌리고 시간은 되돌리지 않는다

**남은 시간을 함께 되돌리면 리셋 버튼이 곧 무한 연장이 된다.** 그래서 되돌리는 범위를
"판" 으로만 한정했다.

세션 8종의 `startRound()` 를 둘로 쪼갰다.

```
startRound()  = 판 고르기 + 시간 초기화 + openLevel(level)
resetRound()  =                          openLevel(지금 판)
```

`openLevel()` 이 보드·컨트롤러를 다시 만들고 `LEVEL_LOADED` 를 다시 발행하므로,
각 `*_CoreAPI` 는 **아무것도 바꾸지 않아도** 화면이 처음 상태로 다시 그려진다.

| 항목 | 리셋 시 |
|---|---|
| 보드 상태 (놓은 말, 그린 선, 눌린 키) | 처음으로 되돌아간다 |
| 남은 시간 | **그대로 흐른다** |
| 판 선택 | 새로 고르지 않는다 (지금 레벨 그대로) |
| 라운드 진행도 | 그대로 |

카드 맞추기(PUZ_06)만 배치를 다시 섞는다. 카드가 전부 닫힌 상태가 곧 "풀기 전" 인데,
이미 본 배치를 그대로 다시 주면 리셋이 정답 확인 수단이 되기 때문이다.
(`seed` 를 준 세션은 같은 배치가 다시 나온다 — 테스트 재현성 때문이다.)

**언제 받는가** — 판이 열려 있고 아직 끝나지 않았을 때만이다. 두 겹으로 막는다.

```
프레젠터   입력이 꺼져 있으면(일시정지·결과 화면) requestReset() 이 false
세션       상태가 ROUND_INTRO / PLAYER_INPUT (러시아워는 MOVING 포함) 이 아니면 false
```

메인 UI 쪽에도 `PuzzleHubModel.resetLevel()` 로 같은 경로를 열어 두었다. 화면 상태가
`IN_GAME` 일 때만 통한다.

## 6. 상단 HUD

```
┌──────────────────────────────────────┐
│  LV 3 / 24            07        [II] │
│  R 1/3                               │
└──────────────────────────────────────┘
   좌 22%          가운데 flex     우 22%
```

좌우 블록의 폭을 같게(22%) 잡아 **가운데 숫자가 화면 정중앙**에 오게 했다.

남은 시간은 `formatSecondsLabel()` 로 **초 단위 숫자 하나**만 그린다 (분:초로 접지 않는다).
`formatClockLabel()`("1:05")은 결과 화면의 통계에만 남았다.

### 6.1 초읽기 (10초 미만)

| 무엇 | 어디서 정하는가 |
|---|---|
| 언제가 초읽기인가 | 순수 계층 `isTimeCritical(seconds)` — `0 < seconds < 10` |
| 색 | `COLOR_TIME_CRITICAL` (빨강) |
| 점멸 | 패널의 `setInterval`, 주기 `HUD_CRITICAL_BLINK_SECONDS`(0.5초) |
| 소리 | `countdownSound` prop 의 Audio gizmo 를 **초가 바뀔 때만** 재생 |

점멸은 글자를 지웠다 그리지 않고 **투명도만** 바꾼다. 글자를 지우면 폭이 흔들려 숫자가
좌우로 움직인다.

0초는 초읽기가 아니다 — 이미 끝난 시간을 두고 점멸시킬 이유가 없다. 인게임을 벗어나면
(결과·메뉴) 인터벌을 반드시 멈추고 **켜짐 상태로 되돌린다.** 꺼진 채로 멈추면 다음 판의
숫자가 보이지 않는다.

`countdownSound` 를 비워 두면 소리 없이 점멸만 한다. 소리는 있으면 좋은 것이지 없으면
안 되는 것이 아니다.

## 7. 결과 화면

| 결과 | 버튼 |
|---|---|
| 클리어 | Restart / **Next Level** / Return to Main |
| 실패 | Restart / Return to Main |

`Next Level` 하나만 조건부로 나타난다. **마지막 레벨을 깼을 때도 숨긴다** — 갈 곳이 없는데
버튼만 남겨 두면 눌러도 아무 일이 없다 (`PuzzleHubModel.canPlayNextLevel()`).

이름만 바뀐 것이 둘 있다: `Retry` → `Restart`, `Menu` → `Return to Main`.
동작은 기존 `retry()` / `quitToMenu()` 그대로다.

## 9. 검증

`../가이드/타입체크와_테스트_실행.md` 의 §1 · §2 · §3 전부 통과.

```
PUZ_01 레이저             110 PASS / 0 FAIL
PUZ_02 러시아워             83 PASS / 0 FAIL
PUZ_03 정렬               124 PASS / 0 FAIL
PUZ_04 색 채우기           111 PASS / 0 FAIL
PUZ_05 연결               115 PASS / 0 FAIL
PUZ_06 카드 맞추기         127 PASS / 0 FAIL
PUZ_07 슬라이드            164 PASS / 0 FAIL
PUZ_08 스위치             139 PASS / 0 FAIL
메인 UI 허브              118 PASS / 0 FAIL   (+25)
보드 UI                    67 PASS / 0 FAIL   (+21)
                       --------------------
합계                    1,158 PASS / 0 FAIL
```

새로 추가한 검증은 이렇다.

**보드 UI** — 트레이 슬롯의 패치/동등 비교, `itemCount` 규격 검증, 빈 슬롯은 집히지 않음,
집는 중 다른 슬롯·칸의 down 무시, 트레이 → 판 드래그의 콜백 순서가 칸에서 집은 것과 같음,
끌지 않고 뗐을 때의 `onItemTap`, 리셋이 누름을 마감하고 입력이 꺼져 있으면 거절되는 것,
배너의 켜기/끄기 멱등성과 보드를 내릴 때 함께 꺼지는 것.

**메인 UI** — 초 라벨(정수/올림/음수/분으로 접지 않음), 초읽기 경계(10초 정각은 아직 아님,
0초는 제외), 레벨 라벨, HUD 스냅샷 반영, 리셋이 메뉴·상세·일시정지·결과에서 거절되고
인게임에서만 핸들까지 내려가는 것.

**실제 스위치 세션과의 통합** — 정답이 **아닌** 칸을 눌러 판을 흐트러뜨린 뒤 3초를 흘리고
리셋하면, 안 눌린 키 캡 수가 처음으로 돌아가고 **남은 시간은 그대로**인지.
(정답 칸을 눌렀다가 그것으로 판이 끝나면 리셋이 거절되는 것이 옳은 동작이라,
검증할 기회 자체가 사라진다.)

## 10. 남은 것

- 나머지 여섯 퍼즐의 보조 레이아웃은 지금 리셋 버튼만 있다. 판 밖에 둘 정보가 생기면
  `side` 나 `items` 에 얹으면 되고, 패널은 손대지 않아도 된다.
- `countdownSound` 는 에디터에서 Audio gizmo 를 만들어 연결해야 소리가 난다. 연결 전에는
  점멸만 한다.
- 보드 패널과 허브 패널이 세로 비율로 자리를 나누므로, `topInsetPercent` 를 바꾸면
  HUD 바 높이(7% + 상단 여백 2%)와 함께 봐야 한다.
