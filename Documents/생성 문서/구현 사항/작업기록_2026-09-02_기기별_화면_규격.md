## 1. 격자가 화면을 넘어가던 이유

예전 본 격자는 정사각형을 이렇게 잡았다.

```ts
View({ style: { height: '100%', aspectRatio: 1 } })
```

이 방식은 **세로만 보고 가로를 정한다.** 화면이 세로로 길수록(폰은 19.5:9 가 흔하다) 격자
높이가 커지고 가로도 같이 커져서, 결국 패널 폭을 넘어선다.

```
   패널 폭 W                      격자 한 변 = 보드 영역 높이
   ├────────────────┤
   ┌────────────────┐
   │  ┌───────────────────┐       ← 넘어간 부분은 잘려 보이지 않는데
   │  │                   │          Pressable 은 살아 있다
   │  │      격자         │          = 화면 밖에 입력 영역이 남는다
   │  └───────────────────┘
   └────────────────┘
```

Yoga 의 기본 `flexShrink` 는 0이라 컨테이너가 좁아도 줄여 주지 않는다. 그래서 격자가
좌우로 삐져나가고, 잘린 부분의 칸은 **보이지 않는데 눌리는** 상태가 됐다. 손가락이 닿는
자리와 눈에 보이는 자리가 어긋나므로, 드래그 중에 격자가 어긋나 보이는 것도 같은 뿌리다.

### 수정 - 좁은 쪽에 맞춰 픽셀로 못박는다

```ts
export function fitSquareSide(availableWidth: number, availableHeight: number): number {
	const side = Math.min(availableWidth, availableHeight);
	return side > 0 ? Math.floor(side) : 0;
}
```

`computeBoardGeometry()` 가 안전 여백을 뺀 사용 가능 영역에서 이 값을 구하고, 패널은
`aspectRatio` 대신 **픽셀 값을 그대로** 넣는다. 보드 영역에는 `overflow: 'hidden'` 을 걸어
두 번째 방어선을 둔다.

두 패널이 같은 자를 쓰도록 캔버스 크기도 한곳에서 정한다 (`PUZZLE_UI_CANVAS_WIDTH/HEIGHT`).
예전에는 보드 패널만 720×1180 이었고 메인 UI 는 기본값이라, 같은 `%` 가 서로 다른 픽셀이었다.

### 안전 여백

기기마다 화면 가장자리를 비운다. 모바일은 노치·둥근 모서리·홈 인디케이터에 더해 **Horizon
자체의 이동/점프 버튼이 화면 아래를 차지**하므로 아래를 특히 넉넉히 잡는다.

| 기기 | 상 | 하 | 좌 | 우 | 글자 배율 |
|---|---|---|---|---|---|
| 모바일 | 3% | 6% | 4% | 4% | 1.15 |
| VR | 4% | 4% | 6% | 6% | 1.10 |
| 데스크톱 | 2% | 2% | 2% | 2% | 1.00 |

세로 비율(위 여백 + 보드 + 보조 레이아웃)이 100% 를 넘으면 `clampBoardArea()` 가 비율대로
줄이고 콘솔에 알린다. 에디터에서 누가 props 를 크게 잡아도 화면 밖으로 나가지 않는다.

## 2. 드래그 중에 격자가 어긋나던 이유

1번의 화면 밖 밀림과 별개로, **칸 안에서도** 흔들림이 있었다.

조작 강조(집음 / 놓을 자리 / 길)는 칸마다 테두리 두께를 0 → 3 / 4 / 5 px 로 바꾼다. 이것을
칸 "얼굴" 자신의 `borderWidth` 로 주면 **얼굴의 내용 상자가 그만큼 줄어든다.** 드래그 한
번에 여러 칸의 강조가 칸 이동마다 켜졌다 꺼지므로, 칸 안의 글자와 무늬가 매번 다시 자리를
잡았다.

### 수정 - 배치를 바꾸는 스타일을 드래그 경로에서 걷어냈다

칸 하나의 구성이 이렇게 바뀌었다.

```
Pressable            입력 판정만. 크기를 바꾸는 스타일이 붙지 않는다
├─ face              색 · 그림자 · 확대. 테두리 없음
├─ glyphFrame        position: absolute — 부품 무늬(막힌 변)
├─ borderOverlay     position: absolute — 조작 강조 테두리
└─ grabRing          position: absolute — 집는 순간 터지는 고리
```

절대 배치된 층은 형제의 배치에 영향을 주지 않으므로, 드래그 내내 격자의 기하가 한 픽셀도
움직이지 않는다. 세 층 모두 얼굴과 같은 `scale` 을 받아 집은 칸에서 함께 커진다.

칸 사이 간격도 `%` 에서 **px** 로 바꿨다. 격자 한 변이 픽셀로 정해졌으므로 간격도 픽셀로
알 수 있고, 그래야 겹쳐 놓는 층을 얼굴에 정확히 맞출 수 있다. `padding` 으로 내는 규칙은
그대로다 - `margin` 이면 간격이 어느 칸에도 속하지 않는 죽은 영역이 되어 드래그가 깜빡인다.

트레이 슬롯과 보조 미니 격자도 같은 이유로 `aspectRatio` 를 버리고 픽셀 크기를 쓴다.
슬롯 8칸을 늘어놓아도 트레이 폭을 넘지 않도록 `computeBoardGeometry()` 가 한 변을 정한다.

## 3. 글자가 작아 보이던 이유

글자 크기가 `fontSize: 22` 처럼 **버튼 크기와 무관하게 박혀** 있었다. 버튼은 화면 비율로
커지는데 글자는 그대로라, 화면이 클수록 글자가 상대적으로 작아 보인다.

### 수정 - 상자 크기에서 글자 크기를 도출한다

```ts
export function fitFontSize(boxHeight: number, options: FontFitOptions = {}): number {
	const raw = boxHeight * (options.ratio ?? 0.34) * (options.scale ?? 1);
	return Math.round(clampNumber(raw, options.minimum ?? 12, options.maximum ?? 48));
}
```

버튼이 커지면 글자도 커지고, 위아래 한계가 있어 아주 작은 상자에서도 읽히고 아주 큰
상자에서 글자만 우스꽝스럽게 커지지도 않는다. 여기에 기기별 배율(위 표)이 곱해진다.

적용한 곳은 다음과 같다.

| 화면 | 대상 |
|---|---|
| 메인 메뉴 | 제목, 퍼즐 카드의 이름·부제·진행도 |
| 퍼즐 상세 | 제목·부제·진행도, Start / Continue / Return |
| 인게임 HUD | 레벨, 라운드, 남은 초, 메뉴 버튼 |
| 시스템 메뉴 | 제목, 버튼 세 개 |
| 결과 | 제목, 상세, 버튼 |
| 보드 | **칸 글자(격자 크기를 따라간다)**, 트레이 라벨·자막, `GameStart` 배너, Reset |

보드의 칸 글자는 행 수 바인딩에서 파생하므로, 9×9 러시아워는 작고 3×3 슬라이드는 크게
나온다. 판이 달라져도 글자가 칸을 넘치거나 텅 비지 않는다.

## 4. 검증

`PuzzleUI_Tests.ts` 의 `testDeviceLayout()`.

- 기기 문자열 분류 (알 수 없는 값은 데스크톱)
- 정사각형이 좁은 쪽을 따르는지
- 상자가 커지면 글자도 커지는지, 상하한과 기기 배율이 도는지
- 세로 비율이 100% 를 넘을 때 위반으로 잡히고 비율대로 줄여지는지
- **세 기기 전부에서** 격자가 사용 가능한 폭·높이 안에 들어가고, 트레이 슬롯 8칸이 폭 안에 들어가는지

`PuzzleUI_Layout.ts` 는 `horizon/core` / `horizon/ui` 에 런타임 의존이 없어 Node 테스트로 그대로 돌아간다.
