# 작업 기록 - 레이저 크리스탈의 "방향" 을 화면에 드러내기

- **날짜**: 2026-09-02
- **신고**: 레이저 퍼즐 조각 중 **어떤 게 아래만 반사되고 어떤 게 위만 반사되는지 알기 어렵다.**
- **수정 파일**: `PuzzleBoardUI_Definitions.ts`(무늬 어휘), `PuzzleBoardUI_Panel.ts`(그리기), `Laser_CoreAPI.ts`(매핑)
- **관련 문서**: `작업기록_2026-09-02_보드_CustomUI_전환.md`(보드가 왜 Custom UI 인지)

---

## 1. 원인 - 같은 글자가 서로 다른 부품을 가리키고 있었다

보드는 칸 하나를 **색 + 글자 한 개**로 그린다. 크리스탈은 종류가 5종인데(§4.1), 그중 둘은
**방향에 따라 동작이 갈린다.**

| 종류 | 방향 | 예전 라벨 |
|---|---|---|
| 직각 삼각형 | 직각 코너 4방향 | 빗금 2종 (`/`, `\`) |
| T자 | 막힌 변 4방향 | `T` 하나 |

직각 삼각형은 **직각 코너에 붙은 두 변(평면)이 광선을 되돌리고** 빗변만 90도로 꺾는다.
그런데 좌하단 직각과 우상단 직각은 **거울 기울기가 같아서** 예전 라벨로는 둘 다 같은
빗금이었다. 우하단과 좌상단도 마찬가지다. 즉 **네 방향이 화면에서 두 가지로만 보였다.**
T자는 아예 네 방향이 전부 같은 `T` 였다.

"아래만 반사되는지 위만 반사되는지" 를 가르는 정보가 화면에 전혀 없었던 것이다.

## 2. 수정 - 칸 자체를 부품 무늬로 쓴다

이미지 애셋을 새로 만들어 올리려면 에디터 작업이 따로 필요하고, 애셋 id 가 월드에 묶여
스크립트만으로는 재현되지 않는다. 그래서 **칸을 그리는 방식 자체를 부품 무늬로** 바꿨다.

### 2-1. 어휘 - `EBoardCellGlyph` (`PuzzleBoardUI_Definitions.ts`)

칸/슬롯 스냅샷에 `glyph` 필드를 하나 더했다. 값은 **방향을 가진 아홉 가지**다.

```
NONE
CORNER_TOP_LEFT / CORNER_TOP_RIGHT / CORNER_BOTTOM_LEFT / CORNER_BOTTOM_RIGHT   직각 삼각형
BLOCKED_UP / BLOCKED_DOWN / BLOCKED_LEFT / BLOCKED_RIGHT                        T자
```

여기에 순수 함수 두 개가 붙는다.

- `getGlyphBlockedEdges(glyph)` — **광선을 되돌리는 변**들 (`{ top, bottom, left, right }`)
- `getGlyphRotationDegrees(glyph)` — 칸의 글자를 몇 도 돌려 그릴지

### 2-2. 그리기 (`PuzzleBoardUI_Panel.ts`)

칸 안에 **절대 배치된 무늬 판**을 한 겹 깔고, 막힌 변에만 두꺼운 테두리를 준다.
`borderTopWidth` / `borderBottomWidth` / `borderLeftWidth` / `borderRightWidth` 를 각각
바인딩으로 잇는 것이라 **노드가 칸당 하나만 늘어난다.**

동시에 칸의 글자를 `transform: [{ rotate }]` 로 돌린다. 글자를 기준 모양으로 고른 것이 핵심이다.

```
L   두 획이 곧 광선을 되돌리는 두 평면이다
    0도 = 좌하단 직각, 90도 = 좌상단, 180도 = 우상단, 270도 = 우하단

T   크로스바 쪽이 막힌 변이다
    0도 = 위가 막힘, 90도 = 오른쪽, 180도 = 아래, 270도 = 왼쪽
```

돌리기만 하면 네 방향이 전부 다른 그림이 되므로, 방향마다 다른 글자를 찾을 필요가 없다.

### 2-3. 라벨 정리 (`Laser_CoreAPI.ts`)

`getCrystalGlyph()` 를 새로 만들어 크리스탈 → 무늬를 매핑하고, 라벨은 **종류만** 나타내도록
정리했다. 방향 정보는 전부 무늬가 진다.

| 부품 | 라벨 | 이유 |
|---|---|---|
| 직각 삼각형 | `L` | 두 평면이 만나는 직각을 본뜬 모양 |
| T자 | `T` | 크로스바가 막힌 변 |
| 팔각 | `X` | 대각 4방향 분배 |
| 십자 | `+` | 직각 4방향 분배 |
| 꽃 | `O` | 모든 방향 흡수 (닫힌 고리) |
| 해골 | `!` | `X` 를 팔각에 넘겨주고 경고 부호로 바꿨다 |

무늬는 판 위뿐 아니라 **인벤토리 트레이 슬롯에도 그린다.** 집기 전에 방향을 고를 수 있어야
하기 때문이다. 고정 크리스탈(§4.3)도 마찬가지로 무늬를 받는다 - 옮기지 못할 뿐 동작은 같다.

---

## 3. 다른 퍼즐에 미치는 영향

`glyph` 의 기본값은 `NONE` 이고, `NONE` 은 막힌 변이 없고 회전각이 0도다. 그래서 무늬를
쓰지 않는 7개 퍼즐의 화면은 **한 픽셀도 달라지지 않는다.**

## 4. 검증

`PuzzleBoardUI_Tests.ts` 의 `testGlyphs()`.

- 무늬가 칸/슬롯 스냅샷의 동등 비교와 패치에 정상적으로 참여하는지
- 좌하단 직각은 왼쪽·아래가, 우상단 직각은 오른쪽·위가 평면인지
- **좌하단과 우상단이 서로 다른 그림인지** (예전에 똑같이 보이던 조합의 회귀 테스트)
- T자 네 방향이 각각 막힌 변 하나를 가지고, 회전각이 넷 다 다른지
