## 2. 기획서와 데이터의 대조

### 2.1 데이터가 기획서와 정확히 일치하는 항목 (검증 완료, 위반 0건)

- 발사체·수신체는 **테두리 칸에만**, 그것도 꼭짓점이 아닌 칸에만 놓인다 (§2 / §5.1).
- 중계체·해골·고정 크리스탈은 **안쪽 5×5 에만** 놓인다 (§5.0).
- 발사체/수신체 화살표(▲▼◀▶ / △▽◁▷)는 **항상 필드 안쪽**을 향한다.
  → 구현에서는 `getInwardDirection(row, col)` 으로 테두리 위치에서 방향을 유도하므로
    CSV 의 화살표 정보를 따로 저장할 필요가 없다.
- 모든 판에 발사체·수신체가 있고, 수신체 색과 짝이 맞는 발사체가 존재한다 (§3 2.1).

### 2.2 기획서와 데이터가 어긋나는 항목

| # | 기획서 | 데이터 | 처리 |
|---|---|---|---|
| 1 | §2 "인벤토리 최대 **5개**" | 슬롯 컬럼 10개, 실제 최대 **9개** (75판 중 15판이 5개 초과) | 데이터가 최신이라 보고 `LASER_MAX_INVENTORY_SLOTS` 를 **10**으로 올렸다. 기획서 원문 값은 `LASER_SPEC_INVENTORY_SLOTS = 5` 로 남겨 UI 슬롯 레이아웃 기준으로만 참고한다 |
| 2 | §4.1 크리스탈 **5종** (삼각/팔각/십자/T자/꽃) | **3종만 사용** (삼각/십자/흡수). 팔각·T자는 오브젝트 테이블에도 없다 | 구현은 5종을 그대로 유지한다. 절차적 생성기는 5종을 다 쓰므로, 기획 데이터로 도는 판에서만 3종이 나온다 |
| 3 | 난이도 1~5 전제 | 난이도 **6까지** 존재 | 난이도 테이블에 D6 을 추가했다 (제한시간 270초 / 3라운드) |
| 4 | §4.2 발사체·수신체·중계체 "각 3개" | 한 판에 발사체 1 : 수신체 3 처럼 **비대칭 구성**이 75판 중 31판 | 오류가 아니다. 십자 ⊡ 분광기와 중계체 ⊚ 로 빔을 갈라 여러 수신체를 동시에 켜는 설계다. 광선 추적기가 이미 다중 분기를 지원하므로 그대로 동작한다 |

### 2.3 CSV 자체의 사소한 흠

- `NPUZ_01_FieldData.csv` 3행(한글 라벨)의 `B4  좌표`, `B5  좌표` 에 **이중 공백**이 있다.
  키 행(2행)은 정상이므로 파싱에 영향은 없지만, 한글 라벨로 매핑하는 도구가 있다면 주의가 필요하다.

### 3.3 레벨 소스 우선순위

```
LaserSession.loadLevel(quest)
  ├─ 필드 테이블에 해당 난이도 판이 있으면 → 그중 아직 안 낸 판을 무작위 선택   ← 기획 CSV
  └─ 하나도 없으면                        → LaserLevelGenerator 로 절차 생성   ← 폴백
```

이 우선순위 자체는 원래 구현에 있던 것이고, 필드 테이블이 샘플 1판에서 기획 75판으로 바뀌면서
실제로 기획 데이터가 쓰이게 됐다. 절차적 생성기는 그대로 살아 있어 난이도별 판이 없을 때 동작한다.

### 3.4 힌트 탐색 예산을 넣은 이유

`getHintStep()` 은 클라이언트에서 **동기로** 솔버를 돌린다. 샘플 판은 크리스탈 2개짜리라 즉시 끝났지만,
기획 데이터는 인벤토리가 6~9개인 판이 많아 완전 탐색이 수백만 조합으로 폭발한다(기본 상한 300,000
조합에 1~2.5초 소요). 예산을 5만 조합으로 묶고, 못 찾으면 힌트 없음으로 처리한다.

### 4.1 나머지 13판에 대해

13판은 **"풀 수 없다"가 아니라 "정해진 탐색량 안에 해를 못 찾았다"** 이다
(솔버가 `isExhausted = true` 로 반환). 인벤토리 7~9개를 빈 칸 20여 곳에 배치하는 조합이
150만 개를 넘어가기 때문으로, 상한을 150만으로 올렸을 때 그중 3판이 추가로 "해 있음"으로 확인됐다.

미확정 13판: `8000103010` `8000104004` `8000104006` `8000104009` `8000104010`
`8000105001` `8000105003` `8000105004` `8000105006` `8000105010`
`8000106003` `8000106006` `8000106007`

기획 데이터는 사람이 손으로 설계한 판이므로 실제로는 풀린다고 보는 것이 타당하다.
확실히 하려면 솔버에 가지치기(수신체까지의 경로 역추적, 색 레이어별 분리 탐색)를 넣어야 하며,
이는 이번 작업 범위 밖으로 남겨 둔다.
