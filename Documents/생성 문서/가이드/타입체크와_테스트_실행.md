## 1. 타입 체크

```bash
node ./node_modules/typescript/bin/tsc --noEmit --skipLibCheck
```

> `--skipLibCheck` 는 반드시 붙인다. Horizon 이 제공하는 `types/*.d.ts` 자체가
> `TS1038: A 'declare' modifier cannot be used in an already ambient context` 를 다량 발생시킨다.
> 우리 코드 문제가 아니다.

현재 기준 **에러 0건**. 단, `Documents/SampleHtml/game.ts` 는 브라우저 샘플이라
`document` / `HTMLElement` 를 참조해 **5건의 오류를 낸다. 우리 코드 문제가 아니다.**

```bash
node ./node_modules/typescript/bin/tsc --noEmit --skipLibCheck 2>&1 | grep -v "^Documents/SampleHtml/"
```

`tsconfig.json` 이 읽기 전용이라 `exclude` 를 넣지 못했다. 쓰기가 가능해지면
`"exclude": ["Documents"]` 를 넣어 이 필터를 없애는 편이 낫다.

## 2. Horizon 에디터 컴파일 제약 검사 (반드시 함께 돌린다)

**로컬 `tsc` 가 통과해도 Horizon 에디터에서는 컴파일이 깨질 수 있다.**
에디터의 TypeScript 는 우리 `tsconfig.json`(target ES2020)보다 낮은 `target` 을 쓰고
lib 도 제한적이다. 실측으로 확인된 제약은 두 가지다.

| 제약 | 증상 | 대응 |
|---|---|---|
| `target < ES2015` | `Set` / `Map` 이터레이터를 `for...of` 로 직접 순회하면 `TS2802` | `Array.from(...)` 으로 감싼다 |
| lib 에 TypedArray 없음 | `Int8Array` 등이 `Cannot find name` | 일반 `number[]` 를 쓴다 |

로컬에서 같은 조건을 재현하는 명령이다.

```bash
node ./node_modules/typescript/bin/tsc --noEmit --skipLibCheck --target ES5 --lib ES2020
```

> `--lib ES2020` 을 남겨 두는 이유: `Map`/`Set`/`Promise` 타입 자체는 살리고
> **다운레벨 반복 위반만** 드러내기 위해서다. `--target ES5` 만 주면 lib 도 ES5 로 떨어져
> 무관한 오류가 쏟아진다.
>
> 이 명령이 잡지 못하는 것도 있다. `Int8Array` 는 ES5 lib 에 있어서 여기서는 통과한다.
> 에디터 lib 은 그보다 더 좁으므로, **ES2015 이후 내장 API 를 새로 쓸 때는
> 기존 `Basics_*` 코드에 전례가 있는지 먼저 확인한다.**
> (전례 있음: `Array.from`, `new Map`, `new Set` / 전례 없어 회피함: `padStart`, TypedArray)

### 2.1 선언 파일(`.d.ts`) 생성 검사 — `--noEmit` 이 못 잡는 것

`tsconfig.json` 에 `"declaration": true` 가 켜져 있고 **에디터는 선언 파일을 만들면서
컴파일한다.** 그런데 §1 의 `--noEmit` 은 선언을 만들지 않으므로, 선언에서만 나는 오류를
**로컬에서는 통과하고 에디터에서만 깨진다.**

```bash
node ./node_modules/typescript/bin/tsc --skipLibCheck --declaration --emitDeclarationOnly --outDir /tmp/dts
```

가장 자주 걸리는 것이 **이름 붙일 수 없는 타입을 export 한 함수가 돌려주는 경우**다.

```
TS4058: Return type of exported function has or is using name 'DerivedBinding'
        from external module "horizon/ui" but cannot be named.
```

`Binding.derive()` 가 돌려주는 `DerivedBinding` 은 `horizon/ui` 가 **내보내지 않는**
타입(`declare class`)이다. 그래서 파생을 돌려주는 `export function` 은 반환 타입을 추론에
맡기면 안 되고, 내보내진 이름으로 못박아야 한다.

```ts
// 이렇게 하면 에디터에서 깨진다
export function createLabelVisibility<T>(...) {
    return Binding.derive([...], ...);
}

// 반환 타입을 명시한다 - `Bindable<T>` 는 horizon/ui 가 내보내는 타입이다
export function createLabelVisibility<T>(...): Bindable<boolean> {
    return Binding.derive([...], ...);
}
```

`private`/`public` 메서드나 지역 변수에는 이 제약이 없다 - 선언 파일에 나가는 것
(`export` 된 함수·클래스의 공개 멤버)만 이름을 적을 수 있어야 한다.

---

**적용 이력** — 에디터 로그로 확인해 아래 파일을 수정했다.

| 파일 | 오류 | 수정 |
|---|---|---|
| `Flow_Board.ts` (3곳) | `IterableIterator` 순회 | `Array.from(this._nodes.values())` |
| `Laser_LevelGenerator.ts` | `Set` 순회 | `Array.from(pathKeys)` |

| `PuzzleBoardUI_Parts.ts` | `TS4058` `DerivedBinding` 을 이름 붙일 수 없음 (§2.1) | `createLabelVisibility()` 의 반환 타입을 `Bindable<boolean>` 으로 명시 |

수정 후 테스트 결과 변화 없음.

## 3. 전체 테스트 (Node)

non-relative import 를 Node 가 해석하도록 `NODE_PATH` 를 걸어 실행한다.

> **`*_Tests.ts` 는 모두 `Documents/Tests/` 에 있다.** 스크립트 루트가 아니다.
> 자세한 이유는 아래 §3.1 을 본다. `--baseUrl .` 덕분에 테스트가 쓰는
> `import ... from 'Flow_CoreAPI'` 같은 non-relative import 는 그대로 해석된다.
> 다만 컴파일 결과가 `$OUT/Documents/Tests/` 아래로 떨어지므로
> **`NODE_PATH` 에 두 경로를 모두 넣는다.**
>
> **스크립트 루트에 `Tests/` 같은 폴더를 새로 만들면 안 된다.** 에디터가 폴더째 지운다
> (§3.1). 반드시 `Documents/` 아래에 둔다.

> **`*_CoreAPI.ts` 는 파일 목록에서 제외한다** (`grep -v CoreAPI`). `horizon/core` 에 의존해
> Node 에서 돌지 않고, 테스트 하네스가 부르지도 않는다. 넣어도 무해하지만 오류 줄만 늘어난다.
> CoreAPI 는 §1 · §2 의 타입 체크로만 검증된다.

### 3.1 파일이 말없이 사라지는 이유 — 카탈로그가 원본이다

**로컬 스크립트 폴더는 원본이 아니다.** 월드의 스크립트 카탈로그(클라우드)가 원본이고,
에디터는 주기적으로 로컬 폴더를 거기에 맞춰 정리한다. **카탈로그에 항목이 없는 로컬
`.ts` 는 삭제된다.** 삭제된 파일은 `.backups/<파일명>.ts/<타임스탬프>_Deleted.ts` 로
백업되지만, 백업은 영구 보관이 아니다 — 에디터가 재동기화하면서 지운다. 필요하면 바로
꺼낸다.

`.editor` 는 그 카탈로그의 로컬 사본이다. 그래서 어긋남을 이렇게 읽는다.

| 상태 | 뜻 |
|---|---|
| 디스크에 있는데 `.editor` 에 없다 | **다음 대조 때 삭제된다** |
| `.editor` 에 있는데 디스크에 없다 | 컴파일이 깨진다 (끊어진 참조) |

```bash
node Documents/Tools/check_registry.js
```

**파일을 되돌려 놓기만 해서는 안 된다.** 파일 복사는 카탈로그 항목을 만들지 않는다.
에디터가 떠 있을 때는 파일 추가를 실시간으로 감지해 등록해 주기도 하지만, 재시작
시점의 대조에서는 카탈로그가 이긴다. **에디터 UI 의 스크립트 목록에서 직접 추가**해야
확실하다.

2026-09-08 의 실측이다. `Player.log` 기준으로 이전 에디터 세션이 10:07:56 에 끝나고
새 세션이 10:08:00 에 시작했는데, **시작 39 초 뒤인 10:08:39 에** 카탈로그에 없던
`RushHour_LevelGenerator.ts` · `Switch_LevelGenerator.ts` · `Puzzle_LocalOwnership.ts`
세 개가 삭제되고 `.editor` 가 99 → 96 항목으로 줄었다. 같은 날 루트의 `Tests/` 폴더도
**폴더째** 사라졌고 이때는 백업조차 남지 않았다.

> **한때 "총 용량 상한(약 1.72 MB)" 으로 설명했으나 근거가 약하다.** 상한보다 600 KB
> 아래인 상태에서도 삭제가 일어났다. 초기 사건들의 로그는 이미 로테이션되어 확인할 수
> 없다. 위의 카탈로그 대조만으로 관측된 모든 삭제가 설명된다.

`Documents/` 아래는 대조 대상이 아니라 건드리지 않는다 (`Documents/SampleHtml/game.ts`
가 그대로 살아 있다). 그래서 인월드에서 돌 필요가 없는 것 — 테스트, 도구 — 은
**`Documents/` 아래**에 둔다. 루트에 `Tests/` 같은 폴더를 새로 만들면 안 된다.

참고로 루트를 줄인 조치는 다음과 같다. 카탈로그 문제와는 별개지만, 루트를 인월드에서
실제로 쓰는 것만 남겨 두면 대조 사고의 영향 범위가 줄어든다.

| 조치 | 절감 |
|---|---|
| `*_Tests.ts` 10 종을 `Documents/Tests/` 로 이동 | 316,725 B |
| 루트 `.ts` 99 개에서 주석 제거 (§3.2) | 356,741 B |

결과적으로 루트는 **109 개 / 1,809,396 B → 99 개 / 1,091,604 B** 가 됐다.

### 3.2 주석은 `ScriptDesc/` 문서에 둔다

주석이 루트 `.ts` 전체의 **24.6%** 를 차지했다. 그래서 주석을 코드에서 걷어내고
스크립트 하나당 문서 하나로 `Documents/생성 문서/ScriptDesc/<스크립트>.md` 에 보존한다.
목록은 `../ScriptDesc/README.md` 를 본다.

**새 스크립트를 쓸 때도 설명은 ScriptDesc 문서에 적고 코드에는 남기지 않는다.**

걷어내기는 도구로 반복 실행할 수 있다.

```bash
node Documents/Tools/strip_comments.js --dry   # 보고만 한다
node Documents/Tools/strip_comments.js         # 실제로 고쳐 쓴다
```

TypeScript 스캐너를 쓰므로 문자열·템플릿·정규식 리터럴을 주석으로 오인하지 않고,
원본의 줄바꿈을 유지하며, 주석이 없는 파일은 기존 아카이브 문서를 덮어쓰지 않는다.

**언제 다시 돌리나** — `build_*.py` 로 `*_FieldData.ts` 를 재생성한 뒤에 돌린다.
`dt_common.py` 의 `banner()` 는 이제 한 줄 경고만 내보내고 설명은 ScriptDesc 문서로
직접 쓰지만, 각 `build_*.py` 템플릿에 남아 있는 인라인 주석은 재생성 때 다시 들어온다.

**검증 방법** — 걷어내기 전후로 아래를 돌려 결과 JS 가 바이트 단위로 같아야 한다.
같다면 동작 변화가 없음이 증명된다.

```bash
node ./node_modules/typescript/bin/tsc *.ts --outDir $OUT/js_before --removeComments \
  --module CommonJS --target ES2020 --baseUrl . --skipLibCheck --strict
# ... 걷어낸 뒤 같은 명령을 js_after 로 ...
diff -r $OUT/js_before $OUT/js_after
```

## 4. 실행 중 나오는 정상 경고

아래 출력은 **전부 의도된 것**이다. 실패로 오인하지 않는다.

| 출력 | 의미 |
|---|---|
| `Cannot find module 'horizon/core'` | `Utility_Events.ts` 가 `import type` 으로만 쓰므로 컴파일 시 소거된다. JS 는 정상 생성된다 |
| 카드 맞추기 `필드 데이터 오류 ... 홀수입니다` | **홀수 데이터 거부를 확인하는 의도된 negative 테스트**의 출력 |
| 러시아워 `탐색 거리 N 수 배치의 실제 최소 이동 수는 M 수입니다` | 생성기가 `minimumMoves` 를 솔버로 재측정해 보정했다는 정상 로그 |
| `[PuzzleProgress] Stored progress is not readable and was discarded` | **깨진 저장 문자열을 버리는지 확인하는 negative 테스트**의 출력 |
| `[PuzzleHandle] SWITCH: level 0 is out of range` | **범위 밖 레벨 거절을 확인하는 negative 테스트**의 출력 |
| `[PuzzleBoardPresenter] endBatch() was called without a matching beginBatch()` | **짝이 맞지 않는 배치 종료를 무시하는지 확인하는 negative 테스트**의 출력 |
| `[PuzzleBoardPresenter] A cell/item press arrived while the previous press was still open` | **놓임(release) 이벤트가 유실된 상황에서 갇힌 드래그를 정리하는지** 확인하는 테스트의 출력 |
| `[PuzzleBoardStage] A board was mounted but no panel is listening` | 테스트 하네스는 패널 없이 프레젠터만 올린다. **인월드에서 이 경고가 뜨면 진짜 문제다** (BoardPanel 누락) |
| `[PuzzleBoardStage] The board Menu button was pressed but no hub panel is listening` | 보드 위 Menu 버튼의 일시정지 요청을 **듣는 쪽 없이** 눌러 보는 검증의 출력이다. **인월드에서 뜨면 진짜 문제다** (MainPanel 누락) |
