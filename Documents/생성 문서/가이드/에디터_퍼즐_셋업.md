# 가이드 — 에디터에서 퍼즐 띄우기 (빈 레벨 셋업)

> 대상: Horizon Worlds 에디터에서 손으로 따라 하는 절차
> 기준 퍼즐: PUZ_08 스위치. **8종 모두 같은 절차이며** 붙이는 스크립트만 다르다 (§3.2)
> 관련 문서: `../설계/Horizon통합_아키텍처.md` (왜 이렇게 되어 있는지),
> `../구현 사항/작업기록_2026-09-02_보드_CustomUI_전환.md` (3D 보드에서 옮겨 온 이력),
> `../구현 사항/퍼즐_구현_현황.md` (전체 현황)

이 문서는 **에디터 조작 절차서**다. 코드 구조 설명은 `../설계/Horizon통합_아키텍처.md` 에 있다.

> **보드는 Custom UI 로 그린다.** 키 캡·타일을 3D 오브젝트로 놓던 방식은 2026-09-02 에
> 걷어냈다. 3D 오브젝트를 배치하는 단계가 통째로 사라졌으므로, 예전 절차를 기억하고 있다면
> `../구현 사항/작업기록_2026-09-02_보드_CustomUI_전환.md` §4 의 이관 절차를 먼저 본다.

## 1. 반드시 알아야 할 함정

**"조용히 아무 일도 일어나지 않는" 형태로 실패한다.** 원인 파악이 어려우므로 셋업 전에 읽는다.

### 1.1 Local 스크립트는 소유자가 지정되어야 실행된다

`*_CoreAPI` 와 Custom UI 패널은 플레이어별로 따로 돌아야 하므로 실행 모드를 `Local` 로 둔다.
그런데 Horizon 에서 **Local 스크립트는 엔티티에 소유자(플레이어)가 지정되기 전까지 아예
실행되지 않는다.** 소유자가 서버인 채로 두면 `start()` 의 소유자 검사에 걸려 조용히
아무 일도 일어나지 않고, Custom UI 는 빈 화면만 그린다.

→ `Puzzle_LocalOwnership.ts` 가 플레이어 입장 시 소유권을 넘겨 준다.
**퍼즐 컨트롤러와 UI 패널을 전부 `targets` 에 넣어야 한다.**

### 1.2 Focused Interaction 은 더 이상 필요 없다

예전에는 화면 터치 이벤트(`PlayerControls.onFocusedInteractionInput*`)를 받으려고
Focused Interaction 모드에 진입해야 했다. 보드가 Custom UI 가 된 지금은 `Pressable` 이
입력을 직접 받으므로 **그 진입이 필요 없다.**

`Switch_CoreAPI` 의 `focusCamera` 는 기본 꺼짐이며, 켜면 **연출 목적**(월드에 세운 패널을
정면에서 보게 고정)으로만 동작한다. 켰다면 퍼즐을 나갈 때 `abort()` 경로를 반드시 거쳐야
카메라가 풀린다.

### 3.1 BoardPanel — 보드 그 자체

Custom UI gizmo 의 **Display Mode** 로 두 가지 연출을 고를 수 있다. 코드는 어느 쪽이든 같다.

| Display Mode | 결과 | 언제 |
|---|---|---|
| `Screen Overlay` | 화면에 보드가 겹쳐 뜬다 | 확인·테스트가 가장 쉽다. 모바일에 유리 |
| `Spatial` (World Space) | 월드에 판이 서 있고 그 위에 격자가 그려진다 | 공간감이 필요할 때. 플레이어를 향하도록 회전시킨다 |

화면은 위에서 아래로 네 칸이다
(`../구현 사항/작업기록_2026-09-03_보드UI_상대배치_전면개편.md`).

```
위 여백  (topInsetPercent)     ← 상태바·노치·호라이즌 버튼 자리 + 퍼즐 제목
본 격자   flex 7               ← 그 안에 정사각형 보드, 격자는 판 비율대로
보조 레이아웃 flex 3            ← 오브젝트 트레이 · 정보 미니 격자 · Reset 버튼
아래 여백 (bottomInsetPercent)  ← 홈 인디케이터 자리 + Menu(일시정지) 버튼
```

> **2026-09-03 개편으로 prop 이 바뀌었다.** `boardAreaPercent`/`auxAreaPercent`/
> `boardSquarePercent`/`boardMarginPercent` 는 **없어졌다** - 7:3 분할이 고정이 되고
> 보드 크기는 아래 두 값이 정한다. 에디터에서 옛 prop 에 값을 넣어 두었다면 그 칸은
> 그냥 사라지므로 따로 지울 것은 없다.

props 는 전부 기본값으로 동작한다.

| Prop | 기본값 | 내용 |
|---|---|---|
| `showTitle` | **false** | 보드 제목 줄. HUD 가 레벨·시간을 이미 그리므로 기본은 꺼짐 |
| `topInsetPercent` | 6 | 화면 **위**에 비워 둘 비율(%) — 상태바·노치가 판을 가리면 키운다 |
| `bottomInsetPercent` | 8 | 화면 **아래**에 비워 둘 비율(%) — `Menu` 버튼이 여기 앉는다 |
| `boardWidthPercent` | 96 | 보드 정사각형이 쓰는 **가로**(%) — 나머지가 좌우 여백으로 반씩 |
| `boardHeightPercent` | 94 | 보드가 본 격자 영역 **세로**에서 쓰는 (%) — 나머지가 트레이와의 틈 |
| `screenPixelRatio` | 2 | 읽기값을 패널 좌표로 옮기는 배율. **글자·테두리에만 쓴다** (아래 참고) |
| `cellGapPercent` | 1.2 | 칸 사이 간격 — **칸 하나 대비 %** 다 |
| `introSeconds` | 0.45 | 레벨 시작 시 `GameStart` 배너가 **완전히 보이는** 시간(초). 이 동안은 보드 입력이 잠긴다 |
| `introFadeSeconds` | 0.3 | 배너가 페이드 아웃되는 시간(초). 페이드가 시작되면 입력은 먼저 열린다 |
| `drawBackgroundWhenEmpty` | false | 퍼즐 밖에서도 패널 배경을 그릴지 |
| `tintTexturesWithFill` | false | 텍스처를 칸 색으로 물들일지 (§3.4) |

| `canvasWidth` / `canvasHeight` | 0 / 0 | 캔버스를 직접 못박는다. 0 이면 화면 비율에서 자동 |
| `showLayoutDebug` | false | 실측값 한 줄을 화면 아래에 띄운다 |
| `showLayoutProbe` | false | **측정 화면만** 그린다. 상대 배치가 어떻게 그려지는지 재는 용도 |
| `showTrayDebug` | false | 오브젝트 트레이 진단 — 부품이 안 보일 때 켠다 (§3.5) |

> **`screenPixelRatio` 를 재는 법**: `showLayoutDebug` 를 켜고 스크린샷을 찍어,
> **스크린샷의 실제 가로 픽셀 ÷ 로그의 `screen` 가로** 를 넣는다. 실측 iPhone 은
> 1179 ÷ 590 = 2 였다. 이 값이 틀려도 **판과 트레이는 정확히 그려지고 글자만 조금 크거나
> 작아진다** - 배치에는 쓰이지 않기 때문이다.

> **패널 크기(캔버스)는 보통 건드릴 것이 없다.** 두 패널이 시작할 때 플레이어의 화면 비율에
> 맞춰 스스로 잡는다 - 그래야 화면에 꽉 차고 옆으로 월드가 새지 않는다
> (`../구현 사항/버그수정_2026-09-02_UI가_화면을_꽉_채우지_않음.md`).
> 가로 화면에서는 메인 메뉴가 4열 x 2행이 되고 본 격자가 조금 커진다.

**격자 크기·색·숨김은 전부 코드가 정한다.** 에디터에서 칸을 만들거나 배치할 일이 없다.
패널은 최대 9×9 격자와 슬롯 8개를 미리 만들어 두고 퍼즐이 쓰는 만큼만 보여 준다.

보조 레이아웃에서 **리셋 버튼은 8종 공통**이고, 트레이(레이저의 크리스탈)와 정보 미니
격자(스위치의 동시 눌림 영역)는 그 퍼즐이 쓸 때만 나타난다. 리셋은 판만 되돌리고
**남은 시간은 되돌리지 않는다.**

### 3.1.1 HubPanel — `PuzzleUI_MainPanel` props

| Prop | 기본값 | 내용 |
|---|---|---|
| `progressVariableKey` | `PuzzleHub:progress` | 진행도 영구 변수 키 (§4.1) |
| `countdownSound` | — | 남은 시간 10초 미만일 때 1초마다 울릴 **Audio gizmo**. 비워 두면 숫자만 점멸한다 |
| `canvasWidth` / `canvasHeight` | 0 / 0 | 캔버스를 직접 못박는다. **BoardPanel 과 같은 값**을 넣어야 한다 |
| `screenPixelRatio` | 2 | 읽기값을 좌표 단위로 옮기는 배율. **BoardPanel 과 같은 값**을 넣는다. 여기서는 글자 크기와 **세로 여백 모두**에 쓰이므로, 값이 절반이면 메뉴 글씨가 깨알이 되고 버튼이 위로 몰린다 (`../구현 사항/버그수정_2026-09-03_허브UI_글자크기와_상세화면_정렬.md`) |

인게임 HUD 바는 이렇게 그려진다.

```
LV 3 / 24            07        [MENU]
좌측 = 레벨      중앙 = 남은 초   우측 = 시스템 메뉴
```

우측 `MENU` 를 누르면 **타이머가 멈추면서** 시스템 메뉴가 뜬다 - Resume / Restart Level /
Return to Main 세 버튼이다 (`구현 사항/작업기록_2026-09-02_재입장과_시스템메뉴.md`).

10초 미만이 되면 가운데 숫자가 빨갛게 점멸한다. `countdownSound` 에 Audio gizmo 를 넣으면
그 소리가 1초마다 함께 난다. 그 플레이어에게만 들리게 하려면 gizmo 를 HubPanel 과 같은
Local 소유로 두고 `Puzzle_LocalOwnership` 의 `targets` 에 넣는다.

### 3.2 PuzzleController — `*_CoreAPI` props

**8개 퍼즐의 CoreAPI props 는 전부 같다.** 아래 표는 어느 퍼즐을 붙이든 그대로 통한다.
붙일 스크립트만 바꾸면 된다.

| 퍼즐 | 스크립트 | 난이도 범위 |
|---|---|---|
| PUZ_01 레이저 해킹 | `Laser_CoreAPI` | 1~6 |
| PUZ_02 러시아워 | `RushHour_CoreAPI` | 1~5 |
| PUZ_03 정렬 | `ColorSort_CoreAPI` | 1~5 |
| PUZ_04 색 채우기 | `ColorFill_CoreAPI` | 1~5 |
| PUZ_05 연결 | `Flow_CoreAPI` | 1~5 |
| PUZ_06 카드 맞추기 | `CardMatch_CoreAPI` | 1~5 |
| PUZ_07 슬라이드 | `SlidePuzzle_CoreAPI` | 1~5 |
| PUZ_08 스위치 | `Switch_CoreAPI` | 1~5 |

> **메인 UI 는 난이도를 직접 고르지 않는다.** 난이도별 기획 판을 오름차순으로 이어 붙여
> **레벨 목록**을 만들고(`buildPuzzleLevelTable()`), Start / Continue 가 그 위를 움직인다.
> `difficulty` prop 은 `autoStart` 단독 구동에만 쓰인다.

**여러 퍼즐을 한 레벨에 두려면** PuzzleController 를 퍼즐 수만큼 만들고 각각 다른
`*_CoreAPI` 를 붙인다. `autoStart` 는 전부 꺼 둔다(기본값) — 두 개 이상이 동시에
`autoStart` 로 켜지면 나중에 뜬 보드가 앞의 것을 덮는다 (`PuzzleBoardStage` 는 한 번에
하나만 올린다). **BoardPanel · HubPanel · OwnershipSetter 는 퍼즐마다 만들 필요가 없다.**
보드 패널 하나를 8종이 함께 쓴다.

> **기존 월드를 옮길 때 주의** — `autoStart` 의 기본값이 바뀌어도 **에디터에 이미 저장된
> 값은 그대로 남는다.** 예전에 켜 둔 PuzzleController 가 있으면 직접 꺼야 메인 UI 로
> 시작하는 흐름이 된다.

| Prop | 기본값 | 값 / 내용 |
|---|---|---|
| `difficulty` | 1 | `autoStart` 로 단독 구동할 때의 난이도. 메인 UI 로 시작하면 쓰이지 않는다 |
| `autoStart` | **false** | 기본은 꺼짐 — 게임은 메인 UI 에서 시작한다. 단독 테스트할 때만 켠다 |
| `seed` | 0 | 0 이면 매번 다른 레벨 |
| `focusCamera` | false | **보통 끈 채로 둔다.** 켜면 보드 정면에 카메라를 고정한다 |
| `boardCentre` | — | `focusCamera` 를 켰을 때만. 보통 BoardPanel 엔티티를 넣는다 |
| `cameraObject` | — | 비워 둔다 (`boardCentre` 정면에 자동 배치) |
| `cameraDistance` | 0.6 | 보드-카메라 거리 (m) |
| `cameraFov` | 40 | 시야각 |

### 3.4 텍스처 입히기 (선택)

판 위 요소에 PNG 를 입힐 수 있다. **아무것도 하지 않아도 게임은 돌아간다** - 그림이 없으면
예전처럼 색으로 그려진다. 구조는
`../구현 사항/작업기록_2026-09-02_퍼즐_요소_텍스처_파라미터화.md` 에 있다.

```
1. PNG 를 애셋 라이브러리에 올린다 (Texture 애셋이 된다)
2. PuzzleController 의 <요소>Texture prop 에 그 애셋을 끼운다
3. 회색조 한 장으로 여러 상태를 그릴 거면 BoardPanel 의 tintTexturesWithFill 을 켠다
```

퍼즐마다 요소가 다르므로 prop 이름도 다르다.

| 퍼즐 | 텍스처 prop |
|---|---|
| PUZ_01 레이저 | `crystalTriangleTexture` `crystalOctagonTexture` `crystalCrossTexture` `crystalTeeTexture` `crystalFlowerTexture` `emitterTexture` `receiverTexture` `relayTexture` `skullTexture` `crystalTexture`(기본) `fixedCrystalTexture` `placementTexture` `borderTexture` `boardTexture` |
| PUZ_02 러시아워 | `goalPieceTexture` `blockerPieceTexture` `emptyTexture` `borderTexture` `boardTexture` |
| PUZ_03 정렬 | `batteryTexture` `unknownTexture` `emptySlotTexture` `lockedSlotTexture` `boardTexture` |
| PUZ_04 색 채우기 | `cleanTexture` `contaminatedTexture` `inactiveTexture` `needleTexture` `boardTexture` |
| PUZ_05 연결 | `nodeStartTexture` `nodeEndTexture` `nodeTexture`(기본) `pathTexture` `emptyTexture` `boardTexture` |
| PUZ_06 카드 맞추기 | `hiddenTexture` `revealedTexture` `matchedTexture` `bombTexture` `boardTexture` |
| PUZ_07 슬라이드 | `pieceTexture` `emptyTexture` `boardTexture` |
| PUZ_08 스위치 | `pressedTexture` `unpressedTexture` `maskOnTexture` `maskOffTexture` `boardTexture` |

**레이저는 부품 그림을 이미 잘라 두었다.** `resources/textures/laser/` 의 8장을 그대로

```
LaserProp_CrystalTee.png       -> crystalTeeTexture

LaserProp_Skull.png            -> skullTexture
```

`boardTexture` 는 격자 **뒤에** 깔리는 판 그림이다. 칸 사이 간격으로 비쳐 보이므로
나무판·회로기판처럼 판 전체의 재질을 표현할 때 쓴다.

몇 개가 붙었는지는 시작 시 콘솔에 찍힌다.

```
[SwitchCoreAPI] Registered 2 textures. Elements without one are drawn with a flat colour.
```

### 3.3 OwnershipSetter

`targets` 에 **Local 로 도는 엔티티를 전부** 넣는다.

```
targets = [ PuzzleController(퍼즐마다 하나씩 전부), BoardPanel, HubPanel(쓴다면) ]
```

하나라도 빠지면 그 엔티티만 서버 인스턴스로 남아 조용히 아무 일도 하지 않는다.

> `ServerSpawner` 는 지금 필요 없다 (프리배치 방식).


### 3.5 트레이 배치와 진단

**트레이는 화면에 맞춰 줄을 쌓는다.** 부품은 트레이 높이를 채우는 정사각형이라, 세로로 긴
화면에서는 하나가 화면 폭의 40% 를 넘는다. 그래서 한 줄에 다 넣지 않고 **넘치지 않는
배치 중 부품이 가장 커지는 줄·칸 수**를 고른다 (`PuzzleUI_RelativeLayout.trayGrid`).

세로 폰(비율 0.46) 기준으로 이렇게 잡힌다. 어느 경우에도 **한 페이지에 전부 보인다.**

| 부품 수 | 배치 | 부품 한 변 |
|---|---|---|
| 1 | 1x1 | 화면 폭의 44% |
| 3 | 1x3 | 22% |
| 4 | 2x2 | 22% |
| 7 | 2x4 | 17% |

빈 슬롯은 세지 않는다 — 레이저가 슬롯을 일곱 개 선언해도 부품이 하나면 1x1 이 되어
그 하나가 트레이를 꽉 채운다. 부품을 판에 내려놓으면 남은 부품이 그만큼 커진다.

> **줄 수 상한은 `TRAY_MAX_ROWS`(3) 이다.** 그보다 잘게 쪼개면 부품이 손가락보다 작아진다.
> 상한으로도 다 담기지 않을 때만 좌우 화살표로 페이지를 넘긴다.

#### 부품이 안 보일 때 (진단)

레이저의 크리스탈처럼 **보조 레이아웃의 트레이에 놓이는 부품**이 화면에 나타나지 않을 때,
"애초에 만들어지지 않은 것" 인지 "만들어졌는데 가려진 것" 인지를 가르는 절차다.

진단은 **보내는 쪽과 받는 쪽 두 개**다. 둘을 같이 켜면 어디서 끊겼는지가 곧바로 갈린다.

```
PuzzleController(Laser_CoreAPI) 의 logInventory   = true   ← 보내는 쪽 (세션 -> 슬롯)
BoardPanel(PuzzleBoardUI_Panel) 의 showTrayDebug = true   ← 받는 쪽 (슬롯 -> 화면)
```

**보내는 쪽**은 콘솔에 한 줄을 남긴다.

```
[LaserCoreAPI] Inventory -> tray: session holds 3 crystals, wrote 3 of 7 slots: [0]=TRIANGLE tex=laser.crystalTriangle ...
```

**받는 쪽**은 화면 아래 진단 줄과 콘솔에 같은 요약을 남기고, 슬롯마다 형광 테두리 상자와
`번호+상태`(`0V` / `3.`)를 그린다.

```
tray items=7 vis=3 page=1/1 size=7 side=88 slots=VVV____
```

슬롯 글자를 읽는 법이다.

| 글자 | 뜻 | 부품이 안 보인다면 |
|---|---|---|
| `V` | 내용이 있고 페이지에도 펴져 있다 | 상자·내용 둘 다 있다 → 그림·색·크기를 본다 |
| `v` | 내용은 있는데 페이지에서 접혔다 | **가려진 것이다.** 화살표로 넘기면 나온다 |
| `.` | 펴져 있는데 내용이 비었다 | **만들어지지 않은 것이다.** 보내는 쪽 로그를 본다 |
| `_` | 접혀 있고 내용도 비었다 | 남는 슬롯. 정상이다 |

두 로그를 맞춰 보면 원인이 하나로 좁혀진다.

| 보내는 쪽 | 받는 쪽 | 원인 |
|---|---|---|
| `holds 0` | `items=7 vis=0` | 세션에 크리스탈이 없다 — 레벨 데이터/생성기 |
| `holds 3 wrote 3` | `items=0` | 트레이가 규격에 없다 (`itemCount`) 또는 보드가 안 올라왔다 |
| `holds 3 wrote 3` | `vis=0` | 기록이 프레젠터에서 막혔다 (슬롯 수 초과 등) |
| `holds 3 wrote 3` | `vis=3 slots=vvv` | 페이지에 접혔다 — 넘기면 보인다 |
| `holds 3 wrote 3` | `vis=3 slots=VVV` 인데 화면에 없다 | 그리기 문제 — 형광 상자가 보이는지로 다시 가른다 |

마지막 줄이 핵심이다. **형광 상자가 보이는데 그 안이 비었으면** 내용(색·그림)의 문제이고,
**형광 상자조차 안 보이면** 슬롯 상자가 접혔거나 높이가 0 인 배치의 문제다.

## 4. 셋업 순서

```
1. 빈 레벨에 SpawnPoint 배치
2. Custom UI gizmo 생성 -> PuzzleBoardUI_Panel 붙이고 실행 모드 Local
   - Display Mode 를 Screen Overlay 로 두면 배치가 필요 없다
3. Custom UI gizmo 하나 더 -> PuzzleUI_MainPanel 붙이고 실행 모드 Local
   - Display Mode 는 Screen Overlay
4. PuzzleController 빈 엔티티 + <퍼즐>_CoreAPI (Local) - 붙이고 싶은 퍼즐 수만큼
   - props 는 전부 기본값 (autoStart 는 꺼 둔 채로)
5. OwnershipSetter 빈 엔티티 + Puzzle_LocalOwnership (Default)
   - targets = [PuzzleController(전부), BoardPanel, HubPanel]
6. 플레이 -> 퍼즐 8종 격자(2열×4행)가 뜨고, 하나를 누르면
   Start / Continue / Return 화면이 뜨면 성공
```

### 4.1 진행도를 영구 저장하려면 (선택)

Continue 는 마지막으로 클리어한 레벨을 기억한다. **설정하지 않아도 게임은 돌지만**,
그 경우 진행도가 세션 동안만 유지되고 월드를 나가면 초기화된다.

```
1. Systems > Variable Groups > 새 그룹 "PuzzleHub"
2. 그 그룹에 변수 추가: 이름 "progress", 타입 String
3. HubPanel 의 progressVariableKey prop 이 "PuzzleHub:progress" 인지 확인 (기본값)
```

어느 쪽으로 붙었는지는 시작 시 콘솔에 찍힌다.

```
[PuzzleHub] Progress is stored in the persistent variable "PuzzleHub:progress".
[PuzzleHub] Progress is kept in memory only; it resets when the player leaves. ...
```

## 5. 카메라

**기본값(`focusCamera` 꺼짐)에서는 카메라를 건드리지 않는다.** 플레이어는 평소 시점 그대로
화면에 겹친 보드를 조작한다.

월드에 세운 패널(Spatial)을 정면에서 보게 하고 싶을 때만 `focusCamera` 를 켜고
`boardCentre` 에 BoardPanel 을 넣는다. 그러면 이렇게 배치된다.

```
카메라 위치 = boardCentre.position + boardCentre.forward * cameraDistance
카메라 방향 = -boardCentre.forward   (보드를 정면으로 바라본다)
```

`cameraObject` 에 엔티티를 넣으면 그 위치/방향을 그대로 쓴다.

## 6. 정상 동작 확인 — 콘솔 로그 순서

```
1. [SwitchCoreAPI] Server instance. Waiting for ownership transfer.
2. [PuzzleLocalOwnership] Transferred ownership of 2 entities to the player.
3. [SwitchCoreAPI] Started on the local client. Ownership transfer OK.
4. [SwitchCoreAPI] Switch area updated: 010111010
```

**1번은 정상 셋업에서도 한 번 뜬다.** 그 뒤에 3번이 이어서 뜨는지가 판단 기준이다.

`autoStart` 가 켜져 있으면 즉시 격자가 뜨고, 칸을 탭하면 (누른 칸 **위에서** 떼야 확정)
스위치 영역이 0.4초 연출과 함께 XOR 반전된다. 전부 녹색이면 라운드 클리어,
제한 시간 초과면 실패. **화면 아래 보조 레이아웃**의 3×3 미니 격자가 이번 라운드의
스위치 영역이고, 그 옆의 `Reset` 이 판을 처음 상태로 되돌린다 (시간은 그대로 흐른다).

### 6.1 실행 모드가 제대로 걸렸는지 로그로 판별하기

| 콘솔에 보이는 것 | 의미 |
|---|---|
| `Started on the local client. Ownership transfer OK.` | ✅ 제대로 걸렸다 |
| `Server instance. Waiting for ownership transfer.` **만** 뜬다 | ❌ 실행 모드가 `Default` 이거나 소유권이 안 넘어갔다 |
| `[PuzzleLocalOwnership] Transferred ownership of ...` 가 없다 | ❌ `OwnershipSetter` 가 없거나 `targets` 가 비었다 |
| 아무 로그도 없다 | ❌ 스크립트가 아예 안 붙었거나 컴파일 실패 |

## 7. 안 될 때 확인 순서

| 증상 | 원인 / 해결 |
|---|---|
| 아무 일도 안 일어남 / 1번 로그만 뜨고 멈춤 | 실행 모드가 `Default` 이거나 **소유권이 안 넘어감** (§1.1) |
| 월드에 다시 들어왔는데 직전 레벨이 떠 있음 | 2026-09-02 수정됨. HubPanel 이 뜰 때 돌던 퍼즐을 정리하고 메인 메뉴로 맞춘다. 진행도는 영구 변수에서 다시 읽으므로 그대로 남는다 |
| 로그 3번은 뜨는데 격자가 안 보임 | BoardPanel 이 `targets` 에 없다 → 서버 인스턴스라 빈 화면을 그린다 |
| 클리어했는데 결과 화면이 안 보임 | 2026-09-02 수정됨. 보드와 허브가 겹쳐 있었다 — 지금은 결과·일시정지 때 보드를 내린다. 그래도 안 보이면 HubPanel 이 `targets` 에 있는지 확인 |
| 격자는 보이는데 탭이 안 먹음 | 퀘스트가 시작되지 않았다. 메인 UI 에서 Start 를 누르거나 `autoStart` 를 켠다 |
| 아무 화면도 안 뜬다 | HubPanel 이 없고 `autoStart` 도 꺼져 있다 (기본값). 둘 중 하나를 마련한다 |
| **Start 를 누르면 UI 가 사라지고 아바타가 보인다** | **BoardPanel 이 없거나 서버 소유다.** 허브 UI 는 인게임에서 상단 바만 그리므로(PUZ_00 §8.5) 화면을 채우는 것은 BoardPanel 의 일이다. 콘솔에 `[PuzzleBoardStage] ... no panel is listening` 이 뜬다 |
| Continue 가 매번 잠겨 있다 | 영구 변수 그룹이 없어 메모리 저장으로 떨어졌다 (§4.1). 콘솔 로그로 확인 |
| 탭해도 색이 안 변함 | 누른 칸 위에서 떼야 확정된다 (PUZ_08 M2). 손가락을 옮겨 떼면 취소가 **정상** |
| 격자가 화면을 다 덮음 / 너무 작음 | `boardWidthPercent`(가로) 와 `boardHeightPercent`(영역 세로) 를 조정한다. 둘 중 작은 쪽이 판 크기를 정한다 |
| **판이 화면의 절반도 안 됨 / 글자만 작음** | 2026-09-03 개편으로 배치는 해결됐다. 글자만 작으면 `screenPixelRatio` 가 실제와 다른 것이다 (위 §에서 재는 법) |
| 판이 상태바·노치에 가림 | `topInsetPercent` 를 키운다 (기본 6) |
| `Menu` 버튼이 판을 가림 | `bottomInsetPercent` 를 키운다 (기본 8). 버튼은 그 띠 안에만 앉는다 |
| 모바일에서 버튼 글자가 작음 | 2026-09-02 수정됨. 글자 크기가 버튼 크기에서 도출된다. 버튼이 작으면 글자도 작으므로 버튼 비율을 키운다 |
| HUD 바와 보드가 겹침 | `topInsetPercent` 를 HUD 바 높이(상단 여백 2% + 높이 7%)보다 크게 |
| 트레이(레이저 크리스탈)에 부품이 안 보임 | 2026-09-04 수정됨. 트레이가 화면에 맞춰 줄을 쌓는다 (§3.5). 그래도 안 보이면 §3.5 의 진단을 켠다 |
| 배치가 이상한데 원인을 모르겠음 | `showLayoutProbe` 를 켜고 스크린샷 한 장. 읽는 법은 `../구현 사항/작업기록_2026-09-03_레이아웃_프로브_측정.md` §3 |
| `GameStart` 가 계속 떠 있고 Reset 버튼이 안 보임 | `introSeconds`/`introFadeSeconds` 가 너무 크다. 기본 0.45/0.3. **에디터에서 옛 값(1.5)을 덮어쓰고 있으면 prop 을 지워 기본값으로 되돌린다** |
| 초읽기에 소리가 안 남 | `countdownSound` 가 비어 있다 (§3.1.1). 점멸만 하는 것이 기본 동작 |
| 텍스처를 끼웠는데 안 보임 | 애셋이 **Texture** 인지 확인한다. 콘솔의 `Registered N textures` 가 0 이면 prop 이 비어 있는 것이다 |
| 텍스처가 온통 한 가지 색으로 나옴 | `tintTexturesWithFill` 이 켜져 있다 (§3.4). 이미 색이 칠해진 그림이면 끈다 |
| UI 옆으로 월드가 보임 | 두 패널의 콘솔 `canvas WxH` 가 서로 다르거나 화면 비율과 다르다. 그래도 남으면 **두 패널의 `canvasWidth`/`canvasHeight` 에 실측 값을 같이 넣는다** (`../구현 사항/버그수정_2026-09-02_UI가_화면을_꽉_채우지_않음.md` §10 · §12) |
| 끌고 가서 떼도 안 놓임 | `../구현 사항/버그수정_2026-09-02_드래그_놓기_판정_실패.md` §7 의 확인 순서를 따른다 |
| Reset 을 눌러도 아무 일이 없음 | 퀘스트가 시작되지 않았거나 일시정지·결과 화면이다. 판이 열려 있을 때만 받는다 |
| 칸이 정사각형이 아님 | 2026-09-03 개편으로 **모든 판에서 정사각형**이다. 아니면 격자 상자 계산(`computeGridBox`)을 의심한다 |
| 퍼즐 종료 후 카메라에 갇힘 | `focusCamera` 를 켰는데 `abort()` 경로를 안 거쳤다. 기본값이면 발생하지 않는다 |
| 격자가 9×9 로 뜬다 | 프레젠터 규격이 안 넘어왔다. `LEVEL_LOADED` 구독 배선 확인 |

## 8. 에디터 조작 요약

| 하고 싶은 것 | 방법 |
|---|---|
| 빈 오브젝트 만들기 | Build 메뉴 > Gizmos > **Empty Object** |
| Custom UI 만들기 | Build 메뉴 > Gizmos > **Custom UI** |
| Display Mode 바꾸기 | Custom UI gizmo 선택 > Properties 패널 > **Display Mode** |
| 스크립트 붙이기 | 오브젝트 선택 > Properties 패널 하단 **Attached Script** 드롭다운에서 선택 |
| 실행 모드 바꾸기 | **Scripts 패널**에서 스크립트 항목의 **⋮ (three-dot) 메뉴** > 실행 모드를 `Local` 로 |
| props 값 넣기 | 스크립트를 붙이면 Properties 패널에 `propsDefinition` 항목이 그대로 나타난다 |
| 소유권 | 코드로만 넘긴다 (`entity.owner.set(player)`) — `Puzzle_LocalOwnership` 이 담당 |

Scripts 패널의 각 항목은 아래처럼 표시되며, **부제의 `Default` / `Local` 이 곧 현재 실행 모드**다.

```
[T] Switch_CoreAPI                    [복제] [⋮] [삭제]
    Compiled · Default          <- 여기가 실행 모드
```

> 실행 모드 전환의 정확한 클릭 경로는 공식 문서에 명시돼 있지 않고 에디터 버전에 따라 다르다.
> 항목의 `⋮` 메뉴를 먼저 확인하고, 없으면 스크립트를 선택했을 때 나오는 설정 패널을 본다.

## 10. 에디터 재오픈 시 주의

- 이 폴더는 에디터가 열려 있는 동안 감시·동기화하는 작업 폴더다. 에디터가 닫힌 상태에서 지운 파일은
  다음에 월드를 열 때 **서버(클라우드) 기준으로 부활할 수 있다.** 부활했다면 에디터를 연 상태에서
  같은 파일들을 다시 지우면 된다 (목록 = `.backups` 의 `manual_removed` 항목).
- 매치3 엔티티들(보드, 메뉴 UI 등)은 스크립트 missing 상태로 표시된다. 오류가 아니라 예상된
  결과이며, 해당 엔티티를 에디터에서 삭제하면 정리가 끝난다.
