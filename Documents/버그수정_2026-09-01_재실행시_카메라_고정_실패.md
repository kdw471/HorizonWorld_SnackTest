# 버그 수정 기록 - 두 번째 실행부터 카메라가 고정되지 않는 문제

- **날짜**: 2026-09-01
- **증상**: 프리뷰를 처음 실행하면 고정 카메라가 정상 동작하지만, 정지 후 **다시 실행하면 카메라가 고정되지 않은 채**(아바타 3인칭 카메라) 퍼즐이 시작된다.
- **수정 파일**: `Puzzle_HorizonBridge.ts` (`enterPuzzleInteraction` / `exitPuzzleInteraction`)
- **영향 범위**: 이 브리지를 쓰는 8개 퍼즐 전부. 각 퍼즐의 `*_CoreAPI` 는 수정할 필요 없음.

---

## 1. 원인

### 1-1. 실행 순서가 첫 실행과 재실행에서 다르다

퍼즐 컨트롤러(`Switch_CoreAPI` 등)는 Local 실행 모드라서 다음 순서로 기동한다.

```
서버: PuzzleLocalOwnership 이 플레이어에게 소유권 이전
  → 클라이언트: *_CoreAPI.start() 실행
  → enterPuzzleInteraction() → LocalCamera.setCameraModeFixed() 호출
```

- **첫 실행**: 플레이어가 월드 로딩을 마치고 **뒤늦게 합류**한다. `OnPlayerEnterWorld` → 소유권 이전 → 로컬 `start()` 가 도는 시점에는 클라이언트의 카메라 시스템이 이미 준비되어 있어 `setCameraModeFixed()` 가 정상 동작한다.
- **재실행(두 번째부터)**: 플레이어가 **이미 월드 안에 있는 상태**에서 시뮬레이션만 리셋된다. 소유권 이전과 로컬 `start()` 가 월드 기동 직후, **클라이언트 카메라(LocalCamera) 초기화가 끝나기 전에** 실행된다. 이 시점의 `setCameraModeFixed()` 호출은 오류 없이 **조용히 무시**되어, 카메라가 고정되지 않은 채 퍼즐이 시작된다.

### 1-2. 원본 매치3 템플릿은 이미 이 문제를 알고 있었다

원본 `Basics_CoreAPI`(현재 `.backups` 에 보관)는 카메라 배치를 즉시 하지 않고 **300ms 지연**시켰다.

```ts
// .backups/Basics_CoreAPI.ts - 원본 매치3 템플릿
start() {
    if (this.entity.owner.get() !== this.world.getServerPlayer()) {
        this.constructSystems();
        this.async.setTimeout(() => {
            this.moveCamera();      // ← 카메라 배치를 300ms 뒤로 미룬다
        }, 300);
    }
}
```

퍼즐용으로 새로 만든 `enterPuzzleInteraction()` 은 이 지연 없이 `start()` 에서 **즉시** 카메라를 고정했기 때문에, 템플릿이 우회하고 있던 초기화 타이밍 문제가 재실행에서 다시 드러난 것이다.

## 2. 수정 내용 (`Puzzle_HorizonBridge.ts`)

### 2-1. 고정 카메라 적용을 함수로 분리

카메라 모드 + 위치/회전 + FOV 적용을 `applyFixedCamera(setup)` 하나로 묶었다. 같은 값을 `duration: 0` 으로 다시 놓는 것이라 **몇 번을 불러도 결과가 같다** (이미 성공한 경우 재적용해도 화면 변화 없음).

### 2-2. 즉시 1회 + 300ms/1000ms 재적용

```ts
const CAMERA_APPLY_RETRY_DELAYS_MS = [300, 1000];

export function enterPuzzleInteraction(component, setup) {
    // ... enterFocusedInteractionMode ...
    applyFixedCamera(setup);                       // 즉시 (첫 실행 커버)
    for (const delayMs of CAMERA_APPLY_RETRY_DELAYS_MS) {
        component.async.setTimeout(() => applyFixedCamera(setup), delayMs);  // 재실행 커버
    }
}
```

- 즉시 호출: 첫 실행처럼 카메라가 준비된 경우 지연 없이 고정된다.
- 300ms 재적용: 템플릿과 같은 값. 재실행 시 무시된 첫 호출을 회복한다.
- 1000ms 재적용: 300ms 로도 부족한 느린 기기/로딩을 대비한 보험.

### 2-3. 퍼즐 종료 시 예약 취소

`exitPuzzleInteraction()` 첫머리에서 대기 중인 재적용 타이머를 모두 취소한다. 취소하지 않으면 **퍼즐 진입 직후 바로 abort 한 경우**, 뒤늦게 발화한 타이머가 이미 풀어 준 카메라를 다시 고정해 플레이어가 갇힐 수 있다.

---

## 3. 확인 방법

1. 프리뷰 실행 → 퍼즐 시작 → 카메라가 보드 정면에 고정되는지 확인 (기존과 동일해야 함).
2. 프리뷰 정지 → **다시 실행** → 이번에도 카메라가 고정된 채 시작되는지 확인 (수정 전에는 여기서 실패).
   - 재실행 직후 최대 0.3초 정도 아바타 카메라가 보였다가 고정되는 것은 정상이다 (300ms 재적용이 회복하는 순간).
3. 퍼즐 시작 직후 곧바로 메뉴로 나가기(abort) → 1초 이상 기다려도 카메라가 다시 고정되지 **않는지** 확인 (타이머 취소 검증).

## 4. 비고

- 같은 증상이 재발한다면 `[SwitchCoreAPI] Started on the local client.` 로그가 재실행에서도 찍히는지 먼저 확인할 것. 이 로그가 없다면 카메라 문제가 아니라 `PuzzleLocalOwnership` 의 소유권 이전 자체가 안 된 것이다 (다른 원인, 다른 수정 필요).
- `CAMERA_APPLY_RETRY_DELAYS_MS` 에 시점을 추가/조정할 수 있다. 재적용은 눈에 보이지 않으므로 값을 늘려도 부작용은 없다.
