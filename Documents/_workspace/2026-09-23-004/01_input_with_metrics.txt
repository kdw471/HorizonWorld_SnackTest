## 먼저 확인한 것

올려주신 스크린샷 두 장을 픽셀 단위로 재봤습니다. 칸 크기 58px, 조각 안쪽 여백 3px 기준으로 블록의 연속 좌표를 역산하면:

- 1번 사진: 블록 좌상단이 칸 기준 0.155 → 윗칸을 84% 덮음 → 미리보기가 윗칸으로 올라가 있고, 원래 자리에 올리브색 실루엣이 보입니다.
- 2번 사진: 블록 좌상단이 0.638 → 윗칸을 36%만 덮음 → 미리보기가 원래 자리 그대로라 실루엣이 없고 길(파란 칸) 5개가 전부 보입니다.

즉 **드래그 중 미리보기는 이미 "절반" 규칙대로 움직이고 있었습니다.** 문제는 손을 뗄 때였습니다.

## 원인

`NoesisBoard_Panel.onPointerUp` 이 Up 이벤트의 좌표를 한 번 더 컨트롤러에 밀어 넣고 있었습니다. 그런데 실기에서 Up 좌표는 Move 와 기준이 달라서, 이 값이 들어가면 잡은 지점 대비 delta 가 통째로 어긋납니다. 기존 코드는 "마지막 Move 에서 한 칸 안이면 채택"이라는 완충을 뒀는데, 절반 판정을 뒤집는 데는 한 칸이 필요 없습니다. 0.1칸만 어긋나도 0.45 → 0.55 가 되면서 결과가 바뀝니다. 드래그 내내 보여주던 칸과 다른 칸에 놓이는 이유가 이것이었습니다.

## 고친 내용

1. `RushHour_Definitions.ts` — 스냅 규칙을 `snapAxisValueToCell()` 하나로 뽑았습니다. `Math.floor` 로 칸을 잡고 겹침이 0.5를 **넘을 때만** 다음 칸으로 보냅니다. 딱 0.5는 "넘지 않은" 것으로 봅니다 (`Math.round` 는 양수 쪽으로만 올려서 위/아래 판정이 비대칭이 됩니다).
2. `RushHour_DragController.end()` / `RushHour_CoreAPI.trackDragToLocal()` / `RushHour_Board.snapFromContinuous()` — 세 곳이 전부 같은 함수를 쓰도록 했습니다. 미리보기와 확정이 갈라질 수 없습니다.
3. `NoesisBoard_Panel.onPointerUp()` — Up 좌표를 놓는 자리 계산에 쓰지 않습니다. 마지막 Move 좌표로만 확정합니다. `UP_POINT_MAX_DRIFT_CELLS` 상수는 제거했습니다. Up 좌표는 로그에만 남겨 두었습니다.
4. `RushHour_CoreAPI.onPieceDrop()` — 뗄 때 좌표를 다시 `trackDragToLocal` 에 넣지 않습니다. 진단 로그는 "미리보기 자리 vs 확정된 보드 자리" 비교로 바꿨습니다.

`tsc --noEmit` 으로 확인했고, 건드린 파일에서는 오류가 없습니다 (다른 오류들은 `Documents/SampleHtml`·`types/` 쪽 기존 것입니다). `Documents/Tests/RushHour_Tests.ts` 의 0.4/0.6 반올림 테스트도 새 규칙에서 그대로 통과합니다.

## 남은 것 하나

`RushHour_DragController.findPieceAt()` 은 터치 좌표를 "정수 = 칸 중심"으로 보고 거리를 재는데, 패널이 주는 좌표는 "정수 = 칸 왼쪽 위 모서리"입니다. 반 칸이 어긋나 있어서, 조각이 서로 붙어 있으면 패널이 맞힌 조각과 컨트롤러가 고른 조각이 달라질 수 있습니다. 이번 스냅 문제와는 별개라 손대지 않았는데, 이어서 정리할까요?
