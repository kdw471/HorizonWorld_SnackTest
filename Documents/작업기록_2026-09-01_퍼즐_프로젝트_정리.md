## 1. 스위치 퍼즐(PUZ_08) 빈 레벨 세팅 가이드

### 1.1 필요한 스크립트

| 분류 | 파일 |
|---|---|
| 스위치 퍼즐 | `Switch_Definitions`, `Switch_Board`, `Switch_InputController`, `Switch_Session`, `Switch_Solver`, `Switch_LevelGenerator`, `Switch_DataTables`, `Switch_GameEvents`, `Switch_CoreAPI` |
| 공통 계층 | `Puzzle_HorizonBridge`, `Puzzle_LocalOwnership`, `PuzzleUI_Definitions`, `PuzzleUI_Registry` |
| 공용 의존 | `Basics_Input_Screen`, `Utility_Events` — **이름이 매치3 계열 같아도 절대 지우면 안 됨** |

### 1.2 월드에 만들 엔티티 (5종)

**① PuzzleController (빈 엔티티)** — `SwitchCoreAPI` 스크립트를 붙인다. 실행 모드는 **반드시 Local**.

| Prop | 값 |
|---|---|
| `boardCentre` | ②번 엔티티 |
| `keyCapRoot` | ③번 엔티티 |
| `cellSpacing` | 0.07 (기획서 §3 키 판 7cm, 기본값) |
| `difficulty` | 시작 난이도 1~5 |
| `autoStart` | 단독 테스트면 켬. 메인 UI/트리거 시작이면 끔 |
| `cameraObject` | **비워 둠** (보드 정면에 자동 배치됨) |
| `cameraDistance` / `cameraFov` | 0.6 / 40 (기본값) |

**② BoardCentre (빈 엔티티)** — 키 판의 중심. 이 엔티티의 축이 보드 평면을 정의한다:
**forward = 플레이어(화면 바깥) 방향, right = +열, up = −행.**
카메라도 forward 방향 0.6m 앞에 자동 배치된다.

**③ KeyCapRoot (부모 엔티티) + 자식 키 캡 25개**

- 자식 이름은 `KeyCap_00` ~ `KeyCap_24` 처럼 **자리수를 맞춰서** 붙인다.
  이름 오름차순 = A1..E5 (row-major) 순서. 자리수가 다르면 문자열 정렬 때문에 순서가 틀어진다.
- 자식 위치는 대충 둬도 된다 — 레벨 로드 시 스크립트가 격자 위치로 자동 배치하고 FREE 칸은 숨긴다.
- 눌림 상태를 틴트로 칠하므로(눌림 = 녹색, 안 눌림 = 빨강) 틴트 가능한 메시여야 한다.
- **Motion 속성을 `Animated`로 설정할 것** (아래 4.1 참조).
- 비워 두면 연출 없이 로직만 도는 헤드리스 모드로 동작한다.

**④ InputScreenListener 엔티티** — `Basics_Input_Screen`의 `InputScreenListener`를 붙인다.
터치 입력이 전부 여기서 나온다. Focused Interaction 입력은 로컬에서만 발생하므로 **Local 모드**.

**⑤ LocalOwnership 엔티티** — `Puzzle_LocalOwnership`을 붙인다. 실행 모드는 **Default(서버)** 그대로.
`targets`에 **①번과 ④번 엔티티**를 넣는다. Local 스크립트는 플레이어 소유가 되어야 실행되므로,
이 컴포넌트가 첫 입장 플레이어에게 소유권을 넘겨 준다.

### 1.3 정상 동작 확인 (콘솔 로그 순서)

1. `[SwitchCoreAPI] Server instance. Waiting for ownership transfer.`
2. `[PuzzleLocalOwnership] Transferred ownership of 2 entities to the player.`
3. `[SwitchCoreAPI] Started on the local client. Ownership transfer OK.`

`autoStart`가 켜져 있으면 즉시 카메라가 보드 정면에 고정되고, 키 캡을 탭하면
(누른 캡 위에서 떼야 확정) 스위치 영역이 0.4초 연출과 함께 XOR 반전된다.
전부 녹색이면 라운드 클리어, 제한 시간 초과면 실패.

### 1.4 흔한 실패 패턴

| 증상 | 원인 / 해결 |
|---|---|
| 1번 로그만 뜨고 멈춤 | CoreAPI 실행 모드가 Local이 아니거나, LocalOwnership `targets`에 PuzzleController가 빠짐 |
| 터치가 전혀 안 됨 | InputScreenListener 엔티티가 없거나 서버 소유라 로컬에서 안 돎 |
| 자식 개수 경고 | `keyCapRoot` 자식이 25개가 아님 |
| 퍼즐 종료 후 카메라에 갇힘 | 메뉴 복귀 경로에서 `abort()`를 호출해야 Focused Interaction 해제. autoStart 단독 테스트에서 클리어 후 갇히는 것은 정상 |

## 4. 트러블슈팅 기록

### 4.1 "unable to manipulate static entity (moveto)"

- **원인**: 메시 겹침이 아니라, **Motion 속성이 `None`(정적)인 엔티티를 스크립트로 움직이려 해서** 발생.
  `Switch_CoreAPI`가 레벨 로드 시 키 캡 25개를 `entity.position.set()`으로 격자 위치에 자동 배치하는데,
  정적 엔티티는 트랜스폼이 고정되어 있어 이 호출이 거부된다.
- **해결**: KeyCap_00 ~ KeyCap_24 전부 선택 → Properties에서 **Motion을 `None` → `Animated`로 변경**.
  - BoardCentre는 스크립트가 읽기만 하므로 바꿀 필요 없음.
  - `Interactive`(잡기/물리)가 아니라 `Animated`가 올바른 설정이고 비용도 더 싸다.
  - 오류가 계속되면 25개 중 일부만 `None`으로 남았는지 확인.

### 4.2 콘솔 한글 로그 깨짐 → 로그 영어화 (완료)

- Horizon 콘솔에서 한글 로그가 깨져 보여, **콘솔로 나가는 문자열을 전부 영어로 교체**했다 (24개 파일, 138건).
  - 직접 `console.log/warn` 메시지
  - `console.warn`에 join되어 출력되는 `violations` 검증 메시지 (각 퍼즐 DataTables/LevelGenerator)
  - 로그에 삽입되는 조각 문자열 (RushHour의 행/열 축 이름, ColorFill 다이얼 디버그 문자열 등)
- **한글 유지**: 플레이어에게 보이는 UI 텍스트(퍼즐 이름·부제, 버튼, 토스트, 퀘스트 표시명)는
  콘솔 깨짐과 무관한 화면 표시용이라 그대로 뒀다.
- **제외**: `*_Tests.ts` 9개 (한글 약 670줄) — 컴포넌트로 등록되지 않아 월드에서 자동 실행되지 않고,
  `runXxxTests()`를 직접 호출할 때만 돌아간다. 인월드 테스트 실행 계획이 생기면 그때 번역.
- **규칙**: 앞으로 이 프로젝트의 로그(및 로그로 흘러가는 문자열)는 영어로 작성한다.
- 작업 후 `tsc --noEmit` 오류 0건, 로그 경로 잔여 한글 0건 확인.
