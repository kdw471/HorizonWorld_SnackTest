## 3. 공통 편집기

문법 강조된 `<pre>` 위에 투명한 `<textarea>` 를 겹친 구조. 두 요소의 글꼴·줄 간격·여백·줄바꿈 규칙을 똑같이 맞춰 커서와 글자가 어긋나지 않게 했다. 줄바꿈(`pre-wrap`)은 항상 켜져 있어 가로 스크롤이 없다.

| 조작 | 동작 |
|---|---|
| RUN ▸ / `Ctrl(⌘) + Enter` | 실행 |
| `Tab` | 2칸 들여쓰기 |
| `Esc` | 편집기에서 빠져나감 (Tab 이 들여쓰기로 쓰이므로 키보드 탈출구) |
| ↺ 되돌리기 | 현재 파일을 원래 코드로 복구 (수정했을 때만 보임, 읽기 전용 파일에는 없음) |
| 콘솔의 오류 줄 클릭 | 편집기의 해당 줄·열로 이동 (TS 타입 오류) |

**자동 저장** — 고친 코드는 브라우저 `localStorage` 에 파트·파일별로 저장된다. 새로고침해도 남고, 수정된 파트는 목록에 점이 찍힌다. 원래 코드와 같아지면 저장 항목을 지운다.

```
키 형식:  lab:v3:<실습실>:<파트 제목>:<파일 이름>
예:       lab:v3:dx:삼각형 그리기:Shader.hlsl
          lab:v3:promise:part        ← 마지막으로 보던 파트 번호
          lab:v3:tab                 ← 마지막으로 보던 탭
```

**콘솔** — 각 줄 앞의 숫자는 실행 시작 기준 경과 시간(ms). 이전 실행의 뒤늦은 로그는 실행 토큰으로 걸러 낸다(파트를 바꾸거나 다시 RUN 하면 이전 실행의 출력이 섞이지 않는다).

## 4. Promise 실습실

언리얼 엔진의 `OnSuccess` / `OnFailed` 델리게이트와 대비해 설명한다. 핵심 대비점:

- 델리게이트는 여러 번 발사되고, 놓치면 끝이다 → Promise 는 **한 번만 확정**되고 **결과를 보관**해 늦게 구독해도 받는다
- 델리게이트는 `Broadcast` 자리에서 동기 호출 → Promise 콜백은 **항상 마이크로태스크**로 비동기
- 블루프린트는 실패 핀을 노드마다 연결 → Promise 는 체인을 따라 **에러가 전파**된다
- 델리게이트는 `RemoveDynamic`/`Cancel` 로 끊을 수 있다 → Promise 는 **취소가 없다** (`AbortController` 로 요청)

실행 방식: 편집기 코드를 `new Function('log','sleep','fail', 'return (async function(){ … })()')` 로 감싸 실행. 최상위 `await` 가능.

| 헬퍼 | 설명 |
|---|---|
| `log(msg, kind?)` | 콘솔 출력. kind: `ok` `err` `info` `micro` `macro` `sys` |
| `sleep(ms, value?)` | ms 뒤 value 로 fulfilled |
| `fail(ms, reason)` | ms 뒤 `Error(reason)` 으로 rejected |

| # | 파트 | 확인하는 것 |
|---|---|---|
| 01 | 상태 머신 | 이미 확정된 Promise 도 콜백은 다음 틱에 실행 (상태 다이어그램 포함) |
| 02 | 실행 순서 | 동기 → 마이크로태스크 → setTimeout 순서 고정. 첫 방문 시 자동 실행 |
| 03 | Promise 만들기 | executor 는 동기, 두 번째 resolve 는 조용히 무시 |
| 04 | then · catch · finally | finally 는 값을 건드리지 않고 통과 |
| 05 | 체이닝과 평탄화 | return 누락 시 다음 단계가 undefined 를 즉시 받음 |
| 06 | 에러 전파와 복구 | 중간 단계 스킵 → catch → 정상 리턴으로 체인 복구 |
| 07 | async / await | try/catch/finally 통합, async 는 항상 Promise 반환. `TFuture`/`TPromise` 비교 |
| 08 | 순차 vs 병렬 | 순차 240ms vs 병렬 80ms 실측. eager 실행 모델 |
| 09 | 조합 API 네 가지 | all / allSettled / race / any 확정 조건 (표 포함) |
| 10 | 타임아웃과 취소 | race 타임아웃 뒤에도 원 작업은 계속, AbortController 로 실제 정리 |
| 11 | 재시도와 백오프 | 지수 백오프 30 → 60 → 120ms |
| 12 | 반복문 속 비동기 | forEach + async 는 기다리지 않음 / for + await / map + Promise.all |
| 13 | 체인 vs 분기 | 같은 Promise 에 then 두 번 = 분기. 확정 뒤 구독해도 값을 받음 |
| 14 | 함정 정리 | 실수 네 가지를 한 스크립트에서 재현 |

각 파트 설명 끝에 **"바꿔 보기"** 한 줄이 있다 — 어디를 고치면 무엇이 달라지는지.

## 6. DirectX 12 실습실

### 6.1 실행 방식

브라우저는 C++ 도, D3D12 도 실행할 수 없다. 그래서 파트마다 파일 탭을 셋 둔다.

| 파일 | 실행 | 역할 |
|---|---|---|
| `Shader.hlsl` | 예 | HLSL 부분집합 → GLSL ES 3.00 으로 변환해 WebGL2 로 컴파일 |
| `Pipeline.js` | 예 | C++ 이 하던 리소스 생성·커맨드 기록을 D3D12 호출 이름과 1:1 대응하는 `dx.*` API 로 수행 |
| `D3D12.cpp` | 아니오 (읽기 전용 "참고") | 실제 D3D12 코드 발췌. Pipeline.js 의 어느 줄에 해당하는지 주석으로 연결 |

RUN 을 누르면:

```
① Pipeline.js 파싱 (setup / frame 함수 추출)
② Shader.hlsl → GLSL 변환 (VS · PS · 컴퓨트 엔트리)
③ 그래픽스 프로그램 컴파일·링크        ← D3DCompile + CreateGraphicsPipelineState
④ setup(dx) 한 번                       ← 리소스 생성
⑤ 입력 어셈블러 구성                    ← IASetVertexBuffers / IASetIndexBuffer
⑥ 매 프레임 frame(dx, t)                ← 커맨드 기록 + 실행
```

뷰포트(16:9)에는 정지/재생 버튼, 경과 시간·프레임 수, **변환된 GLSL** 버튼(콘솔에 줄 번호와 함께 출력)이 있다. DX 탭이 보이지 않을 때는 렌더 루프를 멈춘다.

### 6.3 D3D 규약을 맞춘 부분

- **행렬** — `m4` 는 DirectXMath 와 같은 행 벡터·왼손 좌표계(이동 성분이 4번째 행). HLSL `mul(v, M)` 은 GLSL `v * M` 으로 바뀌며, 상수 버퍼에 올리기 전 `m4.transpose` 가 C++ 의 `XMMatrixTranspose` 단계에 해당
- **클립 z** — D3D 의 [0, 1] 을 정점 셰이더 끝에서 GL 의 [-1, 1] 로 변환 (`gl_Position.z = z * 2 - w`)
- **감기 방향** — D3D 기본(`FrontCounterClockwise = FALSE`, 시계 방향 = 앞면)을 `gl.frontFace(CW)` 로 맞춤. `geom.cube()` 는 바깥에서 시계 방향이 되도록 인덱스를 만든다
- **SV_POSITION** — 픽셀 셰이더에서 읽으면 y 를 뒤집어 D3D 처럼 위→아래 증가

## 7. Pipeline.js API

`setup(dx)` 는 한 번, `frame(dx, t)` 는 매 프레임(t 는 초) 호출된다. 전역으로 `m4`, `geom` 헬퍼가 있다.

### 7.1 setup — 리소스 생성

| 호출 | D3D12 대응 | 비고 |
|---|---|---|
| `dx.inputLayout([[sem, fmt], …])` | `D3D12_INPUT_ELEMENT_DESC[]` | fmt: `float` `float2` `float3` `float4` |
| `dx.vertexBuffer(floats)` | `CreateCommittedResource` + `Map`/`memcpy` | 레이아웃 순서로 인터리브 |
| `dx.indexBuffer(ints)` | `D3D12_INDEX_BUFFER_VIEW` (R16_UINT) | |
| `dx.texture(name, {width, height, data, filter, wrap})` | 텍스처 + SRV + 정적 샘플러 | RGBA8. filter `POINT`/`LINEAR`, wrap `WRAP`/`CLAMP`/`MIRROR` |
| `dx.computeTarget(name, {width, height, data?, float?})` | `ALLOW_UNORDERED_ACCESS` 텍스처 (UAV) | 내부에 2장, dispatch 마다 교체(핑퐁). `float` 은 `EXT_color_buffer_float` 가 있을 때만 |
| `dx.bind({ shaderName: resourceName })` | SRV/UAV 슬롯에 리소스 꽂기 | 셰이더 변수명 ≠ 리소스명일 때 |
| `dx.pipelineState({…})` | `D3D12_GRAPHICS_PIPELINE_STATE_DESC` | `topology` `cullMode`(NONE/FRONT/BACK) `frontCounterClockwise` `depthEnable` `depthFunc` `depthWrite` `blend`(OPAQUE/ALPHA/ADD) |
| `dx.entry({vs, ps})` | D3DCompile 엔트리 이름 | 기본 `VSMain` / `PSMain` |

### 7.2 frame — 커맨드 기록

| 호출 | D3D12 대응 | 비고 |
|---|---|---|
| `dx.clear([r,g,b,a], depth?)` | `ClearRenderTargetView` / `ClearDepthStencilView` | |
| `dx.constants({name: value})` | 상수 버퍼 `memcpy` | float / 배열 2~4 / 배열 16(mat4). cbuffer 에 없는 이름은 콘솔 경고 |
| `dx.draw(vertexCount, instances)` | `DrawInstanced` | |
| `dx.drawIndexed(indexCount, instances)` | `DrawIndexedInstanced` | indexBuffer 필요 |

## 8. HLSL 변환 규칙

### 8.1 그래픽스 셰이더

| HLSL | GLSL | 비고 |
|---|---|---|
| `float2/3/4`, `float4x4`, `int2`, `uint3` … | `vec2/3/4`, `mat4`, `ivec2`, `uvec3` … | `half` → `float` |
| `cbuffer { … }` | `uniform …` | 이름으로 `dx.constants` 와 연결 |
| `struct … : SEMANTIC` | struct + `in`/`out` 변수 | VS 입력 시맨틱 → attribute, VS 출력 필드 → varying (정수형은 `flat`) |
| `SV_POSITION`, `SV_TARGET` | `gl_Position`, `fragColor` | |
| `SV_VertexID`, `SV_InstanceID` | `gl_VertexID`, `gl_InstanceID` | uint 선언이면 캐스팅 |
| `Texture2D` + `SamplerState`, `.Sample()` | `sampler2D`, `texture()` | `.SampleLevel` → `textureLod`, `tex[xy]` / `.Load` → `texelFetch` |
| `mul(a, b)` | `(a) * (b)` | 중첩 가능 |
| `lerp` `saturate` `frac` `atan2` `rsqrt` `fmod` `ddx`/`ddy` `clip` | `mix` `clamp(…,0,1)` `fract` `atan` `inversesqrt` `mod` `dFdx`/`dFdy` `discard` | |
| `1.0f`, `2f` | `1.0`, `2.0` | 접미사 제거 |
| `input` `output` `sample` `filter` … | `input_` … | GLSL 예약어 회피 |

> **가장 흔한 오류 — GLSL 에는 암시 형변환이 없다**
> - `float x = 1;`, `uv * 2` → 오류. `1.0`, `2.0` 으로 쓴다
> - `uint` 와 비트 연산: HLSL 의 `id & 2` 는 GLSL 에서 "uint 와 int 불일치" 오류 → **`id & 2u`**
> - 벡터 생성자(`float3(1, 0, 0)`)는 괜찮다

### 8.2 컴퓨트 셰이더 에뮬레이션

WebGL2 에는 컴퓨트 셰이더가 없다. `[numthreads(x,y,z)]` 가 붙은 함수를 **픽셀 셰이더로 바꿔**, 출력 텍스처를 렌더 타깃으로 걸고 풀스크린 삼각형을 그린다. 픽셀 하나 = 스레드 하나, `SV_DispatchThreadID` = `gl_FragCoord` 의 정수 좌표. GPU 에서 실제로 병렬로 돈다.

| 기능 | 지원 |
|---|---|
| `RWTexture2D` 에 자기 픽셀 쓰기 (엔트리마다 하나) | ✅ |
| `Texture2D` 임의 위치 읽기 (`tex[xy]`, `.Load`) — 이웃 읽기 | ✅ |
| `SV_DispatchThreadID` / `SV_GroupThreadID` / `SV_GroupID` / `SV_GroupIndex` | ✅ (numthreads 로 계산) |
| 다른 위치에 쓰기 (scatter) | ❌ |
| `groupshared`, `GroupMemoryBarrierWithGroupSync` | ❌ (C++ 참고 탭에서 설명) |
| 원자 연산 (`InterlockedAdd` …) | ❌ |
| 3D 디스패치 (z > 1) | ❌ |

`dx.dispatch` 는 항상 "현재" 텍스처를 읽고 "뒷면"에 쓴 뒤 교체한다 — D3D12 의 UAV ↔ SRV 상태 전이와 리소스 두 개 교대에 해당.

11번 파트의 "스레드" 는 브라우저 JS 가 단일 스레드라 **순서대로 실행되는 기록 함수**다. 실제 병렬은 아니지만 기록/제출 분리, 리스트별 상수, 제출 순서 = 실행 순서는 그대로 재현된다.

### 해결한 버그

## 11. 운영 주의

- **공개 공유 링크의 버전 고정** — 새 버전을 발행해도 링크로 연 화면이 그대로면, 공유 메뉴에서 공유 버전을 최신으로 갱신하거나 공개 공유를 껐다 켠 뒤 강력 새로고침(Ctrl+Shift+R). 이전 버전의 대표 증상: 모든 편집기가 비어 있고 TS 탭이 "컴파일러 불러오는 중…" 에서 멈춤
- **Claude 호출 기능(`sample`)은 공개 공유와 함께 쓸 수 없다** — "페이지 수정" 같은 기능을 되살리려면 공개 공유를 꺼야 한다
- **편집 내용은 브라우저 로컬에만 저장** — 다른 기기·브라우저·시크릿 창과 공유되지 않는다
- **TS 컴파일러는 cdnjs 에서 내려받는다** — 첫 로딩에 수 초, 차단된 네트워크에서는 TS 탭 실행 불가
- **WebGL2 필요** — 없으면 DX 탭 뷰포트에 안내가 나오고 렌더링하지 않는다

## 12. 한계

- C++ 은 실행되지 않는다 (D3D12.cpp 는 참고용)
- HLSL 변환기는 부분집합: 지오메트리/헐/도메인 셰이더, `Texture2DArray`, `StructuredBuffer`, 다중 렌더 타깃, 스텐실 미지원
- 컴퓨트 에뮬레이션의 제약은 §8.2 표 참고
- 깊이 범위를 [0,1] → [-1,1] 로 늘려 쓰므로 근평면 근처 클리핑이 미세하게 다를 수 있다
- 컴퓨트 타깃 `float` 형식은 GPU 가 `EXT_color_buffer_float` 를 지원할 때만 (아니면 8비트로 대체하고 콘솔에 안내)

## 13. 검증 방법

발행 전에 Node 에서 자동으로 확인한다. GPU 컴파일·실제 그림은 브라우저에서만 확인할 수 있다.

| 검사 | 내용 |
|---|---|
| 스크립트 문법 | 페이지의 `<script>` 블록 10개를 `new Function` 으로 파싱 |
| TS 예제 13개 | 페이지와 같은 lib·옵션으로 타입 검사 + 실행. 의도된 오류 수(13번 파트 4개)와 일치하는지 |

| jsdom 스모크 | 페이지를 실제 로드: 부팅 오류 없음, 파트 수(14 / 13 / 11)·편집기 내용·파일 탭, 탭 전환, RUN, 파일·파트를 오가도 편집 유지, **파트 간 편집 격리**, 되돌리기 |

브라우저에서의 최종 확인 기준:

- 세 탭 모두 편집기에 코드가 보이고 파트 수가 14 / 13 / 11
- TS 탭 하단이 `TypeScript 4.7.4 · strict …` 로 바뀜
- DX 01번 RUN 시 삼각형, 09번 RUN 시 움직이는 맨델브로 (콘솔에 빨간 줄 없이 `프레임 루프 시작`)
