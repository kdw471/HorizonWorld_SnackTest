# 퍼즐 게임 생성 프롬프트 모음

`Docs/` 폴더의 시스템 기획서 8종(PDF 5 + PPTX 3)을 분석하여, **각 게임을 그대로 구현할 수 있는 프롬프트 형식**으로 정리한 문서 모음입니다.

## 사용 방법

1. **`PUZ_00_공통_퍼즐모드_기반.md`를 먼저 읽힌다.** (모드 구조, 패널 레이아웃, 조작 규격, 3계층 테이블 등 8개 퍼즐 공통 컨텍스트)
2. 만들고자 하는 퍼즐의 개별 프롬프트를 **이어서** 제공한다.
3. 각 문서의 마지막 `구현 요구사항` 절에 알고리즘/자료구조/레벨 생성기/테스트 케이스가 명시되어 있으므로, 그대로 구현 지시로 사용한다.

```
[공통 기반 프롬프트]  +  [개별 퍼즐 프롬프트]  →  게임 구현
```

## 8개 퍼즐의 공통 골격

모든 퍼즐이 아래 구조를 공유하므로, 하나의 프레임워크 위에 8개 룰셋을 얹는 방식으로 구현하는 것을 권장합니다.

```
- 제한 시간 기반 승패 판정 (시간 초과 = 실패)
- 난이도별 제한시간 / 라운드 수 (퍼즐당 1~3 라운드)
- 3계층 데이터 테이블 (메인 / 필드 / 오브젝트)
- 해킹 패널(퍼즐 보드) + CCTV 패널(연출) 2패널 VR UI
- 손 형태 전환 → 인디케이터 → 그랩/터치 → 햅틱 진동 인터랙션
- 오브젝트 상태: On / Off / Fault
```

## 레벨 생성 시 공통 원칙

각 프롬프트에 명시했듯, **무작위 배치 대신 "완성 상태에서 역방향으로 흐트러뜨리는" 방식**을 우선합니다. 이는 항상 해가 존재함을 보장합니다.

- PUZ_03 정렬 / PUZ_07 슬라이드 / PUZ_08 스위치 → **역방향 셔플로 solvability 보장**
- PUZ_01 레이저 / PUZ_02 러시아워 → **솔버(탐색/BFS)로 생성 결과를 검증 후 채택**
- PUZ_05 연결 → **경로 분해 방식으로 생성**하여 "모든 서브 사용" 조건 자동 충족
- PUZ_04 색 채우기 → **자동 플레이 봇 시뮬레이션**으로 제한 시간 내 클리어 가능 여부 검증
- PUZ_06 카드 맞추기 → `iObjectTile`이 **짝수인지 데이터 검증** 필수
