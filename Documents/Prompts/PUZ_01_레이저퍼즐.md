## 프롬프트

**너의 역할:** 아래 명세를 그대로 만족하는 "레이저 해킹" 퍼즐 게임을 구현하라. 레벨 데이터로 구동되고, 항상 풀 수 있는 레벨만 생성하는 솔버/제너레이터를 함께 포함해야 한다.

### 1. 컨셉 & 목표

- **컨셉:** 끊겨 있는 신호를 연결해, 잠겨 있는 문을 여는 등의 '기믹 활성화'에 사용한다.
- **목표:** 크리스탈을 사용해, **레이저를 특정 지점(수신체)에 도달**하게 만든다.

### 2. 필드 규격

```
┌───────────────────────────┐
│  발사체/수신체 전용 테두리 (1칸)   │   ← 플레이어 배치 불가
│  ┌─────────────────────┐  │
│  │                     │  │
│  │   5 × 5 배치 영역     │  │   ← 크리스탈 배치 / 중계체·해골 배치
│  │                     │  │
│  └─────────────────────┘  │
└───────────────────────────┘
        [크리스탈 인벤토리 슬롯 — 최대 5개]
        [라운드 표시]
```

- **크리스탈 배치 영역: 5×5 고정.**
- 그 **주변 1칸씩의 테두리 영역**은 발사체–수신체 기믹이 배치되는 영역으로, 플레이어는 이용할 수 없다. (문서상 발사체/수신체 배치 영역은 2×7, 2×5 형태로 표기)
- 플레이어가 사용할 수 있는 크리스탈이 놓인 인벤토리 영역: **최대 5개**.
- 별도의 **라운드 표시** UI 존재.
- 모든 크리스탈과 기믹은 **1×1 기본 바닥**을 가진 형태이며, 그 위에 크리스탈/발사체가 배치된다.

### 3. 핵심 규칙 (그대로 구현할 것)

```
1.0  레이저는 발사 오브젝트에서 출발한다.
1.1  레이저는 직선으로만 출력된다.
1.2  발사체 오브젝트의 색상 == 레이저의 색상.
     (빨간 발사체 = 빨간 레이저, 초록 발사체 = 초록 레이저)

2.0  수신 오브젝트에 레이저가 도달하면 완료된다.
2.1  단, 수신 오브젝트의 컬러 == 도달한 레이저의 컬러여야 한다.
     → 발사체 == 레이저 == 수신체 컬러가 모두 동일해야 완료.

3.0  레이저는 크리스탈을 지나가면 궤도가 변경된다.
3.1  크리스탈은 총 5종.
3.2  크리스탈은 퍼즐 시작 시 지급되며, 개수와 종류는 레벨 데이터에서 지정한다.
3.3  크리스탈을 모두 사용하지 않아도 클리어 가능하다.
3.4  크리스탈은 (배치 후) 방향을 전환할 수 없다.

4.0  퍼즐에 따라 아래 추가 조건이 붙는다.
4.1  [중계체] 반드시 경유해야 하는 오브젝트.
4.1.1   발사체처럼 '색상'을 보유한다. 단, 여러 개의 색상을 지닐 수도 있다.
4.2  [해골 크리스탈] 반드시 피해야 하는 오브젝트.
4.2.1   레이저가 닿으면 수신 오브젝트가 HIDE(비활성) 상태가 되어 완료 불가.

5.0  크리스탈 배치 영역은 5×5 고정.
5.1  주변 1칸 테두리는 플레이어가 이용할 수 없다.
```

**클리어 판정:** 모든 수신체가 (자신과 같은 색의 레이저를 수신하여) On 상태 + 모든 중계체를 경유 + 해골 크리스탈에 레이저가 닿지 않음.

### 4. 오브젝트 정의

#### 4.1 크리스탈 — 플레이어가 조작 가능. 총 5종 11개

| # | 이름 | 개수 | 동작 |
|---|------|------|------|
| 1 | 직각 삼각형 크리스탈 | 4 (상/하/좌/우) | 빗변으로 들어오는 레이저를 **직각으로 반사**. *평면 방향으로 들어오는 레이저는 되돌아간다.* |
| 2 | 팔각 크리스탈 | 1 | 입사 방향과 무관하게 **대각선 4방향으로 분배** |
| 3 | 십자 크리스탈 | 1 | 입사 방향과 무관하게 **직각 4방향으로 분배** |
| 4 | T자 크리스탈 | 4 (ㅓ/ㅗ/ㅜ/ㅏ) | 입사 방향과 무관하게 **2~3방향으로 분배** |
| 5 | 꽃 크리스탈 | 1 | 모든 방향에서 들어오는 레이저를 **흡수** |

#### 4.2 기믹 #1 — 플레이어가 조작 불가. 총 4종 12개

| # | 이름 | 개수 | 동작 |
|---|------|------|------|
| 1 | 발사체 | 3 | 레이저 시작점. 기본 빨강 + 추가 색 2종 |
| 2-1 | 수신체 | 3 | 레이저 목표점. 기본 빨강 + 추가 색 2종 |
| 2-2 | 비활성화 수신체 | 1 | 해골 크리스탈에 레이저가 닿아 수신 불가가 된 상태 |
| 2-3 | 활성화 수신체 | 1 | 올바른 레이저를 수신해 '완료'된 상태 |
| 4 | 중계체 | 3 | 레이저가 **통과해야 하는** 오브젝트. 기본 빨강 + 추가 색 2종 |
| 5 | 해골 크리스탈 | 1 | 레이저가 닿으면 **모든 수신체가 비활성화**되어 클리어 불가 |

#### 4.3 기믹 #2 — 고정 크리스탈

- 퍼즐 시작 시 필드에 **고정 배치된 크리스탈**. 유저가 이동할 수 없다.
- 기본 디자인은 일반 크리스탈과 동일하되, **박혀 있는 등 "조작할 수 없다"는 정보를 디자인으로 전달**해야 한다.

### 5. 레이어(높이) 규칙

- 레이저는 **종류(색)에 따라 각각 고유한 높이(층)** 를 가진다.
- 따라서 **발사체 / 중계체 / 수신체는 3단계 층으로 구분**된다. (색 = 층)
- 그 외 기믹/오브젝트(크리스탈, 해골)는 **모든 레이저와 상호작용**하므로 층 구분이 없다.

### 6. 상태

기믹/오브젝트는 **On / Off / Fault** 3상태를 표현한다.
> 예) 해골에 레이저가 닿아 Fault가 된 수신체, 올바른 색을 수신해 On이 된 중계체/수신체.

### 7. 데이터 테이블

```
[레이저 메인 테이블]
  - 레이저 퀘스트 ID
  - 퍼즐의 난이도
  - 난이도별 제한시간
  - 난이도별 라운드 개수
  - 난이도에 속한 퍼즐 ID

[레이저 필드 테이블]
  - 퍼즐 ID
  - 기본 기믹 배치 좌표값
  - 크리스탈 종류와 개수

[레이저 오브젝트 테이블]
  - 크리스탈 / 기믹 ID
  - 기능 정보
  - 리소스 정보
  - 상태별 연출 정보
```

### 8. 구현 요구사항

1. **레이저 전파는 BFS/DFS 기반 광선 추적**으로 구현한다. 분배 크리스탈(팔각/십자/T자) 때문에 하나의 발사체에서 여러 갈래가 생기므로, 방문한 `(셀, 진입방향, 색)` 조합을 기록해 **무한 루프를 방지**한다.
2. 배치 변경 시마다 전체 광선을 **즉시 재계산**하고 결과를 시각화한다.
3. **솔버**: 남은 크리스탈 조합을 5×5 빈 칸에 배치하는 탐색으로 해가 존재하는지 판정한다. 레벨 생성기는 이 솔버로 검증된 레벨만 출력한다. (규칙 3.3에 따라 **여분 크리스탈을 남기는 해도 정답**으로 인정)
4. 다음 예외를 반드시 테스트한다:
   - 직각 삼각형에 평면 방향으로 입사 → 되돌아감
   - 해골에 레이저 도달 → 전 수신체 Fault, 클리어 불가
   - 중계체를 경유하지 않고 수신체 도달 → 클리어 실패
   - 색이 다른 레이저가 수신체 도달 → 클리어 실패
   - 서로 다른 색 레이저는 층이 다르므로 **교차해도 간섭하지 않음**
5. 플레이 플로우: `퍼즐 시작 → 크리스탈 지급 → 배치/회수 반복 → 실시간 광선 갱신 → 클리어 판정 → 라운드 진행(1~3회)`

## 모바일 조작 규격 (VR 핸드 인터랙션 대체)

> 이 절은 원본 기획서의 VR 그랩 조작을 **모바일 터치 / 드래그 앤 드롭**으로 재구성한 것이다.
> 규칙 절(§1~§7)은 그대로 유지되며, 조작 방식만 이 절로 대체한다.
> 구현: `Laser_DragController.ts`, `Laser_Session.ts`

### M1. 단일 터치 전용

- 동시에 **한 개의 크리스탈만** 드래그할 수 있다.
- 이미 하나를 조작 중일 때 들어오는 추가 터치(멀티터치)는 **완전히 무시**한다.

### M2. 크리스탈 배치 / 회수

- **인벤토리 → 필드:** 인벤토리 슬롯의 크리스탈을 터치해 5×5 배치 영역의 빈 칸으로 끌어다 놓는다.
- **필드 → 다른 칸:** 이미 놓인 크리스탈을 집어 다른 빈 칸으로 옮길 수 있다.
- **필드 → 인벤토리:** 놓인 크리스탈을 집어 **배치 영역 밖에 놓으면** 인벤토리로 회수된다.
- 고정 크리스탈(§4.3)은 집을 수 없다.
- 크리스탈의 방향은 배치 시점에 확정되며 이후 바꿀 수 없다 (§3 3.4). 회전 조작을 제공하지 않는다.

### M3. 스냅 & 미리보기

- 드래그 중 크리스탈의 중심이 위치한 칸이 **스냅 대상**이며, 손을 떼면 그 칸 중앙으로 반올림 스냅된다.
- 드래그 중에는 스냅 대상 칸을 하이라이트한다. 놓을 수 없는 칸(테두리 / 이미 점유된 칸)은
  **다른 색으로 표시**해 미리 알린다.
- 배치 영역 밖에서 손을 떼면 M2의 회수 규칙을 따른다.

### M4. 히트박스 보정

- 터치 지점 중심부에 **가장 가까운 크리스탈 하나만** 선택한다.
- 손가락으로 가려지는 것을 감안해 히트박스를 칸보다 다소 넉넉하게 잡는다 (기본 0.75칸 반경).

### M5. 화면 이탈 처리

- 드래그 유지 상태로 포인터가 화면/퍼즐 영역 밖으로 벗어나도 **드래그 입력은 계속 유지**된다.
- 그 상태에서 손을 떼면 M2의 회수 규칙이 적용된다.

### M6. 실시간 피드백

- 배치·회수·이동이 일어날 때마다 **전체 광선을 즉시 재계산**하고 갱신한다 (§8.2).
- 광선 갱신 결과는 `BEAM_UPDATED` 이벤트 하나로 전달되며, 연출 계층은 이것만 구독하면 된다.
- 해골에 광선이 닿는 순간 `SKULL_HIT` 을 발행해 전 수신체 Fault 연출을 트리거한다.
- 선택 중인 크리스탈에는 아웃라인 또는 LED 활성 이펙트를 적용해 조작 대상을 식별시킨다.

### M7. 리셋

- 놓은 크리스탈을 한 번에 모두 회수하는 **리셋** 조작을 제공한다 (`resetPlacements()`).
