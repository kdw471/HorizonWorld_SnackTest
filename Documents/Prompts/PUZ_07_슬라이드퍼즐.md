## 프롬프트

**너의 역할:** 아래 명세를 그대로 만족하는 "슬라이드 퍼즐"(N-퍼즐)을 구현하라. 규격·연출 수치가 명시되어 있으므로 **그대로 적용**할 것.

### 1. 컨셉

- **모든 이미지 조각을 초기 위치로 되돌려야 한다.**

### 2. 승패 조건

- **클리어:** 제한 시간 안에 모든 조각을 초기 상태로 만들 시 클리어.
- **실패:** 제한 시간 동안 모든 조각을 맞추지 못할 시 실패.

### 3. 기본 시스템

- 해킹 패널 위에 **검은색 이미지 조각들이 생성**된다.
- **랜덤으로 섞인 이미지**가 각 조각들에 표시된다.

### 4. 규격 및 사이즈 (그대로 사용)

| 항목 | 값 |
|---|---|
| 완성된 이미지 | **35cm × 35cm** |
| 3×3 이미지 조각 | **11.5cm × 11.5cm**, 조각 간격 **0.25cm** |
| 4×4 이미지 조각 | **8.6cm × 8.6cm**, 조각 간격 **0.2cm** |
| 이미지 조각 두께 | **4cm** |
| 조각 인터랙션 영역 높이 | **7cm** (가로·세로는 이미지 조각과 동일) |
| 핸드 포인트 변경 콜리전 | **50cm × 20cm × 40cm** |

**이미지 조각 규칙**
- 이미지 조각의 컷팅은 **간격을 무시**한다. (간격을 무시하고 모두 붙였을 때 완성된 이미지로 보여야 한다)
- 이미지 조각은 **언제나 제일 마지막 조각이 비어있다.** (3×3이면 index 8, 4×4면 index 15)

```
3×3 인덱스           4×4 인덱스
0  1  2              0   1   2   3
3  4  5              4   5   6   7
6  7  8(빈칸)         8   9  10  11
                    12  13  14  15(빈칸)
```

### 5. 인터랙션

```
- 사방(상하좌우)에 비어있는 칸이 존재하는 경우에만 인터랙션이 가능하다.
- 손을 조각 근처에 호버했을 때 인터랙션 가능한 경우,
  선택된 조각의 모서리에 Emissive가 켜진다.
      · Emissive Color = #FF5C41
      · 이 때 S_PieceHover_SFX 를 재생한다.
- 조각을 터치하면 비어있는 칸으로 해당 조각이 이동하며, Emissive가 꺼진다.
- 양손으로 동시에 두 조각을 누른 경우,
  "먼저 눌린 조각 하나만" 이동되며 두 번째 인터랙션은 무시된다.
- 퍼즐이 완성 판정되면 즉시 모든 인터랙션이 불가능해진다.
```

### 6. 이동 연출

```
- 조각을 터치하면 0.25초 동안 미끄러져 빈 칸으로 이동된다.
- 조각이 이동하는 동안에는 "모든 칸의 인터랙션이 불가"하다.
- 조각이 이동될 때 S_PieceMove_SFX 를 재생한다.
```

### 7. 조작

- 해킹 패널 위로 손이 올라가면 **손의 형태가 바뀌고 조각을 누를 수 있는 상태로 전환**된다.

### 8. 섞는 로직 (필수 — 이 방식으로만 구현할 것)

```
- 이미지 조각은 "완성 상태에서 역순으로" 섞는다.
- "직전에 이동한 위치로는 이동되지 않는다." (되돌아가는 이동 금지)
- 섞는 횟수(N)는 테이블 변수(iShuffleNum)로 지정한다.
```

> 이 방식은 항상 **풀 수 있는(solvable) 배치**를 보장한다. 무작위 순열 셔플을 사용하면 절반이 풀 수 없는 배치가 되므로 **절대 사용하지 말 것.**

### 9. 완성 연출

- 완성했을 때 **비어있던 조각이 표시되고 간격이 좁혀지며**, **원본 이미지가 1초간 표시되었다가 사라진다.**
- 원본 이미지가 표시될 때 **S_PUZ07_Success_SFX** 를 재생한다.

### 10. 사이드 패널

- **사이드패널 중앙에 원본 이미지를 표시한다.** (플레이어가 목표 이미지를 항상 참조 가능)

### 11. 데이터 테이블

```
[PUZ 메인 테이블]
  - 퍼즐 ID / 퍼즐의 난이도 / 난이도별 제한시간 / 난이도별 라운드 개수 / 난이도에 속한 퍼즐 ID

[NPUZ_07_ObjectData]  (슬라이드 퍼즐 오브젝트 테이블)
  Index          : 인덱스
  sImagePath     : 이미지 경로

[NPUZ_07_FieldData]   (슬라이드 퍼즐 필드 테이블)
  Index            : 인덱스
  sPuzzleObjectID  : 이미지 그룹 ID
  iDivideNum       : 분할 개수 (3 or 4)   → 3×3 또는 4×4로 분할
  iShuffleNum      : 섞는 횟수
```

- 메인 테이블: 기본 룰(라운드, 제한 시간)과 난이도 그룹·소속 퍼즐 관리.
- 필드 테이블: 오브젝트 배치, 분할 개수, 섞는 횟수 관리.

### 12. 구현 요구사항

1. 보드 모델: `int[] board` 길이 `n*n` (`n = iDivideNum`), 값은 원본 타일 인덱스, 빈칸은 `n*n - 1` 위치의 sentinel.
2. 셔플 알고리즘 (반드시 이 형태로):
   ```
   shuffle(N):
       prev = -1
       repeat N times:
           moves = 빈칸에 인접한 조각들의 위치 목록
           moves = moves 중 prev 를 제외        # 직전 이동 되돌리기 금지
           pick = random(moves)
           swap(빈칸, pick)
           prev = 이동 전의 빈칸 위치      # = 조각이 방금 이동해 들어간 자리
   ```
   *(prev 관리는 "직전 이동을 그대로 되돌리는 수"만 배제하도록 구현한다.
   다음 턴에 그 자리(prev)를 다시 고르면 방금 움직인 조각이 제자리로 돌아가므로 배제 대상이다.)*
3. 입력 잠금 상태를 명확히 관리한다: `IDLE → MOVING(0.25s, 전체 입력 잠금) → IDLE`, 완성 시 `LOCKED_CLEARED`.
4. 양손 동시 입력은 **타임스탬프가 빠른 쪽만 채택**하고 나머지는 폐기한다.
5. 이미지 슬라이싱은 **간격(gap)을 무시한 균등 분할**로 수행하고, 렌더링 시에만 gap을 적용한다. 완성 연출에서는 gap을 0으로 tween한다.
6. 클리어 판정은 매 이동 완료 시점에 `board[i] == i for all i` 로 검사한다.
7. 테스트: 셔플 N회 후 항상 solvable / 직전 되돌리기 배제 확인 / 이동 중 입력 차단 / 인접 빈칸 없는 조각 호버 시 Emissive 미점등 / 완성 후 입력 차단 / 3×3·4×4 규격값 정확성.

## 모바일 조작 규격 (§7 VR 조작 대체)

> 이 퍼즐은 드래그가 없고 **탭 하나**로 끝난다. 규격(§4)과 연출 수치(§6, §9)는 그대로 유지한다.
> 구현: `SlidePuzzle_InputController.ts`, `SlidePuzzle_Session.ts`

### M1. 단일 터치 전용

- 원본 §5는 VR 양손 기준으로 "먼저 눌린 조각 하나만 이동되며 두 번째 인터랙션은 무시된다"고 정한다.
  모바일에서도 멀티터치가 가능하므로 같은 규칙을 적용한다.
- 같은 프레임에 여러 조각이 눌리면 **타임스탬프가 빠른 쪽만 채택**하고 나머지는 폐기한다 (§12.4).
- `queueTouch()` 로 모으고 `flushTouches()` 에서 하나만 처리한다.
  단일 터치가 보장되는 경로라면 `pressPiece()` 를 바로 써도 된다.

### M2. 호버 대체

- VR의 손 호버(§7)는 모바일에 없다. 대신 **지금 누를 수 있는 조각을 상시 표시**한다.
- `MOVABLE_POSITIONS_CHANGED` 이벤트로 목록이 바뀔 때만 알리므로,
  해당 조각들의 모서리에 Emissive(`#FF5C41`)를 켜고 `S_PieceHover_SFX` 를 재생하면 된다.
- **인접한 빈 칸이 없는 조각에는 Emissive를 켜지 않는다** (§5).

### M3. 입력 잠금

- 조각이 미끄러지는 **0.25초 동안 모든 칸의 입력이 막힌다** (§6).
- 완성 판정이 나면 **즉시 모든 입력이 막힌다** (§5). 상태는 `LOCKED_CLEARED` 로 고정된다.
- 거절 사유(`MOVE_IN_PROGRESS` / `NOT_ADJACENT_TO_BLANK` / `ALREADY_CLEARED`)를 함께 전달하므로
  필요하면 UI 피드백에 쓸 수 있다.

### M4. 손가락 가림 대응

- 손가락이 조각을 가리므로, 누른 조각은 살짝 띄우거나 이동 궤적을 강조해 보여 준다.
- 사이드 패널의 원본 이미지(§10)는 `getReferenceImagePath()` 로 얻는다.
  모바일에서는 화면 한쪽에 상시 표시해 목표를 항상 참조할 수 있게 한다.

### M5. 완성 연출

- `PUZZLE_COMPLETED` 이벤트가 원본 이미지 경로를 함께 전달한다.
- 연출은 §9를 따른다. 빈 조각을 표시하고 간격을 0으로 tween한 뒤,
  원본 이미지를 1초간 보여 주고 `S_PUZ07_Success_SFX` 를 재생한다.
