# PUZ_00 · 공통 퍼즐 모드 기반 프롬프트

> 출처: `Docs/[HID] PUZ_01레이저 퍼즐_시스템 기획서_Ver.1.2.0.pdf` (퍼즐 모드 공통 규격) 및 PUZ_01~08 전 문서의 공통 항목
> 용도: PUZ_01~08 개별 프롬프트와 **함께** 제공하는 공통 컨텍스트. 단독 게임 생성용이 아님.

---

## 역할

너는 VR/3D 퍼즐 게임의 시스템 프로그래머다. 아래 공통 규격을 프레임워크로 삼고, 개별 퍼즐 프롬프트(PUZ_01~08)에 정의된 규칙을 그 위에 얹어 구현한다.

## 1. 모드 구조

- `PUZ 모드`(퍼즐 모드)는 `ADV 모드`와 동일하게 **독립된 레벨**이다.
- 플레이어는 **이동 불가**. 카메라는 이벤트에 따라 자동으로 특정 지점으로 이동한다.
- 견습 에이전트(NPC)는 플레이어가 조작하지 않으며 **자동 이동**한다. 자동 이동으로 이벤트 트리거를 발동시키면 퍼즐 퀘스트가 시작된다.
- 하나의 레벨에는 **퍼즐 퀘스트 3~4개**가 배치된다.
- 모든 퍼즐 퀘스트를 완료하면 레벨이 종료된다.
- ADV 모드와 달리 해당 레벨에 **머무르기 기능은 제공하지 않는다**. 퀘스트 종료 시 다음 레벨 또는 로비B로의 이동만 가능하다.

## 2. 기본 레이아웃 (공통 UI)

퍼즐 이벤트가 발동하면 아래 **패널 2개가 자동으로 팝업**된다. 두 패널 모두 플레이어가 **집어서 위치를 자유롭게 옮길 수 있다**.

### 2.1 해킹 패널 (실제 퍼즐 보드)

| # | 요소 | 규격 |
|---|------|------|
| 1 | 해킹 패널 (3D) | 닌텐도 스위치 같은 휴대용 게임기 형태(또는 게임기 형태의 로봇). **모든 퍼즐 퀘스트에 공용** |
| 2 | 해킹 패널 화면 (2D) | 퍼즐 퀘스트 모드별 2D 판넬 이미지 |
| 3 | 라운드 슬롯 | 패널 하단 옆면. 퍼즐 진행도(STEP) 표시. 퍼즐 퀘스트별 **1~3회 클리어** 필요 |
| 4 | 퍼즐 에셋 | 2D 판넬 위에 배치되는 퍼즐용 3D 오브젝트 / 이펙트 / 효과음 |

- 구성: **3D 패널 + 2D 플랫 UI로 보드를 표현**하고, 그 위로 3D 에셋을 배치한다. 플레이어는 3D 에셋과 상호작용하여 퍼즐을 푼다.

### 2.2 CCTV 패널 (연출 전용)

- 견습 에이전트의 모습을 **확대해서 보여주는 화면**. 비행 형태의 로봇.
- 별도 제작 영상 없음. 실제 견습 요원 모습을 실시간 확대.
- 퍼즐 모드는 이동이 불가능하므로, CCTV로 연출 상황을 잘 볼 수 있게 하는 역할.

## 3. 공통 진행 규칙

- 모든 퍼즐은 **제한 시간**을 가진다. 제한 시간 내 클리어 조건 미달성 시 실패.
- 제한 시간·라운드 수는 **난이도별**로 테이블에서 관리한다.
- 한 퍼즐 퀘스트는 **1~3 라운드**로 구성되며, 라운드 슬롯에 진행도를 표시한다.

## 4. 공통 조작 규격 (VR 핸드 인터랙션)

- 해킹 패널 위로 손이 올라가면 **손의 형태가 바뀌고** 조작 가능 상태로 전환된다.
- 핸드 포인트 변경 콜리전 영역: **50cm × 20cm × 40cm** (PUZ_07/08 기준)
- 그랩 가능 오브젝트에는 **아웃라인 또는 메쉬 변환 이펙트(LED 활성화 등)** 로 인디케이터를 표시한다.
- 손에 가까운 오브젝트, 그리고 인디케이터 생성 영역 **중심부에 더 가까운 오브젝트를 우선**으로 표식을 생성한다.
- 상호작용 시 **진동(햅틱)** 을 발생시킨다.
- 양손 동시 사용 정책은 퍼즐마다 다르다 (PUZ_02·03은 허용, PUZ_05·07·08은 금지). 개별 프롬프트를 따른다.

## 5. 공통 오브젝트 상태

기믹과 오브젝트는 기본 **On / Off** 상태와, 특수한 경우 **Fault** 상태를 가진다.
> 예) 해골 크리스탈에 레이저가 닿아 Fault 상태가 되는 수신체 / 올바른 색상의 레이저를 수신해 On 상태가 되는 중계체

## 6. 공통 데이터 테이블 구조

모든 퍼즐은 **3계층 테이블**을 따른다.

```
[PUZ 메인 테이블]  →  기본 룰(라운드, 제한 시간), 난이도 그룹과 소속 퍼즐 관리
  - {퍼즐명} 퀘스트 ID
  - 퍼즐의 난이도
  - 난이도별 제한시간
  - 난이도별 라운드 개수
  - 난이도에 속한 퍼즐 ID

[필드 테이블]      →  개별 퍼즐의 배치 정보(오브젝트 좌표, 종류, 개수) 관리
  - 퍼즐 ID
  - 오브젝트 배치 좌표값
  - (퍼즐별 고유 파라미터)

[오브젝트 테이블]  →  기믹/오브젝트의 기능, 리소스, 연출 관리
  - 오브젝트 ID
  - 기능 정보
  - 리소스 정보 (스태틱 메쉬 경로 등)
  - 상태별 연출 정보
```

## 7. 구현 시 공통 요구사항

1. **로직과 표현을 분리**한다. 퍼즐 규칙은 순수 상태 머신으로 구현하고, VR 인터랙션/연출은 어댑터 계층에서 처리한다. (2D 프로토타입으로도 동일 로직이 검증 가능해야 한다.)
2. **모든 수치는 하드코딩하지 않고** 위 테이블 스키마에 대응하는 데이터 구조에서 읽는다.
3. **레벨 생성기는 항상 해결 가능한(solvable) 배치만 출력**해야 한다. 생성 후 솔버로 검증하고, 실패 시 재생성한다.
4. 실패/성공 판정, 남은 시간, 라운드 진행도를 외부에서 조회 가능한 API로 노출한다.
5. 각 퍼즐의 **예외 처리 규칙**(개별 프롬프트에 명시)은 반드시 테스트 케이스로 작성한다.

## 8. 공통 모바일 조작 규격 (§4 VR 핸드 인터랙션 대체)

> 원본 §4는 VR 핸드 트래킹 기준이다. 이 프로젝트는 **모바일**로 만들므로,
> 규칙 절(§1~§3, §5~§7)은 그대로 두고 **조작 절만 이 절로 대체**한다.
> 퍼즐별 세부 규격은 각 `PUZ_0N_*.md` 하단의 "모바일 조작 규격" 절을 따른다.

### 8.1 단일 터치 전용 (모든 퍼즐 공통)

- 동시에 **하나의 오브젝트만** 조작한다. 조작 중 들어오는 추가 터치는 **완전히 무시**한다.
- 원본 §4의 "양손 동시 사용 정책은 퍼즐마다 다르다"는 조항은 모바일에서 **적용하지 않는다.**
  PUZ_02·03이 VR에서 양손을 허용하더라도 모바일에서는 단일 터치로 통일한다.
- 멀티터치가 물리적으로 가능한 환경이므로, 같은 프레임에 여러 입력이 들어오면
  **먼저 들어온 하나만 채택**하고 나머지는 폐기한다.

### 8.2 선택 (호버 대체)

- VR의 손 호버는 모바일에 없다. 대신 다음으로 대체한다.
  - **상시 표시:** 지금 조작할 수 있는 오브젝트를 항상 하이라이트한다.
  - **누름 표시:** 누르는 순간 눌림 상태를 표시한다.
- 터치 지점 중심부에 **가장 가까운 오브젝트 하나만** 선택한다.
- 손가락이 작은 대상을 덮으므로 **히트박스를 칸보다 넉넉하게** 잡는다 (기본 0.75칸 반경).
- 조작할 수 없는 대상에는 하이라이트를 켜지 않는다.

### 8.3 드래그

- 드래그 중에는 허용된 축 값만 유지한 채 이동한다.
- 손을 떼면 오브젝트의 중심이 위치한 칸으로 **반올림 스냅**한다.
- 놓을 수 있는 자리와 없는 자리를 **다른 색으로 구분**해 미리 보여 준다.

### 8.4 화면 이탈

- 드래그 유지 상태로 포인터가 화면/퍼즐 영역 밖으로 나가도 **드래그 입력은 계속 유지**된다.
- 오브젝트는 이동 가능한 **최외곽 경계에 고정**된다.
- 그 상태에서 손을 떼면 퍼즐별 규칙(스냅 / 회수 / 리스폰)을 따른다.

### 8.5 손가락 가림 대응

- 손가락이 조작 대상을 가리는 것이 모바일의 근본 제약이다. 퍼즐마다 다음 중 하나로 대응한다.
  - 활성화된 오브젝트를 **손가락 위로 크게 띄워** 보여 준다 (카드 맞추기)
  - 조작 버튼을 **대상 바깥에** 둔다 (색 채우기의 터치 버튼)
  - 목표 이미지를 **별도 패널에 상시 표시**한다 (슬라이드 퍼즐)

### 8.6 진동(햅틱)

- 원본 §4의 햅틱 규정은 그대로 유지한다. 선택·이동·완료 시점에 짧은 진동을 준다.
- 모바일 기기의 햅틱 지원 여부를 확인하고, 없으면 무시한다.
