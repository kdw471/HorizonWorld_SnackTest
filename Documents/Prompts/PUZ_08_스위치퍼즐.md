## 프롬프트

**너의 역할:** 아래 명세를 그대로 만족하는 "스위치 퍼즐"(Lights Out 변형)을 구현하라. 클래식 Lights Out과 달리 **토글 패턴(스위치 영역)이 라운드마다 데이터로 주어지는 임의의 3×3 마스크**라는 점이 핵심이다.

### 1. 컨셉

- **모든 키를 눌러 녹색의 키로 만들어야 한다.**

### 2. 승패 조건

- **클리어:** 제한 시간 안에 **모든 키를 눌린 상태**로 만들 시 클리어.
- **실패:** 제한 시간 동안 모든 키를 누르지 못할 시 실패.

### 3. 기본 시스템 & 규격

- 해킹 패널 위에 오브젝트가 생성된다: **키 판**, **키 캡**.
- 오브젝트(키 캡)는 **녹색과 빨간색**으로 구분된다.

| 항목 | 값 |
|---|---|
| 단일 키 판 (1×1) | **7cm × 7cm** |
| 완성된 키 판 (5×5) | **35cm × 35cm** |
| 키 캡 (1×1) | **6cm × 6cm** *(조작 콜리전 표기는 7cm × 7cm)* |
| 핸드 포인트 변경 콜리전 | **50cm × 20cm × 40cm** |

### 4. 키 판 (필드)

- 모든 라운드는 **5×5 키 판**에서 플레이한다. 좌표는 **A1~E5** (세로 A~E / 가로 1~5).
- **키 판의 사용 여부는 `FREE`로 표기**한다. **`FREE` 좌표에는 아무런 오브젝트가 생성되지 않는다.**

```
5×5 전체 사용            키 판 3×3만 사용 시
A1 A2 A3 A4 A5          FREE FREE FREE FREE FREE
B1 B2 B3 B4 B5          FREE  B2   B3   B4  FREE
C1 C2 C3 C4 C5          FREE  C2   C3   C4  FREE
D1 D2 D3 D4 D5          FREE  D2   D3   D4  FREE
E1 E2 E3 E4 E5          FREE FREE FREE FREE FREE
```

**생성 연출**
- 키 판 생성 연출은 **러시아워 퍼즐과 동일**.
- 1×1 키 판은 각각 **랜덤하게 확장되며 생성**된다. 모든 타일 생성 소요 시간 **1초**.
- 모든 **녹색 키 캡이 생성된 후**, 키 캡이 **필드데이터에 따라 동시에 눌리며 녹색으로 변한다. (0.2초)**

### 5. 키 캡 (오브젝트)

- 키 캡은 **두 가지 상태**가 존재한다: **눌린 상태 / 안 눌린 상태**.
- 데이터 테이블 표기:
  ```
  눌린 상태    = 1
  안 눌린 상태 = 0
  ```
  *(문서 도식의 라벨 표기 `(안 눌린 상태=1) / (눌린 상태=0)`과 텍스트 정의가 상이하므로, **구현에서는 `1 = 눌림(녹색/목표 상태)`, `0 = 안 눌림(빨강)` 으로 통일**하고 데이터 임포터에서 한 번만 매핑한다.)*
- 키 캡의 **눌림 상태에 따라 윗면의 모양과 색상이 변한다.**
- 초기 배치(`NPUZ_08_FieldData`)는 5×5 각 칸의 0/1 배열로 주어진다.

### 6. 스위치 영역 (핵심 메커닉)

```
- 스위치 영역 = 유저가 상호작용 시 "동시에 영향을 받는 영역"
- 스위치 영역은 3×3을 기준으로 하며, "중앙은 항상 포함"한다.
  (영역의 중심에 불이 들어오지 않는 경우는 없다.)
- 퍼즐의 라운드마다 각각 다른 영역을 제공한다.
- 테이블(sSwitchArray)에 따라 녹색/빨간색으로 조합되어 해킹패널 우측에 표시되어야 한다.
- 1×1 키 캡이 눌릴 시, 3×3 스위치 영역에서 동시에 상태가 변하는 키 캡이 존재한다.
- 상태가 변하는 키 캡의 영역은 좌측 패널 스위치 영역에 맞춰 변한다.
- 영향을 받는 키 캡의 상태가 0→1, 1→0 으로 반전(toggle)된다.
```

**즉:** 플레이어가 `(r, c)`를 누르면, 3×3 마스크 `M[dr][dc]`(dr, dc ∈ {-1, 0, +1}, 중앙 `M[0][0] = 1` 고정)에서 값이 1인 오프셋에 해당하는 모든 키 캡의 상태가 **XOR 반전**된다.

### 7. 조작 규격 (VR)

```
- 해킹 패널 위로 손이 올라가면 손의 형태가 바뀌고 키 캡을 누를 수 있는 상태로 전환된다.
- 키 캡은 "버튼이 완전히 눌렸을 때" 색상이 변한다.  (빨간색 → 녹색 / 녹색 → 빨간색)
- 끝까지 누르지 않았다면 키 캡은 변하지 않는다.
- [예외] 손이 옆으로 들어갈 시, 콜리전의 중앙에 가까워질수록 키 캡이 눌린다.
- [예외] 양손을 사용한 동시 터치는 할 수 없다. 콜리전에 "먼저 들어간 손만" 인식된다.
```

**조작 연출 타이밍**
```
0.0초 : 중앙의 키 캡을 누름
0.2초 : 스위치 영역의 (영향받는) 키 캡 연출 재생
0.4초 : 모든 연출 종료
```

### 8. 데이터 테이블

```
[PUZ 메인 테이블]
  - 스위치 퍼즐 ID
  - 퍼즐의 난이도
  - 난이도별 제한시간
  - 난이도별 라운드 개수
  - 난이도에 속한 퍼즐 ID

[NPUZ_08_FieldData]  (스위치 퍼즐 필드 테이블)
  - 퍼즐 ID
  - 스위치 영역 ID
  - 배치된 키 캡 좌표      (5×5의 0/1 배열, 미사용 칸은 FREE)

[NPUZ_08_ObjectData]  (스위치 퍼즐 오브젝트 테이블)
  - 스위치 영역 ID 좌표    (sSwitchArray: 3×3 마스크)
```

### 9. 구현 요구사항

1. 상태 모델:
   ```
   grid[5][5] : PRESSED(1) | UNPRESSED(0) | FREE(없음)
   mask[3][3] : 0/1,  mask[1][1] == 1 고정 (중앙 항상 포함)
   ```
2. 입력 처리:
   ```
   onPress(r, c):
       if grid[r][c] == FREE: return
       for dr in -1..1, dc in -1..1:
           if mask[dr+1][dc+1] == 1:
               (nr, nc) = (r+dr, c+dc)
               if inBounds(nr,nc) and grid[nr][nc] != FREE:
                   grid[nr][nc] ^= 1            # 토글
       playSequence(0.0s 중앙 → 0.2s 영역 → 0.4s 종료)
   ```
   - 판 밖으로 벗어나는 오프셋과 `FREE` 칸은 **영향 없음**으로 처리한다. (랩어라운드 금지)
3. 클리어 판정: **`FREE`가 아닌 모든 칸이 1(눌림)** 이면 클리어.
4. **레벨 생성기 (반드시 이 방식)**: 목표 상태(모두 1)에서 시작해, 임의의 유효 칸을 K번 눌러 역방향으로 흐트러뜨린다. Lights Out 계열은 토글이 자기역원(involution)이므로 **이렇게 만든 배치는 항상 K수 이내로 풀 수 있다.** 무작위 0/1 배열은 마스크·판 형태에 따라 **해가 없을 수 있으므로 사용 금지.**
   - 난이도는 `K`(셔플 누름 횟수), 사용 칸 수(`FREE` 비율), 마스크 복잡도로 조절한다.
   - 선택적으로 GF(2) 선형대수 솔버(가우스 소거)를 구현해 임의 배치의 해 존재 여부와 최소 해를 검증한다.
5. 스위치 영역 마스크는 **해킹 패널 우측에 3×3 미니 UI**로 상시 표시한다 (녹색 = 영향 있음, 빨간색 = 영향 없음).
6. 입력 배타성: 콜리전에 먼저 진입한 손의 ID를 잠그고, 해제될 때까지 다른 손 입력을 무시한다. 부분 누름(완전히 눌리지 않음)은 상태를 변경하지 않는다 — **누름 깊이 임계값 도달 시점에만 토글**을 발생시킨다.
7. 테스트: 경계 칸에서 마스크 클리핑 / FREE 칸 무영향 / 중앙 항상 포함 검증 / K회 역셔플 배치의 해 존재 / 양손 동시 입력 차단 / 부분 누름 미반응 / 0.2초 딜레이 연출 순서.

## 모바일 조작 규격 (§7 VR 조작 대체)

> 이 퍼즐은 드래그가 없고 **탭 하나**로 끝난다. 규격(§3)과 연출 수치(§4, §7)는 그대로 유지한다.
> 구현: `Switch_InputController.ts`, `Switch_Session.ts`

### M1. 단일 터치 전용

- 원본 §7은 VR 기준으로 "콜리전에 먼저 들어간 손만 인식된다"고 정한다.
  모바일에서도 같은 규칙을 적용한다 — **터치 하나가 진행 중이면 추가 터치 다운은 완전히 무시**한다.
- 같은 프레임에 여러 키 캡이 눌리면 **타임스탬프가 빠른 쪽만 채택**하고 나머지는 폐기한다.
- `queueTouch()` 로 모으고 `flushTouches()` 에서 하나만 처리한다.
  단일 터치가 보장되는 경로라면 `pressKey()` 를 바로 써도 된다.

### M2. 부분 누름의 모바일 대체

- 원본 §7의 "완전히 눌렸을 때만 토글 / 끝까지 누르지 않으면 변하지 않는다"는
  누름 깊이가 없는 모바일에서 다음으로 대체한다.
  - **다운했던 키 캡 위에서 손을 떼는 순간에만** 눌림을 확정한다 (`touchDown` → `touchUp`).
  - 손가락을 키 캡 밖으로 끌고 나가서 떼면 **취소**된다 (`RELEASED_OUTSIDE`). 상태는 변하지 않는다.
- 히트박스는 키 캡(6cm)보다 넉넉한 조작 콜리전(7cm)을 그대로 쓴다 (§3, PUZ_00 §8.2).

### M3. 입력 잠금

- 누름 연출이 재생되는 **0.4초 동안 모든 키 캡의 입력이 막힌다** (§7).
- 완성 판정이 나면 **즉시 모든 입력이 막힌다**. 상태는 `LOCKED_CLEARED` 로 고정된다.
- 거절 사유(`SEQUENCE_IN_PROGRESS` / `FREE_CELL` / `ALREADY_CLEARED`)를 함께 전달하므로
  필요하면 UI 피드백에 쓸 수 있다.

### M4. 스위치 영역 상시 표시

- §6의 스위치 영역 3×3 미니 UI는 모바일에서 더 중요하다 — 손가락이 판을 가리는 동안에도
  어떤 영역이 반전될지 미리 알 수 있어야 한다.
- `MASK_CHANGED` 이벤트가 라운드 시작마다 마스크를 전달한다.
  해킹 패널 우측에 녹색(영향 있음)/빨간색(영향 없음)으로 상시 표시한다 (§9.5).

### M5. 연출 이벤트 순서

- `KEY_PRESSED`(0.0초, 중앙 눌림) → `AREA_TOGGLED`(0.2초, 영역 반전 연출) →
  `PRESS_SEQUENCE_FINISHED`(0.4초, 종료 + 클리어 판정) 순으로 발행된다 (§7).
- 손가락이 중앙 키 캡을 가리므로, 영역 연출(0.2초)은 손가락 밖의 칸들에서 뚜렷하게 보이도록 한다.
