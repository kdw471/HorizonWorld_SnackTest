## 프롬프트

**너의 역할:** 아래 명세를 그대로 만족하는 "색 채우기" 타이밍 액션 퍼즐(원형 다이얼 + 회전 바늘)을 구현하라. 이 퍼즐만은 배치 퍼즐이 아닌 **반응속도/타이밍 퍼즐**이다.

### 1. 컨셉 & 플레이 방법

- **컨셉:** 제한시간 내에 **타이밍에 맞춰 오염된 영역을 정화**시켜야 한다.
- **플레이:** 제한 시간 안에, **돌아가는 다이얼(바늘)이 오염된 영역에 도달했을 때 터치**하면 그 오염 영역을 정화할 수 있다. **모든 칸을 정화시키면 클리어.**

### 2. 승패 조건

- **클리어:** 제한시간 내에 **모든 오염 영역을 정화된 영역의 색상으로 변경** 시 클리어.
- **실패:** 제한시간 내에 모든 오염 영역을 정화하지 못하면 실패.

### 3. 시스템 구성

- 레벨에는 **제한시간 / 정화영역 / 오염영역 / 터치 버튼**이 존재한다.
- **제한시간과 오염 영역은 난이도별로 달라진다.**
- 다이얼은 **18칸**으로 나누어지며, 최소 단위인 한 칸은 **20°** 의 영역을 가진다. (18 × 20° = 360°)
- 유저가 정화해야 하는 부분(오염 영역)은 **붉은 색상**으로 표시한다.

### 4. 다이얼 영역 — 난이도 테이블

| 난이도 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| **활성화 영역의 칸 수** | 12 | 10 | 8 | 8 | 6 | 6 |
| **오염 영역의 칸 수** | 12-13 | 10 | 12-14 | 5/5 | 3/3/3 | 2/2/2/2 |

> 표기 해석: `5/5` 처럼 슬래시로 나뉜 값은 **분리된 오염 덩어리(그룹) 각각의 칸 수**를 의미한다.
> (난이도 3의 `12-14`, 난이도 1의 `12-13`은 범위값이며 난이도 4는 `6/4` 배리에이션도 존재)

- 다이얼에는 **활성화 영역 / 비활성화 영역**이 있고, **활성화되는 칸은 연속될 수도 있고 따로 떨어져 있을 수도 있다.**

### 5. 정화 규칙

```
- 연속된 오염 영역은 1회 터치로 "연속된 모든 영역"이 한 번에 정화된다.
- 이미 정화된 영역을 터치해도 "패널티 없음".
- 정화 머티리얼: MI_NPUZ_04_Safescale
    ㄴ Set – MainColor (0 → 1)
```

### 6. 다이얼 바늘

```
- 다이얼 바늘은 퍼즐 시작 시 "시계방향"으로 회전을 시작한다.
- 다이얼 바늘은 난이도별로 다른 회전 속도를 가진다.
- 유저가 다이얼 바늘을 터치하면 바늘은 "반대 방향"으로 회전한다.
    → 회전 방향 변경 시 "딜레이"가 존재한다.
- 터치 시 바늘의 위치는 활성화 영역 / 비활성화 영역과 상관없다.
    (즉, 어디서 터치하든 방향은 항상 반전된다)
- 오염 영역에 도달했을 때 터치하면 → 정화 + 동시에 회전 방향이 변한다.
```

**즉, 터치 = "방향 반전"이 항상 발생하고, 바늘이 오염 칸 위에 있을 때만 추가로 "정화"가 발생한다.** 이 이중 효과가 이 퍼즐의 핵심 난이도 요소다.

### 7. 데이터 테이블


### 8. 구현 요구사항

1. 다이얼 상태 모델:
   ```
   slots: Slot[18]           // 각 20°
   Slot = { active: bool, state: CLEAN | CONTAMINATED }
   needle = { angleDeg: float, dir: +1 | -1, speedDegPerSec: float }
   reverseDelaySec: float    // 방향 전환 딜레이
   ```
2. 매 프레임 `angle += dir * speed * dt` (mod 360). 현재 칸 인덱스 = `floor(angle / 20)`.
3. 터치 입력 처리:
   ```
   onTouch():
       idx = currentSlotIndex()
       if slots[idx].state == CONTAMINATED:
           # 연속된 오염 덩어리 전체를 정화 (원형 배열이므로 wrap-around 고려)
           for s in contiguousContaminatedRun(idx): s.state = CLEAN
       # 정화 여부와 무관하게 항상 방향 반전 (딜레이 적용)
       scheduleReverse(reverseDelaySec)
   ```
   - `reverseDelay` 동안은 방향 전환 연출/입력 잠금 처리 여부를 파라미터로 둔다.
4. 클리어 판정: 모든 `active` 슬롯이 `CLEAN` 이면 즉시 클리어.
5. **레벨 생성기**: 난이도 표의 `활성화 칸 수`와 `오염 그룹 구성`을 입력받아, 18칸 원형 배열 위에 지정된 크기의 오염 덩어리들을 서로 인접하지 않게(그룹이 합쳐지지 않게) 배치한다. 활성화 영역은 연속/분산 모두 허용한다.
6. 밸런싱 검증: `(총 오염 그룹 수) × (평균 왕복 이동 시간)` 이 제한 시간 내에 들어오는지 시뮬레이션한다. 방향 반전 딜레이가 크면 클리어 불가능한 레벨이 생성될 수 있으므로 자동 플레이 봇으로 검증한다.
7. 테스트: 정화된 칸 터치 시 무패널티 확인 / 연속 오염 1회 터치 전체 정화 / 원형 wrap-around 구간(17↔0)의 연속 판정 / 비활성 영역에서의 터치도 방향 반전 발생 / 방향 전환 딜레이 중 재터치 처리.

## 모바일 조작 규격

> 이 퍼즐은 배치가 아니라 타이밍 퍼즐이라 드래그가 없다. 조작은 **탭 하나**뿐이라
> VR/모바일 차이가 크지 않지만, 아래 항목을 모바일 기준으로 확정한다.
> 구현: `ColorFill_InputController.ts`, `ColorFill_Session.ts`

### M1. 단일 터치 전용

- 같은 프레임에 여러 손가락이 닿아도 **한 번만** 처리한다.
- 최소 터치 간격(기본 0.05초)보다 빨리 들어온 입력은 무시한다.
  §8.3의 방향 전환 딜레이 중 입력 잠금과는 별개의 안전장치다.

### M2. 터치 판정 위치

- 다이얼 어디를 눌러도 동일하게 처리된다. **터치 지점은 판정에 관여하지 않는다.**
  판정 기준은 오직 **그 순간 바늘이 가리키는 칸**이다 (§6).
- 따라서 화면 어디에나 큰 터치 버튼을 두어도 되고, 다이얼 전체를 버튼으로 삼아도 된다.
  손가락이 다이얼을 가리는 문제를 피하려면 다이얼 바깥에 버튼을 두는 편이 낫다.

### M3. 피드백

- 정화 시 `SLOTS_PURIFIED` 이벤트로 정화된 칸 목록을 전달한다.
  연출은 §5의 `MI_NPUZ_04_Safescale` 머티리얼의 `MainColor` 를 0 → 1 로 올린다.
- 방향 반전은 예약(`REVERSE_SCHEDULED`)과 실제 적용(`DIRECTION_CHANGED`)을 나누어 알린다.
  딜레이 동안 "곧 방향이 바뀐다"는 예고 연출을 넣을 수 있다.
- 입력이 잠긴 동안에는 터치 버튼을 잠금 상태로 표시한다.

### M4. 제한 시간

- 사양에 수치가 없어 자동 플레이 봇(§8.6)으로 실측해 정했다.
- 이 퍼즐은 **한 번의 터치가 오염 덩어리를 통째로 정화**하므로 필요한 터치가 덩어리 수만큼뿐이고,
  다이얼 한 바퀴가 2~4초라 놓쳐도 곧 다시 기회가 온다. 봇 실측은 D1 0.8초 ~ D6 4.1초였다.
- 사람은 좁은 타이밍 창을 여러 번 놓치므로 실측의 5~7배인 **15~30초**를 제한 시간으로 잡았다.
