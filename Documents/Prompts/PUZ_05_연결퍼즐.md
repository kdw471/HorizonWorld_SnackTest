## 프롬프트

**너의 역할:** 아래 명세를 그대로 만족하는 "연결 퍼즐"(Flow / Numberlink 계열)을 구현하라. 단, 일반 Flow와 달리 **경로가 지나갈 수 있는 칸(서브 오브젝트)이 명시적으로 배치**되며 **모든 서브 오브젝트를 전부 사용**해야 한다.

### 1. 컨셉 & 목표

- **컨셉:** 모든 전구에 불이 들어오게 만들어야 하며, **같은 색상의 전구끼리 연결**되어야 한다.
- **목표:** 다양한 색상의 목표 오브젝트(**전구**)에 전력을 공급해 에이전트Q를 돕는다.

### 2. 승패 조건

- **클리어:** 제한시간 동안 필드 위에 존재하는 **모든 전구의 불을 밝히면** 클리어.
- **실패:** 제한시간 동안 모든 전구의 불을 밝히지 못하면 실패.

### 3. 필드 & 오브젝트 규격

- **1×1 타일**: 하나의 오브젝트가 올라갈 수 있는 단일 타일.
- **7×7 필드**: 단일 타일이 7×7 배열로 배치 가능하며 **최대 배치 타일 개수는 49개**.
- 오브젝트 사이즈: **1×1**, **기둥 형태**.
- 오브젝트는 **반드시 생성된 단일 타일 위에만** 생성되어야 한다.
- **타일 배치는 레벨에 따라 다르며, 타일의 위치와 생성 여부는 0/1 비트맵으로 표기**한다.

```
레벨 배치 예시 (1 = 타일 있음, 0 = 없음)

1111111    0011100    0000111    1111111
1011101    0011100    0000111    1111111
1111111    1111111    1111111    1100011
1111111    1111111    1111100    1100011
1111111    1111111    1111100    1100011
1011101    0011100    1111100    1111111
1111111    0011100    1111100    1111111
```

### 4. 오브젝트 정의

| 구분 | 설명 |
|------|------|
| **메인 오브젝트 (M)** | **색상을 가진** 전구. **출발 지점 / 도착 지점** 2가지 상태로 존재. 같은 색이 2개 이상 짝을 이뤄 배치된다 |
| **서브 오브젝트 (S)** | **색상이 없는** 회색 전구. 연결된 메인 오브젝트의 색상을 부여받는다 |

**서브 오브젝트 제약**
```
- 연결된 메인 오브젝트의 색상을 "하나만" 받을 수 있다.
- 색상을 부여받은 서브 오브젝트는 "다른 색상을 부여받을 수 없다".
- 서브 오브젝트는 "단 하나의 입력과 하나의 출력"만 할 수 있다.
- 2개 이상의 입력/출력을 할 수 없다.  → 즉, 경로는 분기·교차할 수 없다.
```

### 5. 핵심 플레이 규칙

```
- 색상이 지정된 메인 오브젝트(전구)를 터치(그랩) 후, 회색 서브 오브젝트로 끌어다 놓으면 해당 색의 불이 들어온다.
- 같은 색상의 전구(오브젝트)는 모두 연결되어야 한다.
- 연결할 수 있는 범위는 "인접한 상/하/좌/우". 대각선 연결 불가.
- 이미 다른 색상이 활성화된 영역은 지나갈 수 없다.
- 시작과 끝은 "같은 색상의 메인 오브젝트"여야 한다.
- 같은 색상은 모두 "하나의 선"으로 연결되어 있어야 한다.
- 모든 서브 오브젝트가 활성화되어야 한다. (필드에 제공된 오브젝트를 전부 사용해야 함)
```

> **클리어 판정 = (모든 색이 각각 하나의 라인으로 M(출발)~M(도착) 연결) AND (모든 서브 오브젝트가 색을 부여받아 활성화)**
> 문서에 "클리어 가능 예시 / 클리어 불가능 예시"가 명시되어 있으며, 남은 서브 오브젝트가 하나라도 있으면 **클리어 불가**다.

### 6. 상호작용 스펙 (VR)

**그랩 / 그리기**
- 메인 오브젝트와 상호작용(그랩) 후 **서브 오브젝트를 지나가면서 불을 밝힌다.**
- **진동(햅틱):** 그랩 시 / 서브 오브젝트를 지나갈 때.
- 상호작용이 가능한 오브젝트는 **빛을 내는 상태를 유지**한다.
- 상호작용이 가능한 오브젝트는 **색상별로 단 하나만** 부여된다. (게임 시작 시 메인 오브젝트 출발점에 생성)
- 이동할 오브젝트 선택 시 **하단의 받침대에서 이동 가능한 구역이 표시**된다.

**그랩 해제**
- 중간에 그랩을 놓으면 **마지막 위치로 되돌아간다.**
- 가장 마지막에 연결된 오브젝트와 유저 손의 연결이 끊어진다.
- **필드의 오브젝트는 연결이 된 상태로 유지된다.** (그린 경로는 남는다)

**지우기 (Undo)**
- 채워져 있는 서브 오브젝트를 지우는 방법:
- **마지막 활성화 부분에서 그랩을 한 뒤, 그렸던 길을 그대로 뒤로 되돌아가면** 서브 오브젝트가 비활성화되며 꺼진다.

**양손**
- **양손을 동시에 사용할 수 없다.** 오른손 사용 중에는 왼손을 사용할 수 없다.

### 7. 게임 시작/종료 연출

- 게임 시작 시 필드와 메인/서브 오브젝트가 생성된다. **생성 연출 방식은 PUZ_01 레이저 퍼즐과 동일.**
- **성공:** 필드 위의 모든 오브젝트가 연결되면 **제한시간이 멈춤과 동시에 필드의 오브젝트가 사라진다.**
- **실패:** 제한 시간 종료와 동시에 **유저는 아무런 상호작용을 할 수 없게 되고**, 모든 오브젝트의 불이 **서서히 꺼지며(2초)** 게임 종료. (타이머 `00:00.00` 표시)

### 8. 데이터 테이블

```
[PUZ 메인 테이블]
  - 전선연결 퀘스트 ID
  - 퍼즐의 난이도
  - 난이도별 제한시간
  - 난이도별 라운드 수량
  - 난이도에 속한 퍼즐 ID

  - 오브젝트 배치 좌표 값
  - 오브젝트 수량 값

[오브젝트 테이블]

```

### 9. 구현 요구사항

1. 상태 모델:
   ```
   tiles: bool[7][7]                       // 0/1 비트맵
   nodes: Map<(r,c), { kind: MAIN|SUB, color: Color|null, role: START|END|null }>
   paths: Map<Color, List<(r,c)>>          // 각 색의 현재 경로
   ```
2. 경로 확장 유효성: `상하좌우 인접` AND `타일 존재` AND `대상 노드가 SUB이고 아직 색이 없음` AND `대각선 아님`. 도착 노드가 같은 색 MAIN(END)이면 해당 색 경로 완성.
3. **되돌아가기(Undo)**: 경로의 마지막 노드에서 그랩하여 직전 노드로 이동하면 마지막 노드를 pop하고 비활성화한다. 스택 구조로 구현.
4. **클리어 검증 함수**는 반드시 두 조건을 모두 확인한다: (a) 모든 색 경로가 START~END로 완결 (b) `모든 SUB 노드의 color != null`.
5. **레벨 생성기**: 7×7 비트맵으로 타일 마스크를 정한 뒤, 그 위에서 **해밀턴 경로 분해**(모든 SUB 칸을 색깔별 단순 경로로 완전 분할)를 랜덤 생성한다. 각 경로의 양 끝을 MAIN(START/END)으로, 중간을 SUB로 확정한다. 이 방식은 "모든 서브 사용" 조건을 자동으로 보장한다.
6. 테스트: 대각선 연결 차단 / 이미 색이 있는 노드 통과 차단 / 서브 노드 입출력 1회 제한(경로 자기교차 금지) / 그랩 해제 시 경로 유지 / 역주행 지우기 / 양손 동시 사용 차단 / 서브가 남았을 때 클리어 불가 판정.

## 모바일 조작 규격 (§6 VR 상호작용 스펙 대체)

> 원본 §6 은 VR 기준이지만 이미 "양손을 동시에 사용할 수 없다" 고 못박고 있어 모바일 단일 터치와 잘 맞는다.
> 구현: `Flow_DragController.ts`, `Flow_Session.ts`

### M1. 단일 터치 전용

- 동시에 **한 색만** 그릴 수 있다. 조작 중 들어오는 추가 터치는 완전히 무시한다.
- 이것이 원본 §6의 "양손 동시 사용 불가" 를 그대로 만족시킨다.

### M2. 그리기 시작 지점

- **출발 메인 오브젝트**를 누르면 그 색의 그리기가 시작된다.
- 이미 그린 경로가 있으면 그 **머리(마지막으로 연결된 칸)** 를 눌러 이어 그릴 수 있다.
- 서브 오브젝트나 도착 메인에서는 시작할 수 없다.
- 상호작용 가능한 지점은 빛을 내 표시한다 (§6).

### M3. 그리기

- 손가락을 끌면 지나간 칸이 순서대로 이어진다.
- **어댑터 책임:** 로직 계층(`moveDraw`)은 인접하지 않은 칸이 들어오면 그 입력을 통째로 거절한다.
  손가락이 빨리 움직여 칸을 건너뛰어 샘플되면, 화면 어댑터가 **셀 경계를 보간해
  중간 칸들을 순서대로 나눠 호출**해야 한다.
- 상하좌우로만 이어지며 **대각선은 이어지지 않는다** (§5).
- 이을 수 없는 칸(타일 없음 / 다른 색이 차지 / 자기 경로와 교차 / 다른 색 메인)에서는
  미리보기가 활성화되지 않고 사유를 함께 전달한다.

### M4. 지우기 (역주행)

- 그렸던 길을 **그대로 되짚으면** 지나온 서브 오브젝트의 불이 하나씩 꺼진다 (§6 / §9.3).
- 스택 구조라 되짚은 만큼만 정확히 지워진다.

### M5. 손을 뗐을 때

- **그린 경로는 그대로 남는다.** 손과의 연결만 끊어진다 (§6 그랩 해제).
- 다시 머리를 잡아 이어 그리거나 되짚을 수 있다.

### M6. 리셋

- 한 색만 지우는 `clearColor()` 와 전부 지우는 `clearAll()` 을 제공한다.

### M7. 실패 연출

- 제한 시간이 끝나면 §7 에 따라 **즉시 입력을 막는다.**
  불이 서서히 꺼지는 2초 연출은 어댑터가 `QUEST_FAILED` 를 받아 처리한다.
