# 04. 스킬 시스템 — Stack과 Rule

> 상위 문서: `ReadMe.md` / 원안: `../Ideation/스킬_시스템_아이데이션.md`
> 형제 문서: `05_퀘스트_숙달도_시스템.md`, `06_스킬_융합_시스템.md`

이 문서가 본 프로젝트의 **핵심 시스템**이다. 다른 시스템은 모두 이 시스템을 굴리기
위한 보조 장치로 설계한다.

## 1. 대원칙

1. **기본 공격은 존재하지 않는다.** 모든 공격은 스킬이다. 검사도 마찬가지이며,
   검술 자체가 하나의 스킬이다(26/02/23).
2. **스킬은 쓰면 자란다.** 스킬을 사용해 얻은 결과(Hit, Crit, Kill, Debuff)가
   그 스킬의 Stack이 된다.
3. **성장은 두 방향이다.**
   - **양적 성장(Stack)**: 스택 누적 → 데미지 등 수치 상승
   - **질적 성장(Rule)**: 임계치 도달 → 스킬의 성질 자체가 변화
4. 후반 성취감 급감을 막는 것은 수치가 아니라 **Rule**이다.

## 2. 스킬 구조

```
Skill
├─ Level        (1~5)  : 레벨업 카드로 상승. 데미지 +10%/레벨
├─ Stack        (0~∞)  : 사용 결과로 누적. 태그 스택으로 관리
├─ Tier         (0~4)  : 스택 임계치 도달로 상승. Rule 획득 기회
└─ Rules        (최대 3): Tier 상승 시 선택으로 획득. 스킬의 질을 변화
```

- 스킬 인스턴스는 `UGameplayAbility` 1개 + 그 스킬 전용 태그 네임스페이스로 구성된다.
- Level과 Tier는 **독립된 축**이다. 카드를 안 뽑아도 스택은 쌓이고, 스택이 없어도
  카드로 레벨은 오른다.

## 3. Stack — 양적 성장

### 3-1. 스택 획득 소스 [제안]

| 소스 | 획득량 | 초당 상한 |
| --- | --- | --- |
| Hit (적중) | +1 | 10 |
| Critical Hit | +2 | 10 |
| Multi Hit (동일 시전 2번째 이후 적중) | +1 | 10 |
| Kill (해당 스킬로 마지막 타격) | +3 | 제한 없음 |
| Debuff 최초 적용 | +1 | 5 |
| 엘리트 처치 | +15 | — |
| 보스 처치 | +50 | — |

초당 상한은 광역 스킬이 군집을 쓸어담을 때 스택이 폭주하는 것을 막기 위한 장치다.
상한은 **스킬별로 독립 계산**한다.

### 3-2. 스택에 의한 상시 보정

```
StackDamageBonus = min(Stack * 0.2%, 60%)
```

- 스택 300에서 상한 60%에 도달한다. 그 이후의 스택은 **오로지 Tier 진행에만** 기여한다.
- 이 상한이 "후반에 스택이 재미없어지는" 문제(26/02/26 우려)에 대한 1차 방어선이다.
  이후 성장은 Rule과 융합이 담당한다.

### 3-3. Tier 임계치 [제안]

| Tier | 누적 스택 | 보상 |
| --- | --- | --- |
| T1 | 40 | Rule 선택 (2택) |
| T2 | 120 | Rule 선택 (3택) |
| T3 | 280 | Rule 선택 (3택) + 스킬 형태 변화 |
| T4 | 600 | 마스터 태그 부여 → 융합 조건 충족 |

- T3의 "형태 변화"는 이펙트와 시전 패턴이 함께 바뀌는 지점이다. 원안의 "점진적으로
  화려해지는 이펙트"(26/03/03)를 여기에 건다. → `10`
- T4 도달 시 `Skill.<Name>.Mastered` 태그를 부여한다. → `06`

## 4. Rule — 질적 성장

### 4-1. Rule의 정의

Rule은 스킬에 붙는 **성질 태그**다. 단순 수치 버프가 아니라 스킬의 동작을 바꾼다.
`TArray<ERule>`에서 무작위 후보를 뽑아 플레이어가 선택하는 방식(26/02/23)을 유지하되,
**완전 랜덤이 아니라 해당 스킬의 Rule 풀에서만** 추출한다.

### 4-2. 원소별 Rule 표 [제안 — 원안의 Rule 명칭을 효과로 구체화]

#### Fire

| Rule | 효과 |
| --- | --- |
| 뜨거움 | 적중 시 `Debuff.Burn` 부여 |
| 화상 | Burn 중첩 상한 3 → 5, Burn 데미지 +50% |
| 잠식 | 화상 상태의 적이 죽으면 반경 300에 폭발(원본 데미지의 60%), 폭발도 화상 부여 |

#### Ice

| Rule | 효과 |
| --- | --- |
| 뾰족함 | 투사체가 적 2체 관통 |
| 차가움 | 적중 시 `Debuff.Chill` 부여 |
| 단단함 | 시전 시 자신에게 흡수 보호막(공격력의 30%, 3초) |
| 빠름 | 투사체 속도 +60%, 사거리 +30% |

#### Wind

| Rule | 효과 |
| --- | --- |
| 빠름 | 해당 스킬 쿨타임 -25% |
| 날카로움 | 해당 스킬 치명타 확률 +20% |
| 응축 | 범위 -40%, 대신 데미지 +90% (질의 변화) |

- **원안 의도 반영**: "모든 게 다 투사체일 필요는 없다." 응축·단단함처럼 투사체가
  아닌 방향의 Rule을 각 원소마다 최소 1개씩 배치한다.
- 한 스킬이 가질 수 있는 Rule은 **최대 3개**다. 4번째 선택지가 나올 때는 기존 Rule
  교체 여부를 묻는다. [제안]

### 4-3. Rule의 확장 활용 (원안 미결 사항에 대한 답)

원안은 "Rule을 깨달은 뒤 활용처: 영역 / 다른 원소 스킬에도 적용?"을 열어두었다.
본 기획서는 다음과 같이 제안한다.

- **영역(Aura)**: 동일 Rule을 서로 다른 스킬에서 3회 획득하면, 그 Rule이 **캐릭터
  자체의 영역**으로 승격된다. 예: 「차가움」 3중첩 → 플레이어 주변 반경 400 상시 둔화장.
  이것이 후반 성장의 세 번째 축이 된다.
- **타 원소 전파**: 기본적으로 불가. 단 융합 스킬은 재료 스킬의 Rule을 **1개까지 상속**
  한다. → `06`

## 5. 스킬 획득 경로

26/03/03의 아이데이션을 다음과 같이 정리한다. 현재 구현은 `GiveAbility` 직접 호출이나,
정식 경로는 아래 3가지다.

| 경로 | 등급 | 비고 |
| --- | --- | --- |
| 레벨업 카드 선택 | 전 등급 | **주 경로.** → `07` |
| 몬스터 드롭 | D~A (S는 극소 확률) | 엘리트 이상만 드롭. 데모 범위 밖 [보류] |
| 보물 상자 | B·A 중심, 소수 S | 맵에 배치. 데모 범위 밖 [보류] |

데모에서는 **레벨업 카드 경로만** 구현한다.

  으로 둔다. Frost Nail처럼 추적형만 자동 타게팅을 사용하고, 나머지는 마우스 방향을 쓴다.
