## 2. 핵심 재미 가설

원안에서 정의한 가설을 설계 언어로 옮기면 다음과 같다.

> 히오스의 퀘스트 성장은 재미있었지만 판이 20~30분에 끝나 성장을 끝까지 밀어붙일 수
> 없었다. 뱀서류의 긴 생존 루프 위에 퀘스트 성장을 얹어, **성장 곡선을 판이 끝날
> 때까지 계속 살아 있게 만든다.**

이 가설을 만족시키기 위한 설계 제약 3가지:

1. **성장의 출처는 레벨업만이 아니다.** 레벨업 카드(수평 확장) + 스킬 스택 퀘스트
   (수직 심화)의 두 축을 동시에 굴린다. → `04`, `05`, `07`
2. **성장의 피드백은 즉각적이어야 한다.** 퀘스트 달성 순간의 사운드·파티클·팝업 UI가
   재미의 절반이다(원안에서 명시적으로 지목한 요소). → `10`
3. **후반 성취감 급감을 구조로 막는다.** 단순 수치 증가가 아니라 **Rule에 의한 질적
   변화**로 성장을 이어간다. → `04`

## 3. 코어 루프

### 3-1. 초 단위 루프 (전투)

```
적 접근 → 스킬 자동 시전(조준만 플레이어가 담당) → 적중/처치
       → 스택 누적 → 경험치 획득 → (반복)
```

### 3-2. 분 단위 루프 (성장)

```
경험치 게이지 충족 → 레벨업 → 시간 정지 → 카드 3장 제시 → 1장 선택
                  → 신규 스킬 획득 또는 기존 스킬 강화 → 전투 복귀
스택 임계치 도달   → 퀘스트 완료 팝업 → Rule 선택(2~3개 중 1개) → 스킬의 질이 변화
```

### 3-3. 런 단위 루프

```
런 시작(메타 강화 반영) → 웨이브 진행 → 엘리트/보스 조우
   → 사망 또는 클리어 → 정산(재화 획득) → 메타 강화 구매 → 다음 런
```

## 4. 한 판의 시간 구성 [제안]

원안 5장의 "게임 플로우 시스템(한 판의 시작과 끝)"에 대한 구체안.

| 구간 | 시간 | 설계 의도 |
| --- | --- | --- |
| 도입 | 0:00 ~ 2:00 | 스킬 1개로 시작. 조작 적응. 적은 느린 추격형만 등장 |
| 확장 | 2:00 ~ 8:00 | 레벨업 빈도 최대 구간. 스킬 2~4개 확보, 첫 Rule 획득 |
| 심화 | 8:00 ~ 15:00 | 스택 임계치 2~3단계 도달. 원거리형·군집형 혼합. 첫 엘리트 |
| 폭발 | 15:00 ~ 20:00 | 융합 카드 등장 가능 구간. 화면이 이펙트로 가득 차는 구간 |
| 결착 | 20:00 | 보스 등장. 처치 시 클리어, 실패 시 런 종료 |

- 엘리트는 5분마다 1체씩 추가 스폰한다.
- 클리어 후에도 계속 플레이하는 **무한 모드**는 데모 범위 밖으로 둔다.

## 5. 승패 조건

- **패배**: 플레이어 Health가 0이 된다. 부활 수단은 기본 제공하지 않는다(메타 강화로
  1회 부활 해금 가능). [제안]
- **승리**: 20분 보스 처치.
- 어느 쪽이든 런은 종료되고 정산 화면으로 넘어간다. → `09`

## 6. 원안 대비 확정/변경 사항

| 원안 항목 | 본 기획서에서의 처리 |
| --- | --- |
| 기본 공격 자동, 스킬 자동 시전 | **기본 공격을 없애고 전부 스킬화**하는 26/02/23 결정을 채택. → `04` |
| 데미지 타입은 하나 | 유지. 방어는 **절대 감소 + 퍼센트 감소 병용**으로 확정. → `03` |
| 아이템·인벤토리·재화 | **런 내 인벤토리는 데모 범위에서 제외.** 재화는 메타 프로그레션 용도로만 사용. → `09` |
| 퀘스트 수명(런 한정 vs 영구) | **런 한정을 기본**으로 하고, 영구 요소는 메타 강화로 분리. → `05`, `09` |
