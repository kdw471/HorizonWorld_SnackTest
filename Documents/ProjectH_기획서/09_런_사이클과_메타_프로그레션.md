# 09. 런 사이클과 메타 프로그레션

> 상위 문서: `ReadMe.md` / 원안: `../Ideation/게임_루프_방향성.md`
> 형제 문서: `05_퀘스트_숙달도_시스템.md`, `01_게임_개요와_코어_루프.md`

## 1. 원안의 미결 쟁점

26/02/26 로그는 두 방향을 대립시켰다.

1. **이어서 하게 한다(RPG형)** — 쌓은 스택이 아깝지 않고, 긴 성장의 뿌듯함이 있다.
2. **매번 처음부터 한다(뱀서형)** — 짧게 치고 빠져 피로도가 낮고, 매번 방향성을
   고쳐보는 재미가 있다.

## 2. 결정안 — 2안(뱀서형) 기반 + 메타 층 분리 [제안]

**런 내 성장은 전부 리셋하고, 영구 성장은 별도 층으로 분리한다.**

근거는 세 가지다.

- 1안의 최대 장점("긴 성장의 뿌듯함")은 **메타 층으로 대체 가능**하지만, 2안의 장점
  ("매번 방향성을 고쳐보는 재미")은 1안 구조에서 재현할 수 없다. 되돌릴 수 없는 것을
  택한다.
- 1안은 26/02/26에서 스스로 지적한 대로 "다시 하게 될 시 고려할 사항이 더 복잡"하다.
  런 간 상태를 저장·복원·밸런싱해야 하며, 1인 개발 규모에서 비용이 크다.
- 원안이 정의한 장르 자체가 뱀서류다. 세션 경계가 명확해야 스폰 디렉터·난이도 곡선·
  보상 정산이 모두 단순해진다.

### 2-1. 1안의 장점을 회수하는 장치

| 1안의 장점 | 본 설계에서의 대응 |
| --- | --- |
| 쌓은 스택이 아깝다 | 정산 시 스택 총량이 **재화로 환산**된다. 헛되지 않는다 |
| 긴 성장의 뿌듯함 | 메타 강화 트리 + 스킬 마스터 기록이 누적된다 |
| 매번 같은 환경이 지루하다 | 시작 시 **주문서(변형 룰) 1장**을 선택해 런 조건을 바꾼다 [보류] |

## 3. 런 정산

런 종료(사망 또는 클리어) 시 다음을 계산한다.

```
Essence = floor(생존초 / 10)
        + 처치수 * 0.2
        + 총 스택 합계 * 0.05
        + (클리어 시 300)
```

정산 화면에는 생존 시간, 처치 수, 최고 DPS 스킬, 획득 Rule 목록, 획득 Essence를
표시한다.

## 4. 메타 강화 [제안]

Essence로 구매하는 영구 강화. 원안 Phase 5의 "Hades 스타일 영구 강화, SetByCaller로
런 시작 시 초기 스탯 반영"을 따른다.

| 강화 | 단계 | 효과/단계 | 비용(누적) |
| --- | --- | --- | --- |
| 활력 | 5 | MaxHealth +10 | 50, 120, 220, 360, 550 |
| 신속 | 3 | MoveSpeed +15 | 80, 200, 400 |
| 통찰 | 3 | 경험치 획득 +5% | 100, 250, 500 |
| 자석 | 3 | PickupRadius +40 | 60, 150, 300 |
| 선택지 | 1 | 레벨업 카드 4장 | 800 |
| 재고 | 2 | 리롤 +1회 | 300, 700 |
| 불굴 | 1 | 런당 1회 부활(체력 30%) | 1,500 |

- 메타 강화는 **수치와 편의성만** 건드린다. 새 스킬이나 Rule을 메타로 해금하지 않는다.
  런 내 선택의 재미를 메타가 잠식하면 안 된다.
- 스킬 해금은 `05` 4장대로 **런에서 T4를 달성한 스킬**이 다음 런 카드 풀에 상위 등급으로
  올라가는 방식으로만 이루어진다.

## 5. 저장 데이터

`UPlayerSaveGameSubsystem`(1/16 구현분)을 그대로 사용한다.

| 저장 항목 | 비고 |
| --- | --- |
| Essence 보유량 | |
| 메타 강화 단계 | |
| 스킬별 최고 Tier 기록 | 카드 풀 등급 결정에 사용 |
| 통계(총 런 수, 최장 생존, 최다 처치) | 정산 화면 표시용 |

`GameInstanceSubsystem`의 생명 주기는 1/16 로그에서 확인한 대로 `Init`에서 생성·초기화,
`ShutDown`에서 소멸이다. 저장은 런 종료 시점과 메타 구매 시점에만 수행한다.
