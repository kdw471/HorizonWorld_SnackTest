> 상위 문서: `ReadMe.md`
> 형제 문서: `03_전투와_데미지_시스템.md`, `10_UI_UX와_피드백.md`
> 관련 로그: `../Ideation/개발_로그_타임라인.md` (02/21 마우스 피킹, 26/03/04 회전 고민)

## 1. 입력 스킴

| 입력 | 동작 |
| --- | --- |
| W / A / S / D | 이동 (월드 기준 8방향, 카메라 정렬) |
| 마우스 위치 | **조준 방향** — 캐릭터 상체·스킬 시전 방향 결정 |
| 마우스 좌클릭 | 수동 시전 지정 스킬이 있을 때만 사용 [제안] |
| Space | 회피(대시) — 데모 범위 밖 [보류] |
| Tab | 스킬·스택 현황 패널 토글 |
| ESC | 일시정지 |

원안은 "W,A,S,D + 마우스 방향(히오스)"으로 명시되어 있다. 따라서 **클릭 이동(마우스
피킹 이동)은 본 기획의 조작 스킴이 아니다.** 02/21에 구현한 마우스 피킹 이동은
초기 프로토타입 자산으로 남기고, 지형 위 마우스 좌표를 구하는 용도
(`DeprojectScreenToWorld` + LineTrace)로만 재사용한다.

## 2. 이동 방향과 조준 방향의 분리

26/03/04 로그에서 제기된 문제 — "이동하면서 뒤를 바라보는 꼴이 된다", "뒷걸음질·게걸음
애니메이션을 다 대응해야 한다" — 는 클릭 이동 방식에서 생기는 문제였다. WASD 조작에서는
아래와 같이 정리한다.

- **이동 방향** = WASD 입력 벡터
- **바라보는 방향(Yaw)** = 마우스 커서가 가리키는 지면 위치
- 두 방향이 다른 것은 **버그가 아니라 사양**이다. 뱀서류에서 뒤로 물러나며 전방에
  스킬을 쏘는 것은 핵심 조작이다.
- 따라서 **8방향 Locomotion 블렌드스페이스가 필수**다. 전진/후진/좌우 스트레이프
  애니메이션을 반드시 확보한다(무료 에셋 확보 목록에 포함).

### 2-1. 애니메이션 요구 사항

| 상태 | 필요 애님 | 비고 |
| --- | --- | --- |
| Idle | 1 | 조준 상태 Idle |
| Locomotion | 8방향(F/B/L/R + 대각 4) | 블렌드스페이스 2D (Direction × Speed) |
| Cast | 스킬 계열별 1종 이상 | 상체 레이어드 블렌드(08/24 작업분 재사용) |
| Hit React | 1 | 짧게, 이동을 끊지 않는 상체 전용 |
| Death | 1 | 런 종료 연출 |

- 상체(캐스팅)와 하체(이동)는 **본 레이어드 블렌드**로 분리한다. 08/24에 준비한
  구조를 그대로 사용한다.
- 애니메이션 그래프는 비동기 스레드에서 돌므로, 상태 값은 미리 캐싱해 전달한다.
  (→ `../Ideation/기술_트러블슈팅_노트.md` 2항)

### 2-2. 메쉬 정면 축

에셋 본연의 **y축 정면을 그대로 사용**한다(08/12·26/03/04 결론). 캐릭터 클래스에서
메쉬 컴포넌트에 -90° Yaw 오프셋을 상수로 적용하는 것으로 끝내고, 블렌더 축 정상화
작업은 더 진행하지 않는다.

## 3. 카메라

| 항목 | 값 [제안] |
| --- | --- |
| 방식 | SpringArm + Camera, 회전 고정(플레이어 회전 미상속) |
| 각도 | Pitch -55° |
| 거리 | 1200 유닛 |
| 추적 | 플레이어 위치에 Lag 0.15초, 마우스 방향으로 최대 150 유닛 오프셋 |
| FOV | 원근 75° |

마우스 방향 오프셋은 조준하는 쪽 시야를 더 확보해주기 위한 것으로, 뱀서류에서
접근 중인 적을 미리 보는 데 중요하다.

## 4. 이동 처리

- 이동은 **등속**을 기본으로 한다(02/12 결정). 가감속은 Ease 곡선 파라미터로 표현하며,
  02/19에 제기된 대로 `UniformMove`/`InterpMove`를 하나의 실행기로 통합하고 곡선을
  파라미터로 넘긴다. [제안]
- 이동 속도는 Attribute `MoveSpeed`가 결정한다(기본 400 u/s). 슬로우·가속 디버프/버프는
  모두 이 Attribute를 경유한다.
- 이동 시 장애물 처리와 높이 고려는 02/19 시점의 미해결 과제로 남아 있다. 데모에서는
  **평지 아레나**로 제한해 회피한다.

## 5. 플레이어 상태(State)

| 상태 | 조건 | 제약 |
| --- | --- | --- |
| Alive.Normal | 기본 | 제한 없음 |
| Alive.Casting | 수동 시전 스킬 사용 중 | 이동 속도 50% [제안] |
| Alive.Staggered | 강한 피격 | 0.3초 입력 무시 [보류] |
| Dead | Health 0 | 입력 차단, 런 종료 시퀀스 |

상태는 GameplayTag로 표현한다(`State.Alive.Casting` 등). → `11`
