# 06. 스킬 융합(Fusion) 시스템

> 상위 문서: `ReadMe.md` / 원안: `../Ideation/GAS_구현_로드맵.md` Phase 4
> 형제 문서: `04_스킬_시스템_Stack과_Rule.md`, `07_레벨업과_카드_선택.md`

융합은 **런 후반의 성장 곡선을 담당하는 마지막 축**이다. 스택 보너스가 상한에 닿고
Rule 슬롯이 차오른 뒤에도 성장할 곳을 만들어 준다.

## 1. 융합 조건

- 재료 스킬 2종이 모두 **T4(마스터)** 에 도달해야 한다.
  즉 `Skill.Fireball.Mastered` + `Skill.WindCutter.Mastered` 보유.
- 조건 충족 시 **즉시 융합되지 않는다.** 다음 레벨업 카드 풀에 융합 카드가 높은
  가중치로 등장하고, 플레이어가 선택해야 성립한다. 선택권을 남기는 것이 중요하다.

## 2. 융합 레시피 [제안]

| 재료 A | 재료 B | 결과 | 성격 |
| --- | --- | --- | --- |
| Fireball | Wind Cutter | **Flame Lance** | 관통 화염 창, 경로상 화상 |
| Fireball | Ice Cone | **Steam Burst** | 광역 폭발 + 시야 차단 둔화 |
| Ice Cone | Wind Cutter | **Blizzard Edge** | 회전 냉기 참격, 상시 둔화장 |
| Fireball | Ember Trail | **Wildfire** | 장판이 적을 따라 번짐 |
| Ice Cone | Glacier | **Absolute Zero** | 광역 속박 후 일제 파열 |

- 데모 범위는 **Flame Lance 1종**으로 한정한다.
- 레시피는 `UPH_FusionRecipeDataAsset`으로 관리한다. 코드에 하드코딩하지 않는다.

## 3. 융합 실행 절차

1. **Fusion Tag Checker**가 ASC의 태그 컨테이너를 스캔해 충족된 레시피를 수집한다.
   (레벨업 시점에만 수행. 매 프레임 스캔하지 않는다.)
2. 충족된 레시피의 융합 카드를 카드 풀에 **가중치 3배**로 삽입한다. → `07`
3. 플레이어가 융합 카드를 선택하면
   - 재료 스킬 2종을 `ClearAbility`로 제거한다.
   - 융합 스킬 `UGameplayAbility`를 `GiveAbility`로 부여한다.
   - 재료의 스택·Rule을 아래 규칙으로 상속한다.
4. 융합 연출을 재생한다(Gameplay Cue, 화면 전체 플래시 + 전용 사운드). → `10`

## 4. 능력치 상속 규칙 [제안]

원안은 "재료가 된 스킬들의 레벨이나 속성값을 참조하여 Execution Calculation으로 결정"
까지만 정해져 있었다. 구체안은 다음과 같다.

```
FusedSkill.Level = max(A.Level, B.Level)
FusedSkill.Stack = floor((A.Stack + B.Stack) * 0.5)
FusedSkill.Tier  = Stack 재평가 결과 (통상 T2~T3에서 시작)
FusedSkill.Rules = A와 B의 Rule 중 플레이어가 1개 선택하여 계승 + 융합 전용 Rule 1개 자동 부여
```

- 스택을 50%만 계승시키는 이유는, 융합 직후 바로 T4에 도달해 성장이 다시 멈추는 것을
  막기 위해서다. 융합은 **성장 곡선을 재점화**하는 장치여야 한다.
- 융합 스킬은 T4 도달 시 마스터 태그를 얻지만, **2차 융합은 데모 범위 밖**이다. [보류]

## 5. 재료 손실에 대한 안전장치

재료 스킬 2종이 사라지는 것은 체감상 손실이 크다. 다음 장치를 둔다. [제안]

- 융합 카드에는 **어떤 스킬이 소모되는지 명시**한다.
- 융합 결과는 재료 두 스킬의 DPS 합계 대비 **최소 130% 이상**이 되도록 밸런싱한다.
- 융합 카드는 거절해도 사라지지 않는다. 조건이 유지되는 한 다음 레벨업에도 등장한다.
